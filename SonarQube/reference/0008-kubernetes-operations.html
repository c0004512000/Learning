REFERENCE 08 / KUBERNETES OPERATIONS

能重建 Pod，
不代表能救回分析歷史。

把 SonarQube Community Build 的架構、監控與故障復原壓成一頁值班可查的判斷表。先確認資料所有權與故障位置，再選擇要操作哪個資源。

01 / 資料所有權與失效後果

元件權責故障時
Runner / Scanner執行靜態分析、上傳 Report重新執行該次分析；先排除網路、Token、TLS
SonarQube Web / CE接收報告、處理、寫入 DBPod 可重建，但需確認 CE Queue、DB 與版本
PostgreSQLIssues、Metrics、設定、Task Queue 的權威資料要靠資料庫備份與 Restore；ES／Pod 無法憑空還原
ElasticsearchDB 的索引副本、搜尋與查詢加速可重建，但重建時間會影響就緒與部分功能
PVC持久儲存介面，儲存路徑由 Chart 決定保住 Index 不等於 DB Backup；刪除前確認 reclaim policy

02 / 上線前的審查清單

  1. 版本：固定 Community Build 版本、Chart 版本、Image、Plugins；核對官方支援的 Kubernetes、DB、Host 前置需求。
  2. DB：獨立 PostgreSQL（依目標版本的 Supported Matrix）、連線驗證、密碼 Secret Reference、備份、容量與 Restore 演練。
  3. ES：明確決定 persistence.enabled、Index 重建時間、StorageClass、磁碟用量、Readiness／Startup Probe。
  4. Pod Security：核對 Restricted Namespace、initSysctl/initFs、Linux Kernel 的 ES 前置設定，並防止以開權限代替排障。
  5. Ingress／Gateway：HTTPS 終止點、CA 信任、Base URL、Header、Runner DNS／Routing、Firewall／NetworkPolicy、Request Body Size。
  6. CI：保持 Release Tag／Commit SHA／Project Key／CE Task／Gate 結果的可核對關聯，並定義平台不可用時的 Fail Policy。
  7. GitOps：如使用 Argo CD，需另驗證 Chart Hooks、升級／Sync 行為；官方尚未完整支援／驗證此安裝方式。
不要複製預設值假裝生產設定。

官方 26.10 提高 Web 與 CE 預設 JVM Heap；舊版資源限制不能直接沿用。對 CPU、Memory、Disk 與 Probe 的值應依真實 Lines of Code、CE Queue、Index Rebuild 與負載量測決定。官方資源要求

03 / 先做非破壞性的檢查

# 替換成經授權的測試 namespace；均為唯讀檢查
kubectl -n sq-learning get pods,svc,pvc
kubectl -n sq-learning describe pod POD_NAME
kubectl -n sq-learning get events --sort-by=.lastTimestamp
kubectl -n sq-learning logs POD_NAME --tail=100
helm -n sq-learning history sonar
helm show values sonarqube/sonarqube --version CHART_VERSION

Pod Running 不代表 Server Ready，也不代表 CE Task 已完成。遇到連線、DB、CE、ES 問題時，先保留 Logs 與當下狀態；未知狀態不可直接以刪 PVC、還原 DB、或關閉 TLS Verification 處理。

04 / 故障決策矩陣

觀察到什麼初步判斷第一個證據
Pod CrashLoop／OOMKilled資源或進程啟動問題Pod Events、Logs、Limits、Kernel Prerequisite
CE Queue 長期 Pending背景處理能力不足或 CE FailureBackground Tasks、CE Logs、DB Latency
DB 完整、ES Read-onlyES Disk Watermark／索引問題Disk Usage、ES Logs、官方恢復流程
資料庫失效權威資料不可用DB Health／Backup／RPO／RTO
Upgrade 後舊 Image 起不來可能是 Schema／Chart／Plugin 不相容Server／DB Versions、Migration Log、Restore 演練
Scanner 報 Gate Timeout可能 CE 延遲或 ES ReindexCE Task、索引進度、CI Timeout

05 / Backup → Restore → Upgrade 的驗證契約

每次演練至少保存：備份時間、DB 版本、Server Build、Chart Revision、目標 SHA／Project、Restore 與 Reindex 完成時間、樣本 Issues／Profiles／Gates 核對結果、CI Gate 查詢結果。升級還要保存 Update Path、Migration 時間、DB 暫時磁碟需求、回退核准流程。

**Helm rollback 只能回退 Helm 管理的 K8s 資源，不會自動回退 DB Migration。** 這是設計 Restore Drill 最重要的判斷。若未實測 Restore，不能因為有備份檔就宣稱符合 RPO／RTO。
