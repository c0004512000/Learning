REFERENCE / GLOSSARY

概念速查

供閱讀時查閱目前課程用語。這些是編寫者的教學定義，不是學習者已掌握的 canonical Glossary；只有真正完成理解驗收的術語，才適合升格為已學會的詞彙。

術語定義與邊界
Static Analysis不需要執行完整應用程式，以程式碼與規則檢查潛在問題；不等於功能測試。
SAST以靜態分析方式檢查應用程式安全風險，免費版提供基礎檢查但不含所有進階能力。
SonarScanner在開發機或 CI Runner 上執行的分析工具；產生與提交分析報告。
Analysis ReportScanner 在 Runner 分析原始碼後產生的結構化資料包（例如分析得到的 Issues / Metrics 與來源資訊），供 Server 後續處理；不是 Dashboard 上的使用者報表。
Compute EngineSonarQube Server 中非同步整合 Scanner 結果的背景元件，負責彙總、計算衍生指標／評級、處理 Issue 關聯與保存結果；並非重新執行相同的原始碼規則掃描。
ProjectSonarQube 中保存某份程式碼品質狀態的邏輯對象，包含分析資訊、Issues、Metrics、品質設定與歷史；不等於 Kubernetes Namespace。
Main Branch（SonarQube）某個 SonarQube Project 中唯一主要的分析歷史與品質狀態；來源可對應 GitHub 非預設分支，需由 CI Checkout 決定，不等於 GitHub Default Branch。
Project Key用於在 SonarQube Server 識別 Project 的唯一鍵。Scanner 可使用 sonar.projectKey 指定分析報告的歸屬。
CI TriggerGitHub Actions 等工具決定「何時執行 Workflow」，不等於 Server 替 PR 或 Tag 建立獨立分析。
Checkout / Commit SHARunner 工作目錄內實際取得並供 Scanner 讀取的程式碼版本；與 SonarQube Main Branch 顯示名稱分開。
Analysis Identity（分析身分）以 sonar.projectKey 指到 Project；另外的 branch / pullrequest 參數才是要求獨立分析的身分。是教學用分類，不是 UI 開關。
Branch Analysis對非主分支保留獨立的品質狀態與歷史；原生 Community Build 不支援。
Pull Request Analysis對某個 PR 相對目標分支的 New Code 作獨立分析及 Gate 判定；原生 Community Build 不支援。
Test Execution Report外部測試工具產生的測試數、通過／失敗、跳過與耗時等結果；不是 Coverage 百分比。
Issue分析規則偵測出的疑慮；需要評估真實影響與修正優先級。
Rule定義一種特定程式碼寫法是否違規的檢查條件；同一 Rule 可能偵測到很多 Issues。
New Code依指定基準視為新增／修改的程式碼範圍；不是自動與上一個 Commit 比，也不等於免費版原生 PR 分析。
New Code Definition新碼起點的設定：Specific analysis 固定於某次既有分析、Number of days 為滑動時間窗、Previous version 依版本週期；與 CI 的掃描時機分開。
Overall Code整個專案的程式碼範圍，包含 New Code 和 Old Code。
Quality Profile某語言啟用哪些 Rules 的設定組；Project 可逐語言指派自訂 Profile，未指定則使用預設。
Rule MetadataRule Key、名稱、Type / Software Quality、Severity 等描述資料，和檢查程式碼的邏輯是不同責任。
Custom Rule / External IssueXPath Template 和 Java Plugin 可新增 SonarQube 管理的 Rule；External Analyzer 只匯入 Issues，無法藉 Profile 啟停外部 Rule。
Standard / MQR ModeStandard 以 Bug / Vulnerability / Code Smell 等 Type 分類；MQR 能對一條 Rule 指定多個品質面向及各自 Severity。
Sonar way core / extended / comprehensiveCommunity Build 26.10 的三種內建 Quality Profile，嚴格程度不同；升級舊版的現有設定不一定被自動改寫。
Quality Gate由 Metric、比較運算子、門檻構成的一組條件；任一條未達標即 FAIL，不是總分，也不等於 CI 自動阻擋。
sonar.qualitygate.waitScanner 設為 true 時等候 Gate 結果，若 Gate FAIL 便讓掃描步驟失敗；後續 Job 仍需 CI 依賴設定。
Coverage測試覆蓋率資料，由外部工具先產生後再匯入；Scanner 本身不負責執行測試。
DashboardSonarQube Server 提供的 Web UI，用來查詢 Project、Issues、Metrics 和 Gate。
H2可供本機短暫測試的內建資料庫，不建議在 Production 使用。
