REFERENCE 06 / FEATURE BOUNDARIES

免費版與商業版，
差的是哪一層能力？

以下先比較自架 SonarQube Community Build 與付費 SonarQube Server。不要將 SonarQube Cloud 的 Free／Team／Enterprise 套用到自架 Server，因為同樣叫 Free，功能表卻是不同產品。

01 / 從你要完成的工作來比較

**Developer+** 是指付費 SonarQube Server 的 Developer Edition 或更高方案；其他差異請依實際採購版別與版本的官方功能表確認。上表不是所有版別、語言與額外授權的完整報價清單。官方功能比較。

02 / 為什麼「CI 在 PR 執行 Scanner」不等於 PR Analysis？

Figure / 同一個 CI Trigger，Server 儲存模型不同

GitHub pull_request Event可以在 Community 與 Commercial 都啟動 Runner
↓ Checkout → Scanner 上傳報告
Community Build只管理該 Project 的單一 Main Branch；沒有 PR #42 專屬狀態
↓ 若使用付費版原生 PR 身分與整合
SonarQube Server Developer+可建立 PR #42 獨立分析結果、New Code Gate 與 PR Decoration

在 GitHub pull_request 事件中，預設 Checkout 可能是 GitHub 的模擬合併 Commit；這是 GitHub 事件語意，不等於 SonarQube 原生 PR 對來源／目標分支的 New Code 評估。兩個分支都持續變更時，PR Gate 也不能代替最新 Merge Result 的建置與測試。

03 / 同一 Repo 的 main、develop 如何追蹤？

COMMUNITY

兩個 Project

demo-main、demo-develop 分開掃描，各有獨立 Issue 與歷史；不是原生 Branch 選單，也不會自動進行跨分支 Issue 同步。

DEVELOPER+

一個 Project

原生管理 main、develop 分支分析狀態，可對分支分別查看品質資訊，並使用支援的 PR 工作流程。

兩種方式都需要 Scanner 分析實際 Checkout 的原始碼。付費並不代表 Server 自己會替代 Runner 進行 Git Clone、Build 或 E2E。

04 / 別把 Cloud Free 當 Community Build

SonarQube Cloud Free 是 SaaS 方案，不是可在 Kubernetes 自架的 Community Build。官方功能表對 Cloud Free 的 PR 分析附有「目標是 main branch」的限制；這不代表 Community Build 也有同樣程度的原生 PR 分析功能。比較時請直接看官方表格的欄位標題。

05 / 怎麼判斷是否值得升級？

先問具體缺少哪種能力：若只需 Release Tag 觸發的主分支持續掃描、Issues、Coverage 匯入和 CI Gate，Community 可以完成基本路徑；若需同 Project 多分支長期保存、PR 差異分析及 Decoration、原生 PR 品質門禁，就要評估付費 SonarQube Server。若要 Portfolios、報表、SCA 或大規模治理，再評估更高方案與授權條件。

官方文件、功能與產品命名會隨版本調整。本頁核對於 2026-11-09，導入前仍需以實際版本的功能表與授權條款覆核。
