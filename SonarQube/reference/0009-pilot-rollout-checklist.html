REFERENCE 09 / MULTI-REPO GOVERNANCE

可比較的 Pilot，
才有可放大的決策。

以下是跨語言和跨 Repo 的驗收契約。若任何欄位未知，就標明 Unknown；不以 Scanner Success 代替完整的品質資料，也不以單一 Dashboard 的綠燈代替 Release Gate 的治理證據。

01 / 語言差異速查

類型分析前要準備匯入 Coverage 的參數
Java編譯好的 .class、相容 Build/Scanner（推薦 Maven／Gradle）sonar.coverage.jacoco.xmlReportPaths（JaCoCo XML）
JavaScript／TypeScript原始碼、相容 Node / Analyzer Runtime、LCOV 報告sonar.javascript.lcov.reportPaths（LCOV）
Python原始碼、正確 Python Version、Cobertura XML 報告sonar.python.coverage.reportPaths（Coverage.py XML）

Scanner 不會自行建立 Coverage；應核對測試工具、產物相對路徑及 SonarSource 所支援的語言／Scanner 版本。官方 Coverage 參數 · Java · Python。

02 / 每個 Repo 應交付的最低證據

責任必須保留的資料
身份Repository、Branch／Tag、Checkout SHA、Project Key、Project Version
掃描環境Runner 類型、Scanner Version、Build / Test 工具與版本
語言與品質政策語言、Quality Profile、Quality Gate、New Code Definition
CoverageReport 格式／檔案路徑／存在性／匯入結果
ServerCE Task ID、Status、指標與 Failed Conditions
CI PolicyObserve／Warn／Enforce、Gate Job Result、部署需要的 needs、例外
維運Scan 耗時、CE Queue、Failure Rate、Error Owner、Fallback

03 / 權限的最小原則

優先使用每 Project 的 Analysis Token，禁止把高權限 User Token 直接共用給所有 Repo；明確審查 Global Execute Analysis、Project Visibility、Administer Profiles／Gates、Secret Rotation。Token 的儲存與範圍應由組織允許的 Secret System 與流程管理。官方 Token · 官方權限。

04 / 受控 Rollout 檢查

  1. 選至少兩個不同語言或建置工具的 Pilot；排除假成功（缺 Report、錯 SHA、錯 Profile）。
  2. 量測 Scan Success、CE Delay、Gate Failure、Noise、Scanner Runtime 與團隊處理成本，別把 Quality Gate FAIL 混入平台錯誤率。
  3. 確認業務 Owner、Profile／Gate 管理者、最低 Token 權限與 Project Visibility；審查相同 Project Key 是否被其他 Repo 誤用。
  4. 在隔離環境完成 Gate PASS／FAIL、Token 失效、Server Timeout、舊 Release 重掃與回退情境。
  5. 有風險與例外處理辦法後，先 Canary 少量服務，再逐批擴大；任何共用 Template 變更都需版本鎖定與回退方案。

05 / Pilot Decision Record 模板

Scope：評估哪些 Repo／語言／部署環境？

Baseline：各 Repo 的 Profile、Gate、New Code、Coverage 是否可追溯？

Evidence：掃描／CE 的成功率、延遲、誤報與受控 Gate FAIL 實驗結果。

Risk：版本／Commit 對錯、Server 不可用、DB Recoverability、Token 及例外處理。

Decision：Go／Conditional Go／Hold。列出 Owner、日期、下一個 Canary 範圍、取消／回退條件。

這份模板不能代替真正的測試報告；不應直接填合成範例數字來宣稱 POC 已成功。
