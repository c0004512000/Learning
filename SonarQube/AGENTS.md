# SonarQube Teaching Workspace

Canonical teaching skill: https://github.com/c0004512000/Skills/blob/main/Learning/Learning-from-docs/SKILL.md

Before teaching or editing, read the canonical SKILL.md, its Required context in order, and applicable upstream formats. CSS can be independently designed, but **no pedagogical exemption** applies.

- Mission: evidence-based assessment of SonarQube Community Build for CI/CD + Kubernetes.
- Build the whole source-grounded Course Map first, author detailed Lessons progressively as needed.
- Use official version-specific SonarSource sources, keep `sources/materials`, `sources/linked`, `sources/evidence`, and `reference` distinct.
- A learner's question is diagnostic input for `NOTES.md`, not proof of learning. Write Learning Records **only** after the user's demonstrated competence, stated prior expertise, confirmed correction, or Mission shift meets the upstream record criteria.
- Lesson design: familiar behavior → one new concept → precise boundary → retrieval/practice/feedback → recap. Do cold-read and blank-slate checks on revisions.
- Quiz alternatives should have similar **word and character lengths**, without answer-format clues; rotate correct-answer positions across Lessons.
- Content and the navigation must work without JavaScript; interactive widgets must have useful fallback or an explicit requirement.
- Public Pages: no private hostnames, secrets, company workflows, customer data, or invented screenshots.
- Do not claim POC or live browser QA completed without actual test evidence. Check mobile and desktop with browser when reachable; record blockers separately.
