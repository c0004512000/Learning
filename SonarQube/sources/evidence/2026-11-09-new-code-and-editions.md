# New Code / Release Version / Edition Boundary — 2026-11-09

## Source-verified definitions
1. SonarQube Community Build separates new-code metrics from overall metrics; the previous version, number of days, and specific analysis methods define a time interval, whereas reference branch is a separate comparison model. Previous Version starts on the date the *current* project version was first analyzed; Number of Days starts at current date minus N; Specific Analysis starts at a selected existing analysis. Source: https://docs.sonarsource.com/sonarqube-community-build/user-guide/about-new-code
2. Specific Analysis requires Web API `api/new_code_periods/set` on current Community Build; not a direct Project Settings UI selection, and not an arbitrary Git SHA. Source: https://docs.sonarsource.com/sonarqube-community-build/project-administration/adjusting-analysis/configuring-new-code-calculation
3. `sonar.projectVersion` labels a project version; for Maven and Gradle the build may supply version, for CLI it is explicitly specified; do not use per-CI build numbers because they fragment version-based New Code and impact housekeeping. Source: https://docs.sonarsource.com/sonarqube-community-build/analyzing-source-code/analysis-parameters/parameters-not-settable-in-ui
4. Project Activity can show version scans, Gate changes and historical measures, while housekeeping removes historical snapshots and detailed file data under retention policy. Sources: https://docs.sonarsource.com/sonarqube-community-build/user-guide/viewing-projects/activity-and-history ; https://docs.sonarsource.com/sonarqube-community-build/instance-administration/system-functions/housekeeping
5. Scanner by default does not wait for Gate (`sonar.qualitygate.wait=false`); `true` polls Gate, fails on red; timeout 300s by default. Separate Quality Gate Check Action is supported. Sources: https://docs.sonarsource.com/sonarqube-community-build/analyzing-source-code/analysis-parameters/parameters-not-settable-in-ui ; https://docs.sonarsource.com/sonarqube-community-build/devops-platform-integration/github-integration/adding-analysis-to-github-actions-workflow
6. JS/TS coverage: external tool generates LCOV, then Scanner imports with `sonar.javascript.lcov.reportPaths`. Generic test execution is a distinct format and cannot substitute for coverage; SonarQube does not generate E2E/stress-test dashboards. Sources: https://docs.sonarsource.com/sonarqube-community-build/analyzing-source-code/test-coverage/overview ; https://docs.sonarsource.com/sonarqube-community-build/analyzing-source-code/test-coverage/javascript-typescript-test-coverage ; https://docs.sonarsource.com/sonarqube-community-build/analyzing-source-code/test-coverage/generic-test-data
7. SonarQube Community Build only supports native main-branch analysis, not native multibranch/PR; SonarQube Server commercial offers native branch/PR features; Enterprise-level reporting, SCA/Advanced SAST require higher tiers/add-ons. SonarQube Cloud Free is a separate product with different PR restrictions. Source: https://docs.sonarsource.com/sonarqube-community-build/feature-comparison-table

## Reasoning, not vendor-guaranteed examples
- If scanning only release tags and changing `sonar.projectVersion` on that same first scan, the *new version's first scan* becomes the start of its New Code period. Thus the scan should not be claimed as an exact git diff between previous and current tags.
- A previous release's unresolved issue may move outside a later release's New Code period; this is conditional on issue dating and scope, not guaranteed solely by the version string.
- Number of Days is a date-based window; do not assert without supporting evidence that it always selects the nearest historical analysis or does a Git diff versus one seven-day-old commit.
- GitHub Actions deployment gating needs valid workflow dependency/condition design in addition to a Gate wait setting.
