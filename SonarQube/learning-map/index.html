PHASE 01 / 已撰寫，尚未驗收

基礎：為何需要靜態分析與後端處理

從既有 E2E／Secret Scanning 出發，理解新增的品質訊號與資料流。

L01 · 靜態分析為什麼需要存在？已撰寫／未驗收

學習目標：能區分執行期測試和靜態分析各自能／不能證明的事

驗收方式：在 E2E 成功情境判斷是否仍需分析，並說出一個未覆蓋的風險

來源：官方文件

L02 · Scanner 如何把分析結果交給 Server？已撰寫／未驗收

學習目標：能分辨 Scanner 分析、報告上傳與 Compute Engine 背景處理

驗收方式：能解釋 Scanner success 但 Dashboard 未更新時應先查哪個環節

來源：官方文件

PHASE 02 / 理解驗收進行中；尚無結果

免費版：分析範圍與品質判定

從 GitHub 觸發到 Server 可處理的分析維度，建立 Rule、Profile、Gate 的區別。

L03 · Community Build 能管理哪些分析？部分理解／待綜合驗收

學習目標：能分辨 GitHub Default Branch、CI Checkout 分支、SonarQube Main Branch 與 PR 分析維度

驗收方式：在 main、develop、PR 三個案例中，能預測掃描來源與 Project Key 如何影響分析歸屬

來源：官方文件 · 分析歸屬證據 · Scanner / PR / 測試報告速查

L04 · Rule、Profile、Issue、Gate 如何合作？概念補強／未通過驗收

學習目標：能區分 Rule、Profile、Issue、Gate 的責任，並解釋固定 New Code 基準與逐次 CI 掃描的差別

驗收方式：調整 Rule / Gate 模擬器，並在導入基準 A、Commit B / C 情境中推導 New Code 與 CI 阻擋結果

來源：官方文件 · L04 Reference · 官方核對證據

必要 Reference 分支：New Code／Release Tag／Project Version 時間基準 · Community vs Commercial 分析能力比較。這兩份是概念補強，不增加必修 Lesson 數量。

PHASE 03 / 暫緩撰寫；尚待驗收

Standalone POC：建立 Project 與第一份分析

依這次學習安排暫跳過詳細 Lesson；進入 Phase 04 前須已具備測試 Project、可連線 Server、Token 等能力。未完成書面驗收的 L05／06 不因此算完成。

L05 · Project / Project Key 與 POC 部署條件規劃中

學習目標：能建立 Repo → Project → Project Key → Main Branch 的正確映射，並說明 DB 的角色

驗收方式：用合成 repo 寫出 Project Key、版本、Docker 與 H2 / DB 的選型證據

來源：官方文件

L06 · 完成第一次掃描並核對 Dashboard規劃中

學習目標：能追蹤 Scanner、Background Task、Dashboard 的同一次分析

驗收方式：保存 Scanner log、Task 完成狀態、Issue 與 Quality Gate 的對應截圖／值

來源：官方文件

PHASE 04 / L07、L08 已撰寫；待實機驗收

GitHub Actions POC：把分析加入 CI

先連通 Runner → Server，再匯入 Coverage、驗證 Gate 與部署 Job 依賴；實機驗證仍待執行。

L07 · Runner 如何連上 SonarQube已撰寫／待實機驗收

學習目標：能正確設計 Checkout、Token、主分支事件與 CA/TLS 驗證

驗收方式：在隔離 repo 跑成功一次掃描，證明 Runner → Server 的連線與授權

來源：官方文件

L08 · Coverage 與 Quality Gate 失敗演練已撰寫／待實機驗收

學習目標：能分辨報告缺失、Scanner 失敗、Server 背景處理與 Gate 失敗

驗收方式：用外部測試工具提供 Coverage；展示至少一個預期 Gate FAIL 案例

來源：官方文件 · 連線與 Gate 官方證據

PHASE 05 / 規劃中

CI/CD 治理：何時掃描與阻擋

把免費版限制納入 release/** 與 PR Merge 的決策，而不是套用付費版假設。

L09 · PR／Merge／Release Tag 的適當整合點規劃中

學習目標：能分辨 Commit SHA、主分支分析與 Release Tag 的結果對應風險

驗收方式：產出 main、PR、tag 觸發與支援能力矩陣，說明採用與放棄理由

來源：官方文件

L10 · Non-blocking → Blocking 的導入門檻規劃中

學習目標：能分清品質 Gate 與 GitHub workflow job 的阻擋責任

驗收方式：設計升級、例外、回退及 SonarQube 不可用時的 CI 行為

來源：官方文件

PHASE 06 / 規劃中

Kubernetes：可維運的部署架構

討論資源、持久化資料、憑證與失效復原，不以 POC 單節點當正式規格。

L11 · Helm、Database、PVC、Ingress 與網路規劃中

學習目標：能說明 Server、DB、儲存、Runner 路徑與憑證的依賴

驗收方式：交付不含機敏資料的部署拓樸和資源／網路驗證清單

來源：官方文件

L12 · Backup、Recovery、Upgrade 與維運規劃中

學習目標：能說明品質平台不可用或資料庫故障時的復原策略

驗收方式：至少設計並記錄一套備份復原與升級回退驗收方案

來源：官方文件

PHASE 07 / 規劃中

Pilot：跨專案試點與正式推廣

以可觀察指標判斷可靠性、噪音與導入價值，再擴展標準化 workflow。

L13 · 不同語言的掃描與規則落差規劃中

學習目標：能辨認語言 Scanner、Coverage 報告與 Quality Profile 的差異

驗收方式：完成兩種語言的分析比較，量測執行時間、Issue 噪音和誤報

來源：官方文件

L14 · 共用模板、權限與 Rollout 決策規劃中

學習目標：能制定可回退的 template、監控與例外治理

驗收方式：根據實測產出採用／暫緩的 decision record 和 rollout checklist

來源：官方文件
