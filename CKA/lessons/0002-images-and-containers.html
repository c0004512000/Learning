映像與容器：準備好的程式，如何開始執行

網站程式改好了，交給另一台機器時，只複製程式碼就一定跑得起來嗎？

這堂只處理一個區分：準備好可以執行的內容，與實際啟動一份應用。先試著回答上面的問題，再往下讀。

1. 另一台機器可能少了什麼？

假設網站用 Python 撰寫。另一台機器除了網站程式碼，還需要能執行 Python 程式的軟體，以及網站用到的其他套件。套件就是別人已寫好、供這個程式使用的功能。

如果每台機器都靠人重新安裝，可能有人裝了不同版本，也可能漏裝。結果就會出現「同一份程式，在這台能跑、另一台卻不能跑」。

為了重複交付同一套內容，我們可以事先把程式與執行所需的檔案準備成一份標準格式的包，並記下啟動程式的方式。

2. 準備好的內容，叫做映像

這種準備好的包叫做容器映像（container image），以下簡稱映像。這裡的「映像」不是圖片，而是用來建立應用執行環境的內容。

以這個網站為例，映像可以包含網站程式碼、執行 Python 所需的軟體，以及網站使用的套件。映像準備好或下載完成，都不表示網站已經啟動。

一份已建立的映像內容不會直接改寫。若要交付修正後的網站程式，就要依修正版建立新的映像。

主要來源：Docker 官方對映像的說明

3. 用這份內容建立獨立的執行環境

機器可以根據映像建立一個供應用執行的隔離環境，再於其中啟動程式。這個環境稱為容器（container）。隔離的意思是：限制程式能看到和使用的檔案、執行中的程式等資源，減少與其他應用互相干擾。

容器仍然依靠所在機器的作業系統與運算資源。它不是另外生出的一整台機器，也不是把一套完整、獨立的作業系統開機。

同一份映像可以建立多個容器。每個容器各自有執行狀態，可以分別啟動或停止；停止其中一個，不代表另一個也會停止。

主要來源：Docker 官方對容器的說明

4. 一份映像，兩個容器

假設用同一份網站映像建立容器 A、B，並啟動它們。接著只停止 A，沒有設定額外的自動重啟。

先預測：此時還有幾個容器在執行？原本的映像會不會因此被刪掉？

想過後，展開對照
對象停止 A 之後
原本的映像仍保留，可繼續用來建立容器
容器 A已停止，程式不再執行；停止不等於刪除
容器 B仍在執行，不會因為停止 A 就一起停止

因此是兩個已建立的容器，其中一個在執行。映像的數量和執行中的容器數量，是兩件不同的事。

5. 修正程式後，為什麼還要換版？

假設舊映像裡的網站會把金額算錯，而你已修正電腦上的程式碼。正在執行的舊容器不會因此自動拿到新程式。

在這個以映像交付網站的流程中，需要先用修正版建立新映像，再要求 Kubernetes 用新映像執行應用、替換舊版。只把舊版重新啟動，仍會執行舊的計算邏輯。

Kubernetes 管理的是這類以容器執行的應用。至於它如何協調多台機器、如何安排容器，我們會在接下來的課程逐步建立。

主要來源：Kubernetes 的容器概念
