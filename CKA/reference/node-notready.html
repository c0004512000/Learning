Node NotReady：先看證據

Node 是承載 Pod 的機器。Ready=False 表示節點狀態檢查回報無法接受工作負載；Ready=Unknown 表示控制平面一段時間沒有收到節點心跳，兩者不可直接當成同一原因。

  1. kubectl get nodes -o wide：確認範圍與狀態。
  2. kubectl describe node <name>：看 Conditions、Events；同時記下時間。
  3. 若狀態指向 kubelet 或與控制平面通訊，登入對應節點檢查 systemctl status kubelet 與 journalctl -u kubelet -n 100 --no-pager。
  4. 按證據再檢查磁碟、記憶體、容器執行階段或 CNI；修復後重新看 Ready、事件與受影響 Pod。
