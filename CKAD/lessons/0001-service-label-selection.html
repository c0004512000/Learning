Service 怎麼知道
哪些 Pod 是它要找的？

今天只練一件事：看懂選取條件，判斷哪些 Pod 符合。

你有兩份相同的網站程式同時運作，想讓使用者透過同一個入口存取它們。Kubernetes 裡，執行這些容器程式的單位叫 Pod；提供穩定存取入口的資源叫 Service。

先不處理網路封包怎麼走。眼前的問題是：這個入口，要把哪些 Pod 視為同一組應用？

本課情境：所有 Pod 和 Service 都放在同一個 Namespace（資源的命名分區），而且都已就緒。先只看「選到了誰」。

1. 先給 Pod 一個可辨認的標籤

下面有三個 Pod。A、B 是網站，C 是另一個 API 程式。名稱只讓我們分辨個體；要表達「屬於哪個應用」，可以加上 label（標籤）。

Pod Aapp: web
Pod Bapp: webenv: prod
Pod Capp: api

app: web 是一組「鍵：值」：鍵是 app，值是 web。這是我們給資源的標記，不是 Kubernetes 讀取程式內容後自動猜出來的。

來源：Labels and Selectors。標籤可以重複出現在不同資源上。

2. Service 寫下「我要哪一組」

現在讓 Service 使用這個 selector（選取條件）：

selector:
  app: web

它的意思是：「找出具有 app: web 標籤的 Pod。」A 和 B 都符合；C 的值是 api，不符合。

B 多了一個 env 標籤，仍然符合。Selector 指定的條件必須滿足，但沒有要求 Pod 只能有那些標籤。

3. 多一個條件，會發生什麼事？

把 Service 的條件改成：

selector:
  app: web
  env: prod

這次要同時滿足兩個條件。Pod A 沒有 env: prod，不符合；B 兩個都有，符合。這不是「符合其中一個就好」。

來源：多個 selector 條件以 AND 組合。

4. 自己改一次

先預測，再切換。選取 app: api 會找到誰？加上 env: prod 後呢？

概念練習：即時比對下列資料，不會操作 Kubernetes。

selector:
  app: web
Pod Aapp: web

Pod Bapp: webenv: prod

Pod Capp: api

5. 換一組資料，自己判斷

不要只記 A 或 B。這次 Pod 的標籤換了。

Pod Dapp: shoptier: frontend
Pod Eapp: shoptier: backend
Pod Fapp: billingtier: frontend

條件只有 app: shop

選出所有符合的 Pod；沒有符合時可以不勾選。

D、E 都有 app: shop。tier 的差異不影響這次選取，因為條件沒有要求 tier。

條件是 app: shop 與 tier: frontend

先用自己的話說一次

一個 Pod 具有 app: shop 與 version: v2。Service 只要求 app: shop。它會被選到嗎？請說明原因。

6. 回到實際設定

在 Pod 設定裡，標籤位於 metadata.labels；在 Service 設定裡，條件位於 spec.selector。以下只是要比較的片段，不是完整部署檔：

# Pod 的片段
metadata:
  name: shop-v2
  labels:
    app: shop
    version: v2

# Service 的片段
spec:
  selector:
    app: shop

Pod 名稱 shop-v2 不必與 Service 名稱一致。這個 selector 比較的是 app 標籤。

選到 ≠ 已證明連得通。

標籤匹配只回答「哪些 Pod 符合條件」。實際連線還要確認 Pod 是否就緒、服務埠與應用是否正常。本課先停在選取規則。

來源：Service 的定義與 selector。本課限定有 selector 的 Service；沒有 selector 的 Service 屬於另一種配置。

今天留下這三件事

  • Label 是 Pod 帶著的鍵值標記；selector 是 Service 要求的條件。
  • 所有條件都必須符合；Pod 可以有額外標籤。
  • 判斷選取結果，和驗證真正連線，是兩個不同步驟。
