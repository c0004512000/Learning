WEEK 01 · DIAGNOSTIC LAB

Pod 在跑，
為什麼服務連不到？

先操作，再找出值得補強的觀念。本課是自訂練習，不是真實考題。

開始前

使用可重建的個人練習叢集，不要在公司正式環境執行。需有 kubectl、可用節點、可拉取 nginx 與 busybox image，以及建立 Namespace 的權限。本站不提供雲端 Terminal。

先執行 kubectl config current-context 與 kubectl get nodes 確認目標。新手可由 官方練習環境指南建立環境。鏡像拉取或節點未就緒屬環境問題，另記錄，不算解題時間。

1. 先做一輪，不看解答

建議先用 40 分鐘完成以下任務。時間是訓練目標，不是官方配分標準；卡住可以查官方文件。

  1. 建立 ckad-lab Namespace。
  2. 建立名稱為 web、image 為 nginx:1.28-alpine 的 Deployment，兩個副本。
  3. 透過 ConfigMap web-config 注入 APP_MODE=practice。
  4. 加入 HTTP readiness probe，檢查 port 80 的 /。
  5. 建立 Service web，port 80 轉至容器 port 80。
  6. 從同 Namespace 的另一個 Pod 請求 http://web。

完成證據：兩個 Ready Pod、環境變數正確、EndpointSlice 有 Ready 位址、測試 Pod 收到 nginx 頁面。

提示：先看哪些資訊？
kubectl -n ckad-lab get deploy,pods,svc
kubectl -n ckad-lab describe deployment web
kubectl -n ckad-lab get pods --show-labels
kubectl -n ckad-lab get endpointslices -l kubernetes.io/service-name=web
kubectl explain deployment.spec.template.spec.containers.readinessProbe

2. 建立故障情境

完成診斷後，用以下練習檔建立或覆寫本課的同名資源。檔案故意放了一個 Service 設定錯誤。

下載 01-service.yaml，在下載的目錄執行：

kubectl apply -f 01-service.yaml
kubectl -n ckad-lab rollout status deployment/web --timeout=120s
kubectl -n ckad-lab run probe --image=busybox:1.37 --restart=Never --command -- sh -c 'wget -T 5 -qO- http://web'
kubectl -n ckad-lab logs probe

若 logs 提示容器仍在建立，等 Pod 開始執行後再查。先確認 nginx Pods 為 Ready，再排查連線。

3. 用證據縮小範圍

Service 透過 selector（選取條件）尋找有對應 label（標籤）的 Pod。EndpointSlice 記錄後端端點與就緒狀態。Pod Running 只描述生命週期階段，不等於應用可接收流量。

先比較 Service selector 和 Pod labels，再檢查 EndpointSlice。若沒選到 Pod，繼續猜 DNS 或 Ingress 通常會浪費時間。

第一層提示：比較兩端
kubectl -n ckad-lab get svc web -o yaml
kubectl -n ckad-lab get pods --show-labels
kubectl -n ckad-lab get endpointslices -l kubernetes.io/service-name=web -o yaml

Service 的 app 值和 Pod 的 app 值相同嗎？

解答與驗證

練習檔中的 Service 選擇 app=wrong-label，但 Pod 的標籤是 app=web。修正 selector：

kubectl -n ckad-lab patch service web -p '{"spec":{"selector":{"app":"web"}}}'
kubectl -n ckad-lab get endpointslices -l kubernetes.io/service-name=web
kubectl -n ckad-lab delete pod probe --ignore-not-found
kubectl -n ckad-lab run probe --image=busybox:1.37 --restart=Never --command -- sh -c 'wget -T 5 -qO- http://web'
kubectl -n ckad-lab logs probe
kubectl -n ckad-lab exec deployment/web -- printenv APP_MODE

等待測試容器執行後，日誌應出現 nginx 歡迎頁，APP_MODE 應為 practice。也要把本地 YAML 的 selector 改成 web，避免下次 apply 再引入錯誤。這份檔案修正後也可作為前段診斷任務的參考答案。

4. 變化題：Ready 與 Running

把 readiness probe path 改成 /not-found，等待探測失敗。先預測 Ready 狀態、容器重啟次數與 Service 請求結果，再實際觀察。完成後改回 /。

判讀重點

在本課預設 Service 行為下，readiness 失敗的 Pod 不會作為正常就緒後端接收 Service 流量；readiness 失敗本身不會重啟容器。Liveness 才會在失敗達門檻後觸發容器重啟。注意更新 Deployment 本身會建立新 Pod，不能把 rollout 的替換誤認為 probe 重啟。
