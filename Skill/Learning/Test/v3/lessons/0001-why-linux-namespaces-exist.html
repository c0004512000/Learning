Namespace 為什麼存在？

Lesson 1

先從沒有 Namespace 的世界開始

Process 執行 application code，但 process table、hostname、network、filesystem 等系統狀態由 kernel 管理。Process 想取得或改變這些狀態，必須透過 kernel。

核心問題：如果所有 process 永遠只能看到同一份 kernel-managed state，要怎麼讓不同工作負載彼此隔離？

補強：Process 與 kernel

如果這裡還不直覺，先看 Process 與 kernel Reference，讀完會直接回到這裡。

再看一個具體入口：/proc

/proc 會讓 user space 看見 kernel 目前管理的 process 與 namespace 資訊。若你不確定它是不是普通檔案，先看 /proc 與 process lifecycle。

回到 Namespace

Namespace 的關鍵不是複製一顆 kernel，而是讓 kernel 對某些資源依 process 的 namespace membership 提供不同的 view。
