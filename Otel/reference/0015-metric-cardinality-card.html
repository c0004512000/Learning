Metric cardinality 預算卡

先算組合上限，再允許 measurement dimensions

估計上限 ≈ C₁ × C₂ × ... × Cₙ

route 20 × result 3 × region 4 = 240 combinations
再加 user_id 100,000 → 理論上限 24,000,000

上線前檢查

  1. 每個 key 描述 measurement，而非 Resource/Scope 嗎？
  2. 每個 value set 有明確上限與 owner 嗎？
  3. 是否用了 route template，而非 raw path？
  4. View 能否 allowlist 必要 keys？
  5. Alert 是否監控 otel.metric.overflow=true？

Overflow：總量仍可保留，但原 attribute combination 被移除；所有按原維度的 queries 可能低估。
