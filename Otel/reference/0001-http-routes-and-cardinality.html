HTTP Span：route、實際 URL 與 cardinality

Quick reference · 用於判讀 traces 與設計 attributes

先看一筆實際請求

GET https://api.example.com/v1/users/42?include=orders
概念 本例的值 OTel 表達與用途
實際 request URL https://api.example.com/v1/users/42?include=orders url.full；常見於 client Span，適合追查一次具體呼叫，但可能含敏感資料且是高基數。
實際 path /v1/users/42 url.path；保留實際 entity ID，因此通常是高基數。
matched HTTP route /v1/users/{userId} http.route；server framework 的 route template，必須是低基數。
logical API operation GET /v1/users/{userId} 不是單一 Attribute：http.request.method + http.route；通常也是 server Span name。
目標 host api.example.com server.address；回答「這個 network call 的目標 server 是誰」。
術語規則：「API endpoint」在日常對話中可能指 route、method + route、host + path，或完整 URL。記錄與討論時，優先使用上表的精確術語；若說 endpoint，先定義它指的是哪一種。

一個乾淨的 HTTP server Span

{
  "name": "GET /v1/users/{userId}",
  "kind": "SERVER",
  "attributes": {
    "http.request.method": "GET",
    "http.route": "/v1/users/{userId}",
    "http.response.status_code": 200
  }
}

同一個 route 的 /v1/users/42、/v1/users/99 都會聚合到同一個 http.route。因此可以穩定地比較此操作的 latency、error rate 與 traffic。

Cardinality（基數）

一個 Attribute 的 cardinality 是它在某個範圍內的唯一值數量。Metric 的 cardinality 則是每一筆 measurement Attributes 的唯一組合數量，不是 Attribute 數量，也不是資料筆數。

Attribute 典型值 基數 適合作為 metric dimension？
http.request.method GET、POST、DELETE 低：有限且受控 是
http.route /users/{userId} 低：route template 數量有限 是
http.response.status_code 200、404、500 通常低：HTTP code 值域受限 是
url.path /users/42 高：隨 entity 數量成長 否
url.full 完整 URL 與 query 高：path/query 組合持續增加 否
user.id、trace_id 使用者或每次請求的唯一 ID 高或極高 否

判別規則

  1. 值是否會隨使用者、訂單、請求、UUID、timestamp 或 query value 持續增加？會，即為高基數。
  2. 值是否是小而可列舉、且不隨流量成長的集合？是，即為低基數。
  3. 若放進 metric，是否要和其他 Attributes 一起分組？須評估組合數量，而非單一 Attribute。
40 routes × 6 methods × 10 status codes
  = 最多 2,400 種 metric attribute combinations

OTel Metrics SDK 預設每個 metric stream 最多追蹤 2,000 個 unique attribute combinations。達到上限後， 新的組合會匯入帶有 otel.metric.overflow=true 的 overflow data point：總量仍正確，但依原本 Attributes 分組或篩選的結果會不完整。這是保護上限，不是「2,000 以下必然安全」的定義。

設計原則：高基數值不是完全不能放進 trace 或 log；它們可協助單次診斷，但需評估 backend indexing/storage 成本、retention 與 PII/secret redaction。高基數值不應作為 metric measurement Attribute，也不應放進 Span name。

兩個常見錯誤

Bad:  http.route = "/v1/users/42"
Good: http.route = "/v1/users/{userId}"

Bad:  span.name = "GET /v1/users/42"
Good: span.name = "GET /v1/users/{userId}"
