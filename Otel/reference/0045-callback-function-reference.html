Callback 到底是什麼？

先搞懂「把函式交出去」與「誰在什麼時候把你叫回來」

先抓住一句話： callback（回呼函式）不是特殊語法，也不是特殊種類的 function。它只是某個函式在一段互動裡扮演的角色：你把函式本身交給別人，之後由對方決定何時呼叫它。

1. 先分清楚：函式本身 vs 立刻呼叫函式

function handleClick(event) {
  console.log(event.target)
}

handleClick      // 函式本身
handleClick()    // 現在立刻呼叫這個函式

這兩個看起來只差一對括號，但意義完全不同。

寫法意思誰決定執行時間
handleClick取得這個函式本身，可以把它存起來或傳給別人還沒有執行
handleClick()現在就呼叫函式目前這行程式

2. Callback 的核心動作：把函式交出去

document.addEventListener('click', handleClick)

這裡傳入的是 handleClick，不是 handleClick()。

意思不是「現在執行 handleClick」，而是：

document，這個函式先交給你。之後如果有符合條件的 click event，請你再呼叫它。
Callback 最重要的判斷方式： 如果你看到「一個函式被當成參數傳給另一個 API / 函式，而接收方之後會呼叫它」，那個被交出去的函式就在扮演 callback。

3. 為什麼叫 call back？

back 是相對於最一開始的控制方向。

第一步：你的程式先呼叫瀏覽器 API

你的程式
   │
   └──► document.addEventListener('click', handleClick)
                                  │
                                  └── 把 handleClick 交出去

之後：瀏覽器在適當時機「呼叫回」你的程式

瀏覽器
   │
   └──► handleClick(event)
            ↑
            這就是 call back

所以不是因為 callback 一定「往回傳資料」，也不是因為一定會非同步。名稱描述的是控制權先交給別人，之後由對方再呼叫回你提供的函式。

4. 放回你現在的 click event 情境

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

完整流程是：

  1. JavaScript 建立 handleClick 這個 function。
  2. JavaScript 呼叫 document.addEventListener(...)。
  3. 把 handleClick 函式本身交給瀏覽器。
  4. 瀏覽器把這個 listener 設定保存在 document 的 event listener list。
  5. 之後使用者真的點擊頁面。
  6. 瀏覽器建立並分派 click event。
  7. 分派路徑走到 document 時，瀏覽器發現有相符的 click listener。
  8. 瀏覽器主動執行 handleClick(event)。
  9. JavaScript engine 開始執行你寫在 handleClick 裡的程式。
因此，JavaScript 不是「抓到 event」。 更精確的說法是：JavaScript 先把 callback 登記給瀏覽器；瀏覽器在事件分派時找到這個 callback，然後呼叫它，並把此次的 event 物件當作參數傳進去。

5. Trigger、event、listener、callback 不要混在一起

名詞在 click 情境中代表什麼
Trigger / 觸發條件使用者真的做了點擊這個動作
Event瀏覽器為這次發生的事情建立的事件物件，例如 click
Event listener登記在某個 EventTarget 上的「事件類型 + callback + options」設定
Callback真正會被瀏覽器呼叫的函式，例如 handleClick

6. Callback 不一定是非同步

Callback 描述的是「誰負責呼叫這個函式」，不是描述同步或非同步。

同步 callback

function double(x) {
  return x * 2
}

[1, 2, 3].map(double)

double 被傳給 map，再由 map 呼叫，因此它也是 callback；只是這些呼叫會在 map 執行期間同步發生。

事件 callback

document.addEventListener('click', handleClick)

handleClick 何時被呼叫，由之後的事件分派決定。

所以：
callback ≠ async
callback ≠ event
callback ≠ listener 本身
callback = 被交給另一方、由另一方負責呼叫的函式

7. 用 Python 類比

如果你比較熟 Python，可以用同樣的控制方向理解：

def handle(value):
    print(value)

def run(callback):
    result = 123
    callback(result)

run(handle)

這裡：

你的程式呼叫 run(handle)
            │
            └── 把 handle 函式交給 run

run() 內部之後呼叫

callback(result)
      │
      └── 實際上就是 handle(result)

handle 的角色就是 callback。

8. 一秒判斷法

看到一段程式時，問自己三題：

  1. 是不是有一個函式被當作值交出去？
  2. 接收它的另一方是不是會在自己的流程裡呼叫它？
  3. 真正決定「什麼時候呼叫」的是不是接收方？

如果三題都是「是」，那個函式就是 callback。

Recap

  • Callback 是一種角色，不是特殊 function 類型。
  • handleClick 是函式本身；handleClick() 是現在呼叫它。
  • Callback 的關鍵是：把函式交給另一方，再由另一方決定何時呼叫。
  • back 指的是控制權先交出去，之後接收方再「call back」進你的程式。
  • 在 DOM event 中，瀏覽器分派事件並呼叫 listener 裡保存的 callback。
  • Callback 不等於 async；同步 API 也可以使用 callback。
