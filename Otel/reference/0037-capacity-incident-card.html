Collector Capacity Incident Card

先定位瓶頸與 component class，再決定 scale

  1. 分 signal/component/destination 量 incoming、completed、failed、refused、bytes。
  2. 看 queue size、capacity、oldest age 與斜率：在長、持平、還是排空？
  3. CPU saturation、memory refusal、network saturation、backend throttle，哪個最早發生？
  4. Component 是 stateless、scraper 還是 stateful；新增 replica 需要 target ownership/affinity 嗎？
  5. Scale Collector 會提升 completion，還是只增加對已過載 backend 的壓力？
  6. Recovery throughput 是否大於 incoming；backlog 的預估 drain time 是多少？
  7. Scale-down 前確認 queue 為低、state 可 drain、connection rebalance 與 minimum replicas。
