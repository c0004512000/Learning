Span lifecycle / export 快速卡

Span ended、processor received、exported、stored 是不同事件

Span 什麼時候算結束？

當描述的 operation 已經完成，Span 應設定 end time。 End 之後，Span 的 duration 才固定，正常情況也不應再修改 attributes、events 或 status。

Python 寫法你怎麼知道它 ended
with tracer.start_as_current_span(...) as span:程式離開 with block 時，context manager 會替你 end Span。
span = tracer.start_span(...)你必須自己在 operation 完成時呼叫 span.end()。
 
with tracer.start_as_current_span("calculate_total") as span:
    total = sum(prices)
    # Span 還在進行

# 到這一行時，with 已離開 → Span 已 end
最重要的判斷：Span 的邊界應跟「你想量測的 operation」一致，不是跟函式、scope 或 exporter 任意對齊。

Debug 時有哪些證據？

你看到的證據可以直接證明什麼不能直接證明什麼
程式已離開 with該 context manager 已執行 Span endExporter 一定成功
span.end() 已執行Span end 被明確呼叫Backend 已收到
span.is_recording() 變成 falseSDK 通常已不再接受新的 Span 資料一定是 sampling 或 export 成功
SimpleSpanProcessor + ConsoleSpanExporter 已印出 SpanSpan 已 end，Processor/Exporter 路徑至少走到 console遠端 backend 已儲存

反過來不成立：「terminal 沒看到 Span」不能直接推論「Span 沒有 end」。也可能是 Processor 沒掛、Exporter 沒連、sampling/recording 行為或 stdout 可見性出了問題。
