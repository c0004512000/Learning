Span / Event / Attribute 決策卡

以最小充分證據設計 telemetry

需要獨立 duration / outcome / causal node？
  ├─ 是 → Span
  └─ 否 → 發生時間有診斷意義？
           ├─ 是 → Event
           └─ 否 → Attribute（或不記錄）

Span name 三個檢查

  1. 描述的是 operation 類型，不是單次 instance。
  2. 值能穩定聚合，不含 user ID、UUID、完整 path 等動態值。
  3. 名稱足以區分 SRE 需要比較的工作類別。

Attribute 四道守門

守門問題若答不出來
事故時用它做什麼查詢？先不要記錄。
值或值組合會無界成長嗎？改成低基數分類或確認 backend 成本。
含個資、credential、payload 嗎？移除、遮罩或只記安全分類。
Sampler 決策時已經知道嗎？需要 sampling 時，盡量在 Span 建立時提供。
SRE 判斷：telemetry 的價值不是欄位數量，而是它能否以可接受成本排除事故假設。
