Collector Memory Pressure Debug Card

分清 inflow、retention、GC、refusal 與 host kill

  1. 核對 container/host limit、limiter hard/soft/spike 與 process heap/RSS 的單位。
  2. 建立時間線：traffic、queue growth、backend failures、GC、refused items、restart/OOMKill。
  3. 確認 memory limiter 是每條 pipeline 第一個 processor，前一元件能否 retry/backpressure。
  4. 找 live retention owner：batch、exporter queue/WAL、tail sampling、connector cache、receiver buffer。
  5. 看 accepted/refused by signal、queue oldest age、GC CPU/效果；GC 無效表示 live references 仍持有資料。
  6. 檢查 spike 是否可能在兩次 measurement 間跨過 hard/container limit。
  7. 先降低 inflow/retention 或擴容，再調 limits；不要只提高 hard limit掩蓋不穩定 queue。
