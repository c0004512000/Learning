Collector Processor 順序判斷卡

把每個 processor 寫成 precondition → transformation → postcondition

Processor 類型通常的 ordering constraint理由
Memory limiter第一個 processor儘早 backpressure，降低後續額外配置
Enrichment/normalization在依賴新欄位的 filter 前Filter precondition 必須先成立
Redaction/sanitize在 buffer/debug/export 前敏感資料不應進入後續 sink/queue
Drop/sampling在 batch 前不要先 buffer 最終會丟棄的資料
Batch通常靠近 exporter在最終保留資料上做輸出批次化

例外：「通常」不是盲目模板；若 processors 有不同 preconditions，先畫 dependency graph。
