Semantic Convention 遷移卡

先版本化契約，再允許 producers/consumers 獨立演進

  1. Inventory：service、scope name/version、schema URL、實際欄位。
  2. Contract：pin target semconv/schema 與 owner。
  3. Canary：看 raw OTLP，不只看 UI alias。
  4. Compatibility：consumer dual-read 或單一 schema translation owner。
  5. Rollout：按 cohort 觀察 old/new traffic 與 query correctness。
  6. Retire：等 producers 與 retention window 都完成再刪舊查詢。

Schema URL：描述 producer schema identity；沒有 schema-aware translator 時，不會自動改欄位。
