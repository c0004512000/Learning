Log correlation 與重複資料判斷卡

先記住：LogRecord 不在 Span 裡；它靠 TraceId / SpanId 對回 Span

第一性模型： Span 與 LogRecord 是兩份獨立 telemetry。若 LogRecord 帶有和某個 Span 相同的 TraceId / SpanId， backend 就能知道兩者來自同一 execution context，這叫 log correlation。 
Span
  trace_id = abc123
  span_id  = def456

LogRecord
  trace_id = abc123
  span_id  = def456

same IDs → related

不要和 Span Event 混在一起

東西資料關係
Span Event真的存在 Span 裡，是 Span timeline 上的一個 timestamped event。
LogRecord是獨立 Logs signal；backend 可用 TraceId / SpanId 把它顯示在相關 Span 附近。
為什麼 UI 看起來像「Span 裡有 Log」？ Trace UI 可以拿目前 Span 的 TraceId / SpanId 去 log backend 查 matching LogRecords，再放到同一個畫面。這是 UI correlation，不代表 LogRecord 被儲存在 Span object 裡。

沒有 trace_id

  1. Log emit 時是否真的位於 current Span 內？
  2. Async/thread boundary 是否保留 Context？
  3. Logging bridge 是否擷取 trace fields？
  4. Exporter/Collector/backend mapping 是否保留？

同一 log 出現兩次

  1. 同一 logger 是否有多個 handlers？
  2. logger.propagate 是否又送到 root handler？
  3. 是否同時 direct OTLP 與 stdout/file collection？
  4. Collector 是否有重複 receivers/routes？
