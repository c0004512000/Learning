OpAMP Convergence Debug Card

不要問「設定送到了嗎？」；依序證明 identity、offer、apply、effective state 與 data-plane outcome

五個不同的事實

  1. Targeted：Server selector 選中了正確 agent instance。
  2. Offered：ServerToAgent 帶有預期 config_hash。
  3. Received：Agent 回報的 last_remote_config_hash 相符。
  4. Applied：remote_config_status=APPLIED；若 FAILED，保存 error message。
  5. Effective：Agent 回報的 effective config 與預期合成結果一致，且資料面 canary 通過。

症狀 → 下一個證據

症狀先查不要先假設
Agent 不在線TLS/auth、network、instance UID、reconnect、first status reportCollector pipeline 壞了
Server 一直重送server hash vs last_remote_config_hash、status compression/sequence gap重送本身就是 bug
狀態 APPLYING 過久apply deadline、Supervisor/agent log、process restart與 health已經生效
狀態 FAILEDerror message、final config validation、local/remote merge、component availability網路問題
狀態 APPLIED 但資料消失effective config、component health、internal telemetry、synthetic OTLP canary控制面成功等於資料面成功

停止 rollout 的條件

  • 身份或 cohort 無法唯一證明。
  • 新 hash 在 deadline 內未收斂為 APPLIED。
  • Effective config 不符合 reviewed result。
  • Collector health 或 telemetry SLO 退化。
  • Rollback 的舊 hash 也無法收斂。
