Fleet Rollout Debug Card

先停止擴散，再把問題分類成 targeting、delivery、apply、effective state 或 data plane

事故前五問

  1. 哪一個 immutable revision/hash？由誰批准？
  2. 哪些 instance UID 理應在 cohort，實際又有哪些？
  3. 各群的 desired/received/applied/effective 分布是什麼？
  4. 失敗是否集中在 distribution、version、region、OS 或 local overlay？
  5. synthetic signals、drop/reject、queue 與 backend ingest 何時開始偏移？

分類與處置

類別證據處置方向
Targeting錯誤 UID/selector/cohort立即 halt；恢復原 revision，修 selector
Deliveryreceived hash 不同或離線查 control-plane auth/network/reconnect
ApplyAPPLYING timeout / FAILED查 validation、能力、Supervisor與 process health
Effective driftAPPLIED 但 final config 不同查 precedence、local overlay、secret/provider resolution
Data plane設定收斂但 canary/SLO 壞rollback；依 signal/pipeline/component 定位

完成的定義

Rollback 指令送出不算完成；last-known-good effective state 收斂，且相同 data-plane invariants 恢復才算。
