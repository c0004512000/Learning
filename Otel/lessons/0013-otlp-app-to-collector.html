13. Application 透過 OTLP 送進 Collector

替換資料出口，保持 telemetry 意義不變 · Lesson 13 of N

本課成果與邊界

你會把 Lesson 3 的 Console exporter 換成 OTLP/HTTP exporter，並能從第一性原理解釋每一個 endpoint、 protocol 與 component 的方向。本課先建立完整資料路徑，不加入 backend、TLS、authentication、retry tuning 或 Kubernetes；也不會自動安裝套件或執行任何 Windows executable。

主要來源：OpenTelemetry Python — Exporters、OTLP Specification

先抓住不變量：資料的意義與去向是兩個問題

Instrumentation 回答：發生了什麼工作？
  span name、kind、attributes、events、status、parent

Export configuration 回答：已完成的 telemetry 要去哪裡？
  processor、exporter、protocol、endpoint

把 ConsoleSpanExporter 換成 OTLPSpanExporter，不應改變 checkout.calculate_total 的名字、attributes 或 parentage。這是 OTel 分層設計的價值： business instrumentation 描述事實，deployment configuration 決定如何搬運事實。

SRE 判讀原則：若更換 backend 或 Collector 就必須大量重寫埋點，通常代表「訊號語意」與 「輸出目的地」耦合太深。OTLP 的目的之一，就是以 OTel data model 搬運資料，降低出口切換造成的資訊損失與改動面。

完整路徑不是一個 exporter，而是兩個 process 的接力

checkout application process
  Span 結束
    → BatchSpanProcessor
    → OTLP/HTTP Span Exporter（HTTP client）
    → POST http://127.0.0.1:4318/v1/traces

Collector process
  OTLP receiver（HTTP server，listen 127.0.0.1:4318）
    → batch processor
    → debug exporter
    → Collector logging output

同一個單字 exporter 會在兩個 process 各出現一次，但角色不同：application exporter 把資料送出 process； Collector exporter 把 pipeline data 送往下一個 destination。本課 Collector 使用 debug exporter，所以第二段沒有 network backend。

為什麼選 OTLP/HTTP 4318，而不是只背「OTLP port」？

OTLP 是 telemetry transport protocol；它可承載於不同 transport。必須把 transport、port 與 path 一起看：

Transport本課 Collector listenerTrace destinationPython exporter 類別
OTLP/HTTP + protobuf127.0.0.1:4318/v1/tracesproto.http...OTLPSpanExporter
OTLP/gRPC127.0.0.1:4317gRPC service/methodproto.grpc...OTLPSpanExporter

因此「使用 OTLP」仍不足以判斷 endpoint 是否正確。HTTP exporter 指向 4317，或 gRPC exporter 指向 http://127.0.0.1:4318/v1/traces，都是 transport mismatch；兩端即使都叫 OTLP 也無法完成對話。

程式只替換輸出層

範例位於 examples/0013-app-to-collector.py。先比較最重要的差異：

# Lesson 3：輸出到 application console
BatchSpanProcessor(ConsoleSpanExporter())

# Lesson 13：輸出到 Collector 的 OTLP/HTTP receiver
exporter = OTLPSpanExporter(
    endpoint="http://127.0.0.1:4318/v1/traces"
)
BatchSpanProcessor(exporter)

Span 建立與 attributes 完全不必知道 Collector 的存在。Python 的 OTLP/HTTP exporter 來自額外 dependency opentelemetry-exporter-otlp-proto-http；dependency 不存在時，import failure 是 application packaging 問題， 還沒走到 network 或 Collector。

為什麼短程式最後呼叫 shutdown？

provider.shutdown()

BatchSpanProcessor 以非同步批次降低 request path 的輸出成本。這也表示 Span 結束不等於 bytes 已立即離開 process。 短命 demo 若立刻退出，buffer 可能尚未 export；controlled shutdown 會要求 processors/exporters 完成關閉流程並 flush。 長時間服務則應把 shutdown 接到 application lifecycle，而不是每個 request 都呼叫。

執行前的必要條件

  1. Python environment 已有 API、SDK 與 opentelemetry-exporter-otlp-proto-http dependency。
  2. Collector 使用 Lesson 12 config，且 OTLP/HTTP receiver 確實 listen 127.0.0.1:4318。
  3. Collector traces pipeline 引用了 otlp receiver 與 debug exporter。
  4. 再啟動 application，觀察 Collector output，而非期待 application 印出完整 Span JSON。

這些是未來 lab 的執行順序，不代表本課已替你安裝或啟動軟體。依你的執行政策，Collector 實作會優先設計成 既有 Docker 環境中的容器方案；未經你明確授權，不下載、安裝或執行 Windows .exe。

SRE debugging lab：用邊界二分，不要一次猜到底

症狀：「Collector debug output 沒有 Span。」先把路徑切成四個可證偽的假設：

邊界最先查的證據若失敗，問題類別
Instrumentation → SDKSpan 是否 recording、是否正常 endprovider / sampler / lifecycle
Processor → app exportershutdown/flush 與 exporter error logbuffer / queue / exporter config
Network → Collector receivertransport、host、port、path；listener 是否存在endpoint / protocol / reachability
Receiver → Collector exporteractive traces pipeline 與 Collector internal errorspipeline activation / processor / exporter

故障注入 A：把 endpoint 改成 4317

OTLPSpanExporter(endpoint="http://127.0.0.1:4317/v1/traces")

預測：HTTP client 對 gRPC listener 說錯語言。這不是 Span data model 錯，也不是 sampling 的直接證據； 先把它歸類為 transport/listener mismatch。

故障注入 B：移除 shutdown

預測：短命 process 可能在批次送出前結束，因此「偶爾看不到」具有 lifecycle/flush 的嫌疑。 注意這只是可檢驗假設，不代表所有遺失都應用 shutdown 解釋；常駐服務要查 queue、timeout 與 exporter failure evidence。

故障注入 C：Collector 宣告 receiver，但 traces pipeline 沒引用

預測：不能以「4318 有 listener」推論 Span 會走到 debug exporter。listener availability 與 active pipeline path 是兩個不同命題，回到 Lesson 12 的 declaration/activation distinction。
