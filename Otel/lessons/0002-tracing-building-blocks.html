2. 從 Span 推導 Tracer 與 TracerProvider

先從已經看得懂的 Span 開始，再問「誰建立它？」· Lesson 2 of N

這一課只要拿下一個勝利

看完後，你應該能不用背架構圖，自己從 Span 推導出 Tracer 與 TracerProvider 為什麼需要存在，並看懂 get_tracer() 與 start_as_current_span() 在做什麼。

本課刻意不先講 Processor、Exporter。 它們只有在下一課真的遇到「Span 建好了，但我要怎麼把它看見？」時才有存在的理由。

1. 先從 Span 開始：我們到底要產生什麼？

Lesson 1 已經知道，Span 是某一次工作的觀測資料。 假設程式正在執行： 

calculate_total()

如果我們想觀測這一次執行，就需要留下類似：

name = "calculate_total"
start_time = ...
end_time = ...
duration = ...
attributes = ...

這一份「描述某一次工作」的資料，就是 Span。

calculate_total 第 1 次執行  -> Span A
calculate_total 第 2 次執行  -> Span B
calculate_total 第 3 次執行  -> Span C

來源：OpenTelemetry — Traces

2. 下一個必要問題：Python 程式要怎麼建立 Span？

既然我們需要 Span，那程式裡一定要有某個東西負責建立它。 OpenTelemetry 把這個物件叫做 Tracer。 

span = tracer.start_span("calculate_total")

先不要替 Tracer 加更多責任。現在只記：

Tracer = 程式拿來建立 Span 的物件。

3. 用 Python Logger 對照 Tracer

如果你用過 Python logging，這個結構其實很熟悉： 

import logging

logger = logging.getLogger("checkout")
logger.info("calculating total")

Logger 不是那一筆 log 本身；它是程式拿來產生 log record 的物件。 Tracer 在 tracing 世界裡扮演非常相似的角色。

LoggingTracing
LoggerTracer
產生 Log Record建立 Span
logger.info(...)tracer.start_span(...)
類比的邊界：Logger 與 Tracer 的內部實作並不相同；這個類比只用來抓住角色： 「程式持有一個物件，再用它產生某種 telemetry」。

4. 那 Tracer 從哪裡來？

Python logging 常見寫法是：

logger = logging.getLogger("checkout")

Tracing 的使用方式也很像：

from opentelemetry import trace

tracer = trace.get_tracer("checkout")

現在先把它直接讀成：「給我一個 checkout 這組程式碼使用的 Tracer。」 它不是在「取得一條 Trace」，也不是去 backend 查資料。 

get_tracer("checkout")
        |
        v
      Tracer
        |
        | start_span("calculate_total")
        v
       Span

"checkout" 跟 "calculate_total" 差在哪？

tracer = trace.get_tracer("checkout")
span = tracer.start_span("calculate_total")
名稱回答的問題
"checkout"哪一組程式碼在使用這個 Tracer？
"calculate_total"這一個 Span 描述的是什麼工作？

官方正式名稱會把第一個稱作 instrumentation scope name； 例如通常可以使用 package、module 或 instrumentation library 的名稱。 現在先把它理解成「誰在產生這些 Span」即可。

來源：OpenTelemetry Trace API — Get a Tracer

5. 現在才有理由問：誰負責提供這些 Tracer？

一個 application 不一定只有一個 Tracer： 

checkout_tracer = trace.get_tracer("myapp.checkout")
db_tracer       = trace.get_tracer("sqlalchemy")
http_tracer     = trace.get_tracer("requests")

如果 application 裡很多地方都需要 Tracer，而且它們應該共享 tracing 的設定， 那就需要一個 application 層級的物件負責這件事。 這個角色才叫 TracerProvider。

TracerProvider = 管理這組 tracing 的共用設定，並提供 Tracer 的物件。

官方 specification 也把 TracerProvider 定義為取得 Tracer 的地方， 並要求 tracing 的共用 configuration 由 Provider 持有，而不是散落在每個 Tracer 上。

來源：OpenTelemetry Trace API — TracerProvider、 Tracing SDK — Configuration

6. 把它翻成真正的 Python

現在這三行才不再只是陌生語法：

from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider

provider = TracerProvider()
trace.set_tracer_provider(provider)
tracer = trace.get_tracer("myapp.checkout")

逐行翻成人話：

provider = TracerProvider()
# 建立 application tracing 的管理者

trace.set_tracer_provider(provider)
# 告訴 OTel：之後取得 Tracer 時使用這個 Provider

tracer = trace.get_tracer("myapp.checkout")
# 取得給 myapp.checkout 這組程式碼使用的 Tracer

接著才是 runtime：

with tracer.start_as_current_span("calculate_total") as span:
    total = sum(prices)

進入 with 時建立並開始 Span；離開 block 時 Span 結束。 這就是下一課真正會執行的核心。

7. Trace 跟 Tracer 千萬不要混在一起

名詞它是什麼
Trace同一次端到端 operation 的多個相關 Span 所形成的因果結構。
Tracer程式裡拿來建立 Span 的物件。

所以 trace.get_tracer() 的意思不是「取得 Trace」，而是「透過 tracing API 取得 Tracer」。 真正的 Trace 是 Span 被建立並透過 Trace ID / parent 關係串起來後形成的資料。

8. 到現在才補 API / SDK 的位置

現在物件角色已經清楚，再看 package boundary 就簡單很多： 

# instrumentation 呼叫的公開 tracing 操作
from opentelemetry import trace

# application 安裝的具體 tracing implementation
from opentelemetry.sdk.trace import TracerProvider

API 是 instrumentation code 可以呼叫的操作介面； SDK 則提供真正記錄 Span、套用 tracing configuration 的實作。 如果 application 沒有安裝 SDK provider，API 仍能被 library 呼叫，但預設不會產生可輸出的 recorded telemetry。

來源：OpenTelemetry Python — Manual Instrumentation、 Trace API — Behavior without an SDK

最後 Recap：每個名詞只留一句話

Span：某一次工作的觀測資料。

Trace：同一次端到端 operation 中，彼此有因果關係的一組 Span。

Tracer：程式拿來建立 Span 的物件。

TracerProvider：管理 application 的共用 tracing 設定，並提供 Tracer 的物件。

Tracing API：instrumentation code 呼叫 tracing 功能的公開介面。

Tracing SDK：真正執行 recording 與 tracing configuration 的具體實作。
