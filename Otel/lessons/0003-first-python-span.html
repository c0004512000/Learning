3. 讓第一個 Python Span 出現在眼前

建立 Span → 決定要記什麼 → 確認何時結束 → 看見輸出 · Lesson 3 of N

這一課只要拿下一個勝利

Lesson 2 已經建立：TracerProvider 提供 Tracer，Tracer 建立 Span。 這一課把它跑起來，並補齊兩個真正會在實作時遇到的問題： 什麼資訊值得放進 Span？Span 到底什麼時候算結束？

1. 先只使用你已經懂的三個角色

from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider

provider = TracerProvider()
trace.set_tracer_provider(provider)
tracer = trace.get_tracer("training.checkout")

with tracer.start_as_current_span("checkout.calculate_total"):
    total = 100 + 200

2. 從「我要看見 Span」推出 Exporter

本課最短的 feedback loop 是：把完成的 Span 印到 terminal。 因此需要一個知道如何把 Span 輸出到目的地的角色：SpanExporter。 

ConsoleSpanExporter()
ConsoleSpanExporter：把可輸出的 Span 寫到 stdout。它不是 tracing backend，也不保存歷史資料。

3. 誰在 Span 結束時把它交給 Exporter？

Tracer 只負責建立 Span；Exporter 只負責輸出。中間需要接住 Span lifecycle 的角色： SpanProcessor。

5. 再加 Resource：這些 telemetry 是誰產生的？

from opentelemetry.sdk.resources import Resource

resource = Resource.create({
    "service.name": "checkout-demo"
})

provider = TracerProvider(resource=resource)

service.name 描述的是所有這些 telemetry 的 producer identity，不是單次 operation 的內容。 所以它屬於 Resource，而不是每個 Span 都手動重複設定。

6. 什麼時候我才應該替 Span 加 Attribute？

不要從「程式裡有哪些變數」開始想。先問： 這份資訊能不能幫我查詢、分組、比較，或在事故時排除假設？ 

這份資訊描述整段 operation 的性質或結果？
  ├─ 否 → 某一個有意義的時間點？ → Event
  │        需要自己的 duration / outcome？ → Child Span
  │        都不是 → 通常不要記
  │
  └─ 是 → 我之後會拿它 filter / group / debug 嗎？
           ├─ 是 → Attribute
           └─ 否 → 通常不要記
資訊適合的模型理由
cart.item_count=3Attribute描述這次 operation 的背景，可用於比較與除錯。
retry.startedEvent重點是「什麼時候發生」。
呼叫 payment serviceChild Span它有自己的 duration、outcome 與 causal position。
service.nameResource所有 Span 共用的 producer identity。

所以本課的： 

span.set_attribute("app.cart.item_count", len(prices))
span.set_attribute("app.cart.total_cents", total)

資料模型上都可以是 Attribute，因為它們描述這一次 calculate_total operation。 但這只是教學範例：production 不應為了「資料看起來完整」就把所有值都記進去。 如果某欄位沒有明確查詢／除錯價值，或含敏感資料、成本過高，就不要記。

Attribute 的一句話：描述「這一次 operation」的可查 key-value metadata。

來源：Trace API — Set Attributes、 Semantic Conventions design guidance

7. Span 到底什麼時候算「結束」？

先回到 Span 的本質：Span 描述一段 operation，而且它需要 start time 與 end time。 當你要描述的 operation 完成時，就應該 End Span。

Python 最常見的兩種方式：

A. 用 with：離開 block 自動 End

with tracer.start_as_current_span("checkout.calculate_total") as span:
    prices = [1999, 1250, 425]
    total = sum(prices)
    # 這裡 Span 還在進行

# 程式走到這裡：with block 已離開 → Span 已 End

這也是你目前範例使用的方式。即使 block 因 exception 離開，context manager 也負責結束這個 Span。

B. 手動建立：你自己呼叫 end()

span = tracer.start_span("checkout.calculate_total")
try:
    total = sum(prices)
finally:
    span.end()

如果你用這種寫法卻忘了 span.end()，這個 Span 的 lifecycle 就沒有被正確收尾。 OTel specification 明確要求：被建立的 recording Span 必須被結束。

Span End 的一句話：告訴 SDK「這個 operation 到這裡完成」，固定 end time / duration，並觸發後續 SpanProcessor lifecycle。

來源：OpenTelemetry Trace API — End、 OpenTelemetry Python — Creating spans

8. Debug 時，我怎麼知道 Span 有沒有 End？

不要只看「terminal 有沒有資料」。依證據強度分開判斷：

證據你能得出的結論
控制流程已離開 with這個 context-managed Span 已呼叫 End。
你確認程式走過 span.end()手動 Span 已收到 End。
span.is_recording() 在 End 後為 falseSDK 通常已不再接受新的 attribute/event/status。
SimpleSpanProcessor + ConsoleSpanExporter 印出 SpanSpan 已 End，而且 Processor/Exporter 路徑至少走到 console。
反過來不成立：terminal 沒看到 Span，不代表它一定沒 End。 也可能是 Processor 沒註冊、Exporter 沒連好、sampling/recording 行為或 stdout 可見性出了問題。

9. 現在才組成完整的 Python 範例

from opentelemetry import trace
from opentelemetry.sdk.resources import Resource
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import (
    SimpleSpanProcessor,
    ConsoleSpanExporter,
)

resource = Resource.create({"service.name": "checkout-demo"})
provider = TracerProvider(resource=resource)
provider.add_span_processor(
    SimpleSpanProcessor(ConsoleSpanExporter())
)
trace.set_tracer_provider(provider)

tracer = trace.get_tracer("training.checkout")

with tracer.start_as_current_span("checkout.calculate_total") as span:
    prices = [1999, 1250, 425]
    span.set_attribute("app.cart.item_count", len(prices))
    total = sum(prices)
    span.set_attribute("app.cart.total_cents", total)
    print(f"Total: {total} cents")

# 到這裡 Span 已 End；SimpleSpanProcessor 已有機會把它交給 ConsoleSpanExporter

11. SRE debug：terminal 沒有 Span，要從哪裡切？

1. 程式有沒有真的進入 start_as_current_span()？
2. operation 有沒有走到 Span End？
3. Provider 有沒有註冊 SpanProcessor？
4. SpanProcessor 有沒有連到正確 Exporter？
5. Exporter 的 stdout / network destination 是否真的可見？

核心習慣：先找 telemetry 最後在哪個已知節點存在，再檢查它到下一個節點的交接。

練習：檢查真正的理解

Q1. cart.item_count=3 為什麼適合當 Attribute？
Q2. 使用 with tracer.start_as_current_span(...) 時，Span 最直接在什麼時候 End？
Q3. terminal 沒有看到 ConsoleSpanExporter 輸出，能不能直接斷定 Span 沒有 End？

最後 Recap：每個名詞只留一句話

Span：某一次 operation 的觀測資料，包含 start/end time 與診斷 metadata。

Attribute：描述這一次 operation、可用於查詢與除錯的 key-value metadata。

Span End：宣告 operation 完成、固定 end time / duration，並觸發後續 processing lifecycle。

SpanProcessor：接收 Span lifecycle，並把完成的 Span交給後續處理。

SpanExporter：把可輸出的 Span 資料送到某個目的地。

Resource：描述產生 telemetry 的 service / entity 共用 identity。

如果你還不能回答兩題，就先停在這裡： 「為什麼這個值是 Attribute 而不是 Event / Child Span？」以及「這個 Span 的 operation 到哪一行才真正完成？」
