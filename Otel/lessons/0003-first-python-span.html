3. 讓第一個 Python Span 出現在眼前

建立 Span → 決定要記什麼 → 確認何時結束 → 看見輸出 · Lesson 3 of N

這一課只要拿下一個勝利

Lesson 2 已經建立：TracerProvider 提供 Tracer，Tracer 建立 Span。 這一課把它跑起來，並只補齊實作第一個 Span 時立即需要的問題： 怎麼讓 Span 被輸出、什麼資訊值得放進 Span、Span 什麼時候算結束。

本課只使用已經建立必要性的概念。 如果某個 telemetry 模型不是理解第一個 Span 的必要條件，就延後到它真正有用時再介紹。

1. 先只使用你已經懂的三個角色

from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider

provider = TracerProvider()
trace.set_tracer_provider(provider)
tracer = trace.get_tracer("training.checkout")

with tracer.start_as_current_span("checkout.calculate_total"):
    total = 100 + 200

2. 從「我要看見 Span」推出 Exporter

本課最短的 feedback loop 是：把完成的 Span 印到 terminal。 因此需要一個知道如何把 Span 輸出到目的地的角色：SpanExporter。 

ConsoleSpanExporter()
ConsoleSpanExporter：把可輸出的 Span 寫到 stdout。它不是 tracing backend，也不保存歷史資料。

3. 誰在 Span 結束時把它交給 Exporter？

Tracer 只負責建立 Span；Exporter 只負責輸出。中間需要接住 Span lifecycle 的角色： SpanProcessor。

5. 再加 Resource：這些 telemetry 是誰產生的？

from opentelemetry.sdk.resources import Resource

resource = Resource.create({
    "service.name": "checkout-demo"
})

provider = TracerProvider(resource=resource)

service.name 描述的是所有這些 telemetry 的 producer identity，不是單次 operation 的內容。 所以它屬於 Resource，而不是每個 Span 都手動重複設定。

6. 什麼時候我才應該替 Span 加 Attribute？

先只問一件事：這個值是不是「這一次 operation」的資訊，而且未來真的有查詢或 debug 價值？

資訊現在怎麼判斷理由
cart.item_count=3可以是 Attribute描述這次計算處理多少 item，可能用來比較 latency。
cart.total_cents=3674模型上可以，但不一定值得記要先有明確 troubleshooting/query 用途。
service.name=checkout-demo不是 Span Attribute 的首選它描述所有 telemetry 共用的 producer identity，已放在 Resource。
某個暫時 local variable通常不要記「程式裡存在」不等於「對 observability 有價值」。
 
span.set_attribute("app.cart.item_count", len(prices))
span.set_attribute("app.cart.total_cents", total)

這兩個值都描述這一次 calculate_total，所以資料模型上可以放 Attribute； 但 production 不應為了讓資料看起來完整就把所有變數塞進 Span。 如果沒有明確的查詢／除錯價值，或涉及敏感資料、過高成本，就不要記。

Attribute：附在 Span 上，用來描述「這一次 operation」且值得查詢的 key-value metadata。

7. Span 到底什麼時候算「結束」？

Span 描述一段 operation，而且它需要 start time 與 end time。 當你要描述的 operation 完成時，就應該 End Span。

A. 用 with：離開 block 自動 End

with tracer.start_as_current_span("checkout.calculate_total") as span:
    prices = [1999, 1250, 425]
    total = sum(prices)
    # 這裡 Span 還在進行

# 走到這裡：with block 已離開 → Span 已 End

這也是目前範例使用的方式。即使 block 因 exception 離開，context manager 也會負責結束這個 Span。

B. 手動建立：你自己呼叫 end()

span = tracer.start_span("checkout.calculate_total")
try:
    total = sum(prices)
finally:
    span.end()

如果忘了 span.end()，這個 Span 的 lifecycle 就沒有被正確收尾。

Span End：告訴 SDK「這個 operation 到這裡完成」，固定 end time / duration，並觸發後續 SpanProcessor lifecycle。

來源：OpenTelemetry Trace API — End、 OpenTelemetry Python — Creating spans

8. Debug 時，我怎麼知道 Span 有沒有 End？

不要只看「terminal 有沒有資料」。依證據強度分開判斷：

證據你能得出的結論
控制流程已離開 with這個 context-managed Span 已呼叫 End。
你確認程式走過 span.end()手動 Span 已收到 End。
span.is_recording() 在 End 後為 falseSpan 已不再處於 recording 狀態。
SimpleSpanProcessor + ConsoleSpanExporter 印出 SpanSpan 已 End，而且 Processor/Exporter 路徑至少走到 console。
反過來不成立：terminal 沒看到 Span，不代表它一定沒 End。 也可能是 Processor 沒註冊、Exporter 沒連好、recording/sampling 行為或 stdout 可見性出了問題。

9. 現在才組成完整的 Python 範例

from opentelemetry import trace
from opentelemetry.sdk.resources import Resource
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import (
    SimpleSpanProcessor,
    ConsoleSpanExporter,
)

resource = Resource.create({"service.name": "checkout-demo"})
provider = TracerProvider(resource=resource)
provider.add_span_processor(
    SimpleSpanProcessor(ConsoleSpanExporter())
)
trace.set_tracer_provider(provider)

tracer = trace.get_tracer("training.checkout")

with tracer.start_as_current_span("checkout.calculate_total") as span:
    prices = [1999, 1250, 425]
    span.set_attribute("app.cart.item_count", len(prices))
    total = sum(prices)
    span.set_attribute("app.cart.total_cents", total)
    print(f"Total: {total} cents")

# 到這裡 Span 已 End；SimpleSpanProcessor 已有機會把它交給 ConsoleSpanExporter

11. SRE debug：terminal 沒有 Span，要從哪裡切？

1. 程式有沒有真的進入 start_as_current_span()？
2. operation 有沒有走到 Span End？
3. Provider 有沒有註冊 SpanProcessor？
4. SpanProcessor 有沒有連到正確 Exporter？
5. Exporter 的 stdout / network destination 是否真的可見？

核心習慣：先找 telemetry 最後在哪個已知節點存在，再檢查它到下一個節點的交接。

最後 Recap：每個名詞只留一句話

Span：某一次工作的觀測資料。

Tracer：程式拿來建立 Span 的物件。

TracerProvider：管理 application 共用 tracing 設定，並提供 Tracer。

Resource：描述產生 telemetry 的實體或服務的共用 metadata。

Attribute：描述這一次 operation、且值得查詢的 key-value metadata。

Span End：宣告這次 operation 已完成，固定 end time / duration，並觸發後續 processing。

SpanProcessor：接收 Span lifecycle，並把完成的 Span 交給後續 exporter。

SpanExporter：把可輸出的 Span 資料送往某個目的地。
