PHASE 05 / LESSON 09 · PRACTICE LAB

Filesystem CLI：用受控實驗驗證掃描契約

本堂目標

能從空白需求自行設計 command，並證明漏洞命中、修復、覆蓋不足、篩選及執行錯誤的差異。

01 / 準備三個輸入

在已核准測試環境使用固定版本 Trivy、Bash、jq；不需要 Docker、公司 repo、部署服務或執行漏洞程式。先核對 help。以下為可重現步驟，預期結果未實測。

mkdir -p trivy-lab/{old,fixed,empty,reports}
cd trivy-lab
printf 'requests==2.31.0\n' > old/requirements.txt
printf 'requests==2.32.5\n' > fixed/requirements.txt
trivy --cache-dir "$PWD/cache" fs --download-db-only
trivy --cache-dir "$PWD/cache" --version

Requests CVE-2024-35195 的公告顯示 2.32.0 之前版本受影響。測試只驗證這筆 CVE，非證明新版完全安全。使用乾淨工作目錄、確認沒有非預期 TRIVY_*、trivy.yaml、ignorefile。

02 / 固定 DB，產生三份報告

for target in old fixed empty; do
  trivy --cache-dir "$PWD/cache" fs --scanners vuln \\
    --skip-db-update --list-all-pkgs --format json \\
    --exit-code 0 --output "reports/$target.json" "$target" || exit 1
done

範例假設已成功準備 vulnerability DB，且純 Python 宣告不需 Java DB。比較前核對 DB metadata、CLI 版本及報告路徑，不應重用之前輸出。

for report in reports/{old,fixed,empty}.json; do
  echo "$report"
  jq -r '.Results[]? | .Packages[]? | [.Name,.Version]|@tsv' "$report"
  jq -r '.Results[]? | .Vulnerabilities[]? | select(.VulnerabilityID=="CVE-2024-35195") | [.PkgName,.InstalledVersion,.Severity]|@tsv' "$report"
done
樣本預期（需實驗確認）
oldrequests 2.31.0 已辨識，指定 CVE 命中
fixedrequests 2.32.5 已辨識，指定 CVE 不命中
empty無 requests；不能視為安全修復

03 / 不重新掃描，改變報告條件

trivy convert --format table reports/old.json
trivy convert --format table --severity CRITICAL reports/old.json

比對指定 CVE 是否因 severity 篩選而消失；先查它在原 JSON 的 severity，不要假定必然是 MEDIUM。

04 / 故意造成失敗與 policy hit

if trivy --cache-dir "$PWD/cache" fs --scanners vuln --skip-db-update --exit-code 42 old; then
  echo 'exit=0'
else
  echo "exit=$?"
fi
if trivy --cache-dir "$PWD/cache" fs --scanners vuln --skip-db-update --exit-code 0 ./does-not-exist; then
  echo 'unexpected success'
else
  echo "scan failed, exit=$?"
fi

前者在有未被篩除發現且正常完成時預期為 42；後者若路徑確實不存在應失敗，不假設固定錯誤碼。不要把缺少有效 report 當成無漏洞。

05 / 實驗驗收

提交去識別的版本資訊、metadata、三份 Packages／指定 CVE 摘要、篩選結果與兩種退出碼。若任一不符，依 expected → observed → failure path 找原因，而非直接改門檻。後續才擴展到 .NET、Node.js、Python 的真實 restore 結果及 workflow。

本堂回顧

  • 受控舊版、修補版、空輸入能區別漏洞與覆蓋。
  • 固定 DB 與輸入條件才能歸因。
  • 篩選後未顯示不代表漏洞消失。
  • 保留 report 與 exit code 證據。
