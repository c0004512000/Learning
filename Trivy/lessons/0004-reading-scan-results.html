PHASE 04 / LESSON 07 · TERMINAL OUTPUT

讀懂 Trivy Output：Log、Summary 與漏洞表格

本堂目標

能由終端輸出辨識執行階段、已掃的輸入、漏洞欄位、未命中與覆蓋不足。

01 / 一次執行有三種不同輸出

先分清楚程序正在做什麼、產生了什麼，以及怎麼結束。Log 是執行過程；Table/JSON 是報告；Exit Code 是程序狀態。三者不能相互取代。

trivy fs --scanners vuln .

以下均為縮短的教學示意，非實測 log；版本間文字及欄位會變動。

INFO [vulndb] Vulnerability DB update required
INFO [vulndb] Downloading vulnerability DB
INFO [vuln] Vulnerability scanning is enabled
INFO Number of language-specific files num=1
INFO [pip] Detecting vulnerabilities...
訊息能推論／不能推論
DB update required / Downloading正在準備資料；尚不能推論下載成功或漏洞結果
Vulnerability scanning enabled已選 vuln scanner；不是已找到漏洞
Number of language-specific files辨識到的語言相關檔案數，不是 package 或 CVE 數
Detecting vulnerabilities正在比對；仍要看後續報告及 exit code
WARN / INFO skipped確認是哪一種資料或檢查被跳過，不代表整次掃描一定失敗
ERROR / FATAL核對程序退出碼、報告是否有效；不能當成 0 漏洞

例如 Python site-packages 缺失而跳過授權偵測，說明該授權辨識所需資訊不足；不等於 requirements.txt 的 vulnerability scan 一定沒跑，也不等於全部套件已辨識。

02 / 先讀 Report Summary

TargetTypeVulnerabilities
requirements.txtpip1
package-lock.jsonnpm0

Summary 通常按 target 分組。第一列表示 requirements.txt 這個已分析輸入中，有一筆符合目前報告條件的漏洞發現。第二列 0 是該列沒有可報告命中；不代表全部依賴一定完整。某些版本用「-」表示未執行／不適用的 scanner；要看該版 legend，而不是當作 0。

03 / 逐欄解讀漏洞表

教學列：以 requests CVE-2024-35195 為例，severity、status 與欄位顯示以實際 DB 為準。

欄位示意值及意義
Libraryrequests：命中的套件
VulnerabilityCVE-2024-35195：公告識別碼，也可能是 GHSA 等其他 ID
SeverityMEDIUM（示意）：嚴重程度，不等於企業風險優先級
Statusfixed（示意）：該漏洞已有修復，不表示目前安裝版本已修好
Installed Version2.31.0：Trivy 讀到的受檢版本；fs 可能來自清單而非已安裝套件
Fixed Version2.32.0：公告所列修復版本；可能多個、空白或依平台不同
Title / URL問題摘要及詳細公告，核對受影響條件與修復資訊

若 installed version 是 2.31.0，fixed version 是 2.32.0，status 顯示 fixed，意思仍可能是目前套件有漏洞、上游已發布修復。實際升級後需要重新 restore 和掃描，不能只改一份報告。

04 / Severity 與 Status 不同

Severity判讀
CRITICAL / HIGH高優先評估；仍應看曝險、可利用性、修復版本及公司政策
MEDIUM / LOW不表示無需修復；可按 SLA、影響及成本分批處理
UNKNOWN已有漏洞發現但缺少可用嚴重程度評級；不是未知有無漏洞，也不是 LOW

Trivy 可依生態系或 vendor advisory 選擇 severity；不同來源可能不一致，可在 JSON 讀 SeveritySource、VendorSeverity、CVSS（若有）。CVSS 主要描述技術嚴重性；是否真的影響你的系統，還要結合使用情況。

Status 描述修補或調查狀態，例如 affected（無修補）、fixed（有修補）、will_not_fix、fix_deferred。支援因資料來源而異；unknown status 與 UNKNOWN severity 是不同欄位，某些狀態不會被報告。

05 / 四種結果不能混為一談

觀察結論
exit 0、套件存在、漏洞命中正常掃描且有發現
exit 0、應有套件皆辨識、漏洞 0目前資料與篩選範圍未命中
exit 0、應有套件未辨識、漏洞 0覆蓋不足；先查輸入
非零、執行失敗、報告不存在／無效不能進行安全判定

如果有自訂非零 findings exit code，非零也可能代表正常完成且政策命中。先看有效設定和報告，不要只看數字。

先確認未出現的輸入是否存在、被排除、受支援或正確生成；0 不是覆蓋完整的證據。

本堂回顧

  • Log 是過程，Summary 是分組，漏洞列是發現，exit code 是狀態。
  • Severity、Status、Installed Version、Fixed Version 的意義各自不同。
  • UNKNOWN severity 仍是漏洞發現。
  • 掃描成功不等於覆蓋完整或沒有漏洞。

主要來源：Reporting · Vulnerability Scanner · Filtering · Requests advisory。範例依官方文件設計，未在公司 Runner 實測。以固定 CLI 版本的 --help 為準。
