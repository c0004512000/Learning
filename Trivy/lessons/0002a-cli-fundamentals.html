PHASE 02 / LESSON 03 · CLI

Trivy CLI：如何自己組合掃描指令

本堂目標

能由需求選擇 Target、Scanner、輸入範圍、輸出和執行控制，不依賴現成指令。

01 / 一次掃描的五個問題

當 CI checkout 完成，磁碟上已有專案。Trivy 是一個讀取輸入並產生報告的程式，不是套件安裝器，也不需要先執行應用程式。先決定要讀哪裡，再決定檢查什麼。

Target：本機專案目錄
↓ 讀取指定輸入
Analyzer：辨識支援格式中的套件名稱、版本、類型
↓ 提供已辨識套件
Vulnerability Scanner：對照漏洞 DB
↓ 篩選發現並輸出
Report（Table／JSON）＋ process exit code

Analyzer 是 Trivy 內部辨識輸入的機制，通常不是你直接呼叫的 subcommand。--scanners vuln 選擇漏洞檢查，而非指定讀取哪種 lockfile。

02 / Command、Flag、Argument

trivy fs --scanners vuln --format json -o report.json ./project
部分作用
trivy執行檔
fsfilesystem 的別名，決定輸入是本機路徑
--scanners vuln選擇漏洞 Scanner；不是 package 類型
--format json指定報告格式
-o report.json--output 的簡寫，指定報告目的地
./project位置參數，實際掃描的路徑

Flag 可以是布林開關（如 --debug），也可以接值（如 --timeout 10m）；多值旗標可依 help 使用逗號。. 代表目前工作目錄，不必然等於 repository root。

trivy --version
trivy --help
trivy fs --help
trivy convert --help
trivy clean --help

Global flags 可在 root help 查到；某些 flags 只在特定 subcommand 有效。以安裝版本的 help 確認可用參數、預設值及別名，而非直接照抄其他版本的文件。

03 / 常用入口：先分清楚掃誰

Command輸入與用途
trivy fs PATH本機路徑，CI checkout 後的主線
trivy repo REPOGit repository，可依支援參數指定 branch/tag/commit
trivy image IMAGE已建置 image；本課僅理解入口，不列入導入實作
trivy sbom FILE已存在的 SBOM，依其可提供的元件資訊比對
trivy convert FILE轉換既有 JSON，不重新掃描
trivy clean清除指定快取資料；不是掃描
trivy config PATH設定檔 misconfiguration 掃描，不是載入 trivy.yaml 的指令

04 / 從一條命令逐步增加需求

只掃套件漏洞

trivy fs --scanners vuln .

Filesystem 的預設 Scanner 在官方版本常包含 vuln、secret；顯式指定 vuln 可以避免把已獨立管理的 Secret Scanning 混進來。

限定語言套件、控制讀取範圍

trivy fs --scanners vuln --pkg-types library \\
  --skip-dirs '**/test-fixtures' --skip-files '**/sample.lock' .

library 與 os 是套件類別，與 vuln/secret 不同維度。排除路徑會減少掃描輸入，不能當成漏洞例外；pattern 應加引號避免 shell 展開，實際用 Debug 與套件清單確認匹配。不要為了加速而一概排除 lockfiles、obj 或所有測試目錄。

保留完整結果

trivy fs --scanners vuln --list-all-pkgs \\
  --format json --output ../report.json --exit-code 0 .

在乾淨設定下，保留可辨識套件和各嚴重度命中；報告放掃描目錄外。exit 0 不因發現漏洞失敗，但不掩蓋真正的執行錯誤。預設 ignorefile、設定檔仍可能影響結果。

排查慢或漏掃

trivy fs --debug --timeout 10m --no-progress \\
  --scanners vuln --format json --output ../debug.json .

debug 增加可見資訊，timeout 改變執行上限，no-progress 只去除進度列。三者不是漏洞過濾條件。

本堂回顧

  • Target 決定讀取來源；Scanner 決定檢查類型。
  • Flag 的預設值及可用範圍取決於 CLI 版本。
  • 讀取範圍、套件種類、報告及退出碼是不同層級。
  • 所有排除設定都需要證明不破壞應有覆蓋率。

主要來源：Filesystem CLI · Vulnerability Scanner · Reporting。範例依官方文件設計，未在公司 Runner 實測。以固定 CLI 版本的 --help 為準。
