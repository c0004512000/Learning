PHASE 05 / LESSON 11

Node.js 與 Python：間接依賴如何完整地被掃描？

本堂目標

能選擇 npm/pnpm lockfile 或 Python 的 resolved snapshot，判斷 dev dependency、環境與 dependency graph 的限制。

01 / npm：為什麼 package.json 不夠？

"example": "^1.2.0" 是可接受版本範圍，而 lockfile 記錄 resolver 所選的版本與間接依賴。Trivy filesystem 主要從受支援 lockfile 取得資訊。無需為 vuln-only 一律安裝 node_modules；但若目標是驗證實際 build，仍須核對 install 的結果與 lockfile 一致。

npm --version
npm ci
trivy fs --scanners vuln --list-all-pkgs --format json -o ../npm.json .

npm ci 要求既有 lockfile，且與 package.json 不一致時失敗；應使用與實際 build 相同的 npm 版本、workspace、registry 和 install flags。若原流程是 npm install，不能無條件改成 ci；先驗證相容性並確認最後使用的 lockfile。安裝可能執行 package scripts，應用核准隔離環境。

02 / pnpm 與 workspace

pnpm --version
pnpm install --frozen-lockfile
trivy fs --scanners vuln --list-all-pkgs --format json -o ../pnpm.json .

pnpm-lock.yaml 可能涵蓋多個 workspace importer。要掃實際 project 而非任意把共享 lockfile 的全部依賴歸給一個服務；檢查 workspace root、lockfile version、peer／optional dependency 與實際 build target。對 v9 或更新 lockfile，官方說明支援 dev 標記及相應 flag；其他版本須實測。

比較意義
預設npm 的開發依賴通常不列入；pnpm 行為依 lockfile／版本
--include-dev-deps支援的生態系可擴大檢查範圍；build tool 也可能構成供應鏈風險
--dependency-tree支援的格式可呈現有漏洞套件的依賴路徑；不是所有套件／格式皆能重建完整圖
trivy fs --scanners vuln --include-dev-deps --dependency-tree .

用已知有 dev-only dependency 的 fixture 比較前後結果，不能因沒有新增漏洞就推斷 flag 無效；先看 Packages。對正式 runtime 與 build-time 風險可用不同 scope，但保留 scope 標記。

03 / Python：requirements.txt 的限制

宣告Trivy 預設／可能的解讀
requests==2.31.0明確版本，可直接辨識該套件
requests>=2.28範圍並非已安裝版本；預設可能無法辨識
requests==2.31.*不是精確版本；comprehensive 可採最低版本作較廣泛檢查，但不是實際版本證據

--detection-priority comprehensive 不是 dependency resolver，不能替代 install、lockfile 或 freeze。

04 / 從實際 venv 取得 resolved snapshot

使用與正式 build 相同的 Python、OS、architecture、extras、index 與安裝條件。下列示範獨立 venv，只適用已核准的隔離測試環境；正式流程應使用實際 build 的環境。

python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
mkdir -p ../python-scan-input
.venv/bin/python -m pip freeze > ../python-scan-input/requirements.txt
trivy fs --scanners vuln --list-all-pkgs --format json -o ../python.json ../python-scan-input

Windows 使用 .\.venv\Scripts\python.exe。PowerShell 若需要寫 UTF-8，可用 Set-Content -Encoding utf8；依實際版本核對 BOM 與工具解析。不要把原本 requirements.txt 覆蓋成 freeze，以免改變 build 合約；scan input 放在獨立目錄，確定檔名受支援。

pip freeze 是當下環境清單，不是跨平台 lockfile；可能混入 build tools、editable/VCS dependencies 或環境污染，且預設省略部分 bootstrap 工具。需要時以 pip freeze --all 和 pip list --format=json 核對，仍需定義要掃的 scope。Poetry/uv 則優先使用其已同步 lockfile，依官方支援的 dependency groups 及平台條件確認。

注意 pip freeze 可能包含私有 URL，輸出前應檢查並保護；不要把敏感連線資訊寫入公開 log 或報告。

05 / 如何追蹤間接依賴

應用程式 → A（直接依賴）
↓ A 宣告 B
B（間接依賴）
↓ Trivy 比對 B 的版本
B 有漏洞
↓ 回到 lockfile / graph 找引入者
升級直接依賴或採用受控 override → 重新解析與測試

freeze 只有平坦名稱與版本，不一定能重建 graph。需要父子關係時應使用受支援 lockfile、原 package manager 的 graph 或其他可信證據。不要看到 B 有漏洞就直接把 B 強制升級而不測相容性。

06 / 比較先前樣本

樣本辨識結果（歷史）
npm lockfile50/50
pnpm lockfile52/52
Python direct-only1/5
Python freeze5/5
Poetry / uv lockfile各 5/5（先前 PoC 紀錄，需以原報告核對）

數字僅表示特定樣本套件辨識，不保證其他 lockfile 或部署條件有相同比例。對每種 repo 保留 expected inventory、Trivy inventory、差異及原因。

理解驗收

同一個 npm lockfile 中有 dev-only 工具 C，預設報告未列出。能直接說 Trivy 不支援 C 嗎？

先自行回答，再查看解析

不能。先查 dev dependency filter，使用受支援的 include-dev-deps 對照 Packages。

Python freeze 在系統 Python 執行，正式 build 用 venv；報告多出 20 個套件。應怎麼做？

先自行回答，再查看解析

重新在實際 venv 產生 snapshot，對照 pip list 與正式安裝條件。不要以較多套件數當完整證據。

本堂回顧

  • lockfile 是解析結果，不是宣告範圍。
  • dev dependency scope 與 runtime scope 要分清。
  • Python freeze 必須來自正確環境，且不是 graph 或跨平台 lockfile。
  • 間接依賴修補需追蹤引入路徑並重新解析。
