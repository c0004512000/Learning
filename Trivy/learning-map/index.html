    對應來源：原始材料／官方文件

最小 CLI PoC 與結果解讀

    對應來源：原始材料／官方文件

PHASE 03 規劃中

讓掃描資料與實際部署一致

檢查套件和建置格式：.NET、Node.js、Python，以及 Docker / IIS publish 的產物差別。

  1. L05 · .NET 與 Node 的套件怎樣才算被看見？ 待撰寫

    學習目標：解釋 packages.config、packages.lock.json、npm/pnpm lockfile 的資訊差異
    驗收方式：對照直接、間接依賴與已解析版本清單
    對應來源：原始材料／官方文件

  2. L06 · Python freeze 和最終部署產物能對上嗎？ 待撰寫

    學習目標：知道 requirements、pip freeze、venv 及 Image 的可觀察範圍
    驗收方式：證明 freeze 來自正確環境且掃描資料符合部署內容
    對應來源：原始材料／官方文件

PHASE 04 規劃中

接到現有 GitHub Actions

以 Linux ARC 與 Windows IIS 的實際 workflow 決定掃描時機；先產報告，不阻擋。

  1. L07 · Runner 能穩定執行掃描嗎？ 待撰寫

    學習目標：確認 CLI 版本固定、DB、CA、Proxy、Docker Socket、Windows 差異
    驗收方式：有成功和失敗情境的可重測證據
    對應來源：原始材料／官方文件

  2. L08 · 掃描應該插在 build、push、deploy 的哪裡？ 待撰寫

    學習目標：能找出 GitOps 更新前與 IIS 真正部署前的 gate 位置
    驗收方式：不會掃完才發現 MSBuild / msdeploy 已部署
    對應來源：原始材料／官方文件

PHASE 05 規劃中

抽成可以維護的共用 Workflow

統一命令、輸入、輸出與故障策略，避免每個服務使用不同的掃描邏輯。

  1. L09 · CommonActionDeployment 應暴露哪些介面？ 待撰寫

    學習目標：設計輸入、報告 Artifact、輸出與 gate 的責任分離
    驗收方式：Linux／Windows 範例可用相同接口呼叫
    對應來源：原始材料／官方文件

  2. L10 · 資料庫下載失敗、快取與升級怎麼辦？ 待撰寫

    學習目標：理解 Scanner 本身可靠性和漏洞 DB 維護責任
    驗收方式：能從 CI 結果區分基礎設施故障與真實漏洞發現
    對應來源：原始材料／官方文件

PHASE 06 規劃中

企業治理與部署前阻擋

從報告到政策，界定新舊漏洞、修復、例外、到期與 CI 阻擋。

  1. L11 · 什麼漏洞應該阻擋部署？ 待撰寫

    學習目標：理解 severity、fixability、baseline、例外治理與 owner
    驗收方式：能用樣本評估 policy，而不把所有結果一律 fail
    對應來源：原始材料／官方文件

  2. L12 · 真的能在部署前擋住嗎？ 待撰寫

    學習目標：驗證 GitOps 更新、IIS publish、msdeploy 各路徑的安全停止點
    驗收方式：實測失敗時沒有更改目標環境
    對應來源：原始材料／官方文件

PHASE 07 規劃中

漸進導入與長期維運

掌握掃描覆蓋率、誤報、例外到期、更新及新 CVE 出現時的重新掃描。

    驗收方式：看得出哪些服務有掃、哪些缺資料
    對應來源：原始材料／官方文件

  2. L14 · 上線後資料庫、工具與重新掃描怎麼維護？ 待撰寫

    學習目標：理解版本固定、維護、掃描結果保存、新漏洞再發現
    驗收方式：提出升級／回復／定期再掃描的操作方案
