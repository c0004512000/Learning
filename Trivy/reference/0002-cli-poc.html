REFERENCE 02 / CLI / RESULT INTERPRETATION

Trivy CLI 與結果判讀速查

這份 Reference 供 Phase 02 的兩堂課往返使用。

最小命令

trivy --version
trivy fs --scanners vuln --list-all-pkgs \
  --format json -o report.json .
trivy image --image-src docker --scanners vuln \
  --list-all-pkgs --format json -o image.json app:tag
trivy convert --format sarif -o report.sarif report.json

切記輸出放在受掃目錄外（上方 fs 示例以 report.json 表示輸出位置，實作時使用外部路徑）。若需要依特定發現回傳非零，用 --exit-code 42 做獨立測試；值可自訂。--severity HIGH,CRITICAL 是漏洞嚴重度篩選，不是套件清單的完整性證明。

讀取報告

jq -r '.Results[]? | .Packages[]? |
  [.Name, .Version] | @tsv' report.json

jq -r '.Results[]? | .Vulnerabilities[]? |
  [.VulnerabilityID,.PkgName,.InstalledVersion,
   .FixedVersion,.Severity] | @tsv' report.json

驗收順序

  1. 執行正常？先核對 exit code、log、報告是否有效。
  2. 應有套件真的存在？核對名稱與版本。
  3. 指定漏洞命中？核對 CVE，不只看總數。
  4. 對照實驗的輸入是否唯一改變？記錄 Scanner/DB、目標內容、參數及修補版本。
四種結論

有漏洞／未命中／覆蓋不足／執行失敗。只有前兩種在掃描正常且需要的套件清單已核對後，才能做該範圍的漏洞判定。

實驗紀錄模板

項目填寫實測證據
工具與 DB版本、更新時間、核准來源
掃描目標檔案內容或 Image ID/digest
指令與結果完整參數、exit code、log、JSON
預期 vs. 觀察套件版本、指定 CVE、差異原因
