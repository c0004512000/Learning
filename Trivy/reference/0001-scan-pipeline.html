Trivy 掃描流程速查

這份 Reference 供第一章與後續 PoC 回頭查詢。不是新的必修課。

一條完整的資料路徑

INPUT → DISCOVERY → MATCH → REPORT → POLICY

  1. 掃描目標：Repo / Folder / Lockfile，或 Container Image。
  2. 辨識套件：從可支援的格式取得名稱、版本、平台與相依關係。
  3. 漏洞比對：用偵測到的軟體版本比對已有的漏洞資料。
  4. 輸出報告：呈現命中的漏洞、嚴重程度與可修補資訊等。
  5. CI Policy：由你們決定 report-only、何種條件 fail、是否阻擋部署。

流程中每個箭頭是「將結果提供下一階段」；Scanner 並非執行應用程式找出所有可能漏洞。

最小掃描目標表

輸入適合回答需要先確認
trivy fs --scanners vuln .這個資料夾內可辨識的依賴資訊有何已知漏洞？Lockfile 是否存在、精確版本及間接依賴是否完整
trivy image --scanners vuln image:tag這個封裝 Image 中可辨識的 OS/Application 套件有何已知漏洞？確實掃到部署的 Image，tag 是否指向預期 digest
python -m pip freeze這個 Python 環境目前裝了哪些套件版本？是否正在正確 venv；它本身不是掃描指令／lockfile

三個容易混淆的「零」

  • 套件 0 個：先調查目標檔案、套件格式、套件辨識狀態。
  • 已辨識 N 個套件、漏洞 0 個：只是現有資料未命中；仍須確認 DB、平台、版本與掃描範圍。
  • CLI exit code 0：要看 CLI 設定與執行是否成功，不能單靠此數字判斷安全政策達成。

你之後在 CI 一定要證明的事

  1. Runner 能使用指定且可維護的 Trivy 版本。
  2. 掃描輸入和真實部署產物對得起來。
  3. 結果被保存並且可供查核。
  4. 掃描失敗、資料不足、無漏洞不能混成同一種 PASS。
  5. 想阻擋時，失敗發生在真正的部署操作之前。
