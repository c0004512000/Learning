CLI、DB 與 Output 速查

組合指令

trivy fs --scanners vuln --list-all-pkgs \
  --format json -o ../report.json --exit-code 0 .
trivy --cache-dir ./cache fs --download-db-only
trivy --cache-dir ./cache fs --skip-db-update --scanners vuln .
trivy convert --format table --severity HIGH,CRITICAL ../report.json

CLI 詳解 · 設定優先順序

DB 與更新

漏洞公告 → 官方 DB build → trivy.db + metadata.json → OCI Registry → Runner cache-dir/db/ → scanner 比對本機套件。:2 是 schema tag；不是固定快照。

行為判斷
6 小時官方建置排程
24 小時metadata 的預設 NextUpdate 間隔，依實際欄位
1 小時CLI 近期下載保護（所查原始碼）
--download-db-only只準備 DB；可能重用，不保證重新下載
--skip-db-update使用既有相容 DB；不保證資料新鮮
--offline-scan停用辨識依賴時的額外查詢，不停止 DB 更新
--db-repository遠端來源；覆蓋預設清單，僅在需要下載時使用
FRESH_CACHE=$(mktemp -d)
trivy --cache-dir "$FRESH_CACHE" fs --scanners vuln --download-db-only
cat "$FRESH_CACHE/db/metadata.json"

用空 cache 嘗試取得當下遠端 DB，核對 UpdatedAt、Version、NextUpdate、DownloadedAt；遠端可能仍舊。詳見 DB 原理與下載 · 更新判斷、cache 與維運。

Output 判讀順序

訊號判讀
Exit / Log有無執行失敗、DB 問題
Target / Packages有無辨識預期輸入及版本
Vulnerabilities目前資料與篩選下的命中
Severity / Status嚴重度與修補狀態分離
Installed / Fixed受檢版本與修補版本分離

UNKNOWN severity 仍屬漏洞發現；fixed status 不代表目前套件已升級。0 漏洞不是覆蓋完整證據。
