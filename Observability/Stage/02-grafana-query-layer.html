02. Grafana：Datasource → Variable → Query → Panel

拆開 Grafana 的 connection、query 與 presentation 責任

這一章只談 Grafana 自己的責任邊界。資料已經存在 backend 後，Grafana 要做五件事：建立 datasource connection、取得 variable 值、執行 panel query、把結果做 field/transform 設定、最後用 panel/layout 呈現。

1. Datasource：Grafana 要去哪裡問

以 Stage Prometheus 為例：

name   = Prometheus
type   = prometheus
uid    = prometheus
url    = http://prometheus-server.prometheus.svc.cluster.local
access = proxy
method = GET

Stage 已證實 這表示 browser 不需要直接連 cluster-internal Prometheus URL；Grafana server 依 datasource 設定代為 query。Datasource 本身不保存 metrics。

2. Variable：先產生「可選條件」

例如 MicroService Dashboard 的：

Namespace = label_values(namespace)
node      = label_values(node)

Variable query 先取得可選值。使用者選了某個 namespace 後，Grafana 把它保存成 $Namespace，再在 panel query 執行前做 interpolation。

3. Panel target：真正決定查哪個 backend

panel
└─ targets[]
   ├─ datasource.uid = "prometheus"
   ├─ refId = "A"
   └─ expr = rate(container_cpu_usage_seconds_total{...}[3m])

所以一個 Dashboard 可以混合多個 backend：每個 target 都能指到不同 datasource UID。MicroService Dashboard 正是這樣同時使用 Prometheus、Loki、Tempo。

4. Query language：Backend 的資料模型決定你能問什麼

BackendQuery language主要操作對象這個 Dashboard 的例子
PrometheusPromQLTime series + labelsrate()、sum by()、container/node metrics
LokiLogQLLog streams + labels + log linescount_over_time()、severity filter
TempoTraceQLTraces / spans / resource & span attributesduration、status、HTTP/DB attributes

5. Panel presentation：Query result 怎麼變成畫面

Panel 再決定 visualization type、unit、legend、threshold、field overrides、transformations、options。這一層可以改「怎麼看」，但不會回頭修改 backend 裡的 telemetry。

例子：把 memory panel 的 unit 從 bytes 改成 GiB，只是 Grafana presentation；Prometheus 裡原本的 node_memory_MemAvailable_bytes samples 不會被改寫。

6. Layout：Panel 順序本身也是設計

MicroService Dashboard 先放 Logs / DB / API，再放 Pod / Cluster resources，代表作者把它設計成一個 troubleshooting surface。Layout 不產生資料，但會影響人怎麼從 symptom 走到 evidence。

UI 上實際怎麼建立

  1. Connections / Data sources：新增 Prometheus、Loki、Tempo，設定 URL 與必要 auth/options。
  2. Dashboard settings → Variables：建立 Namespace、Job 等 variables。
  3. Add visualization：選 datasource，寫 PromQL / LogQL / TraceQL target。
  4. Panel options：設定 title、legend、unit、threshold、field overrides、transformations。
  5. Rows / layout：依 operational question 分組並安排閱讀順序。
UI 是 editor，不是魔法。你在 UI 做的這些操作最後都會落到 Dashboard JSON：datasource UID、variables、targets、fieldConfig、options、grid position。也因此我們可以 reverse engineer 現有 Dashboard。
