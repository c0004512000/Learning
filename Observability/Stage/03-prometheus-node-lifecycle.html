03. Reference：Node Exporter → Prometheus 的資料生命週期

從 Linux host state 到可被 PromQL 查詢的 time series。

誰最先擁有 CPU / Memory 狀態？

Linux kernel。Node Exporter 讀取 host state，再用 Prometheus exposition format 暴露 metrics。

Linux host state
  ↓ collectors
node-exporter
  ↓ /metrics
Prometheus scrape
  ↓ TSDB
node_cpu_seconds_total{cpu="0",mode="idle",instance="...",job="..."}

Scrape 必須解決三件事

  • 去哪裡：target address + port
  • 抓什麼：metrics path
  • 這是誰：job / instance / discovery labels / relabeling

為什麼 labels 很重要？

node_cpu_seconds_total 是 metric family，不是一條單獨曲線。不同 instance、cpu、mode、job 形成不同 time series。

Stage 待 source-of-truth：
  • 實際 node-exporter workload / image / args / mounts
  • Service / ServiceMonitor / annotations
  • Prometheus scrape config / relabel rules
  • runtime target 是否 UP
  • 實際 node_* series 是否存在
Prometheus discovery 找到 target，就能證明 Dashboard 一定正常嗎？

查看答案

不行。Discovery 只是其中一站。
