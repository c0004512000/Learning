00. Taiwan Stage Grafana：從資料誕生到 Dashboard

先建立完整 observability lifecycle，再進入兩個 Tier 1 scope Dashboard

先建立因果鏈：Grafana Dashboard 是最後一站，不是資料來源。要真正知道一個 Dashboard 為什麼有資料，必須一路追到「誰產生 telemetry、誰收集、誰保存、Grafana 如何查、最後怎麼畫」。

這一題的 scope

目前只聚焦兩個 Dashboard：MicroService Dashboard 與 Node Exporter Full。這只是本次學習範圍，不代表 Taiwan Stage Kubernetes Dashboard 的正式分類。

ingest / remote write / push / scrape result

先理解「有資料」到底需要什麼

以 Node CPU 為例，Grafana 上的 CPU Busy 不是一個神奇的 Dashboard 欄位。要出現那條線，至少要同時成立：

  1. Node 的 CPU 狀態可被讀取。
  2. Node Exporter 類元件把它暴露成 node_cpu_seconds_total。
  3. Prometheus 成功 scrape，series 被寫入 TSDB。
  4. Grafana datasource 指向正確的 Prometheus。
  5. PromQL 使用正確的 job/instance labels。
  6. Panel 把 query result 轉成你看到的視圖。

任何一層斷掉，都可能表現成「Dashboard 沒資料」。因此 debugging 也應沿著同一條鏈逐站證明，而不是從 Grafana 猜。
