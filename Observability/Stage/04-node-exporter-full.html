04. Node Exporter Full：從 node_* metrics 到 128 個 Panels

把 Node metrics lifecycle 套回 Taiwan Stage 的實際 Dashboard JSON

現在把上一章套回真實 Dashboard。Stage inventory 顯示 Node Exporter Full UID 是 rYdddlPWk，共有 128 個 panels、16 個 row sections、4 個 variables。Panel 類型以 graph 為主，另外有 gauge 與 stat。

Dashboard 的四個 variables

VariableQuery / 值作用
DS_PROMETHEUSdatasource type = Prometheus選 datasource
joblabel_values(node_uname_info, job)先選 Node Exporter scrape job
nodelabel_values(node_uname_info{job="$job"}, instance)再從該 job 選 instance
diskdevices[a-z]+|nvme[0-9]+n[0-9]+Hidden regex，用於 disk device filter

node 依賴 $job，所以這是 chained variable：先縮小 job，再產生 instance 選項。

CPU Busy 並不是 Node Exporter 直接給的欄位

(((count(count(node_cpu_seconds_total{instance="$node",job="$job"}) by (cpu)))
 - avg(sum by (mode)(
     rate(node_cpu_seconds_total{
       mode="idle",
       instance="$node",
       job="$job"
     }[$__rate_interval])
   ))) * 100)
 / count(count(node_cpu_seconds_total{instance="$node",job="$job"}) by (cpu))

這段先用 rate() 算 idle CPU time 的變化，再從 total CPU capacity 推成 Busy percentage。也就是：

Node Exporter 原始 counter
        ↓
Prometheus time series
        ↓
PromQL rate + aggregation + arithmetic
        ↓
Grafana 的 CPU Busy 視圖

Memory、Filesystem 也是同樣模式

# RAM Used
100 - (
  node_memory_MemAvailable_bytes{instance="$node",job="$job"} * 100
  / node_memory_MemTotal_bytes{instance="$node",job="$job"}
)

# Root FS Used
100 - (
  node_filesystem_avail_bytes{
    instance="$node",job="$job",mountpoint="/",fstype!="rootfs"
  } * 100
  / node_filesystem_size_bytes{
    instance="$node",job="$job",mountpoint="/",fstype!="rootfs"
  }
)

Stage 現在真正的 Grafana 問題：stale datasource UID

Dashboard JSON 已證實 Node Exporter Full 的大量 targets 與 job/node variables 都綁定 Prometheus datasource UID becxci96j0tfkc。最新 Stage datasource inventory 中找不到這個 UID。

這個現象的邊界要講清楚：

  • 它能證明：這份 Dashboard definition 的 datasource binding 已經 stale / dangling。
  • 它不能證明：Prometheus backend 沒有 Node metrics。
  • 它也不能證明：Node Exporter ingestion 本身壞掉。

修復方向是在 Grafana 端把 variables / panel targets 改綁到實際有效的 Prometheus datasource，然後再用 node_uname_info、node_cpu_seconds_total 等 query 驗證資料與 labels。

如果要從零重建這個 Dashboard，真正順序是

  1. 先證明 Node Exporter 在每個目標 Node 上產生 node_* metrics。
  2. 讓 Prometheus discovery + scrape 建立正確的 job/instance series。
  3. 在 Grafana 建立有效 Prometheus datasource。
  4. 建立 job → node chained variables。
  5. 逐類建立 CPU、Memory、Filesystem、Network、Disk PromQL。
  6. 最後才是 panel type、unit、legend、threshold 與 row layout。
