04. Node Exporter Full：一台 Node 如何變成 128 個 Panels

心智模型： Node Exporter 產生 node_* metrics → Prometheus 保存 time series → Grafana 用 PromQL 組合出 CPU、Memory、Disk、Network 等視圖。

Dashboard 依賴的資料

# CPU busy
rate(node_cpu_seconds_total{mode="idle",instance="$node",job="$job"}[$__rate_interval])

# RAM
node_memory_MemAvailable_bytes{instance="$node",job="$job"}
node_memory_MemTotal_bytes{instance="$node",job="$job"}

# Filesystem
node_filesystem_avail_bytes{instance="$node",job="$job",mountpoint="/"}

Dashboard 沒有直接取得一個叫「CPU Busy」的 metric；它用 PromQL 從較原始的 counters / gauges 計算視圖。

Variables

job  = label_values(node_uname_info, job)
node = label_values(node_uname_info{job="$job"}, instance)

第二個 variable 依賴第一個，因此是 chained variable。

Stage 目前的重要異常： Dashboard JSON 大量引用 Prometheus datasource UID becxci96j0tfkc，但最新 datasource inventory 找不到這個 UID，因此這一層存在 stale datasource reference。

128 個 Panels 為什麼合理？

Node health 不是一個指標：CPU、memory、filesystem、network、disk I/O、load、uptime 都是不同 operational questions。Dashboard layout 的工作就是把這些問題組成 troubleshooting surface。

CPU Busy 是 node-exporter 直接輸出的 metric 嗎？

查看答案

不是。Node Exporter 暴露較原始的 node metrics；PromQL 再計算 Dashboard 要呈現的數值。
