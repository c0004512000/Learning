Frontend OTel / Faro Learning Map

動態學習地圖：只展開實際走過與目前需要的路徑

Ultimate Goal
接手並維運既有 Faro 前端可觀測性方案：能從瀏覽器事件一路追到 Faro telemetry、Alloy／OTel Collector 與 backend，並能用程式碼、DevTools 與觀測平台證據定位問題、協助導入、修改與優化。

Capability Milestones

  1. 看懂 browser 原生事件與 Faro instrumentation 的責任邊界。
  2. 讀懂並安全修改 @sre2/faro-click-tracking。
  3. 能在宿主前端專案導入並用 DevTools 驗證資料。
  4. 能把 frontend span 與 backend span 串成同一條 trace。
  5. 能沿 Alloy／OTel Collector／backend pipeline 做 production troubleshooting。

這裡刻意不預先展開固定 12 課；後續 lesson / reference 會依實際文件內容與學習卡點逐步長出來。

已走過的 prerequisite branch

A. DOM / document / Event dispatch

為什麼出現：只說「DOM 是可操作的頁面結構」仍太抽象；需要知道瀏覽器記憶體裡有什麼物件、document 指向誰、event 是誰建立、又是如何被分派。

Reference｜DOM、document 與事件分派 →

狀態：具體模型已建立；尚未用 retrieval 證明完全 mastered。

B. Callback

為什麼出現：理解 addEventListener() 需要先分清楚 handleClick 與 handleClick()，以及「函式先交出去、之後由另一方呼叫」的控制方向。

Reference｜Callback 到底是什麼 →

狀態：call-back 控制模型已建立；尚未用 retrieval 證明完全 mastered。

Now

回到 Faro 前，只需要能自己重建：

使用者 click
  → browser 建立 Event
  → browser 分派 event
  → listener registration 命中
  → browser 呼叫 callback(event)
  → JavaScript 讀取 event.target
