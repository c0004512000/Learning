How the Browser Knows What You Clicked

Milestone 1 · Browser native click → JavaScript callback

這堂課的目標
學完後，你應該能從一段 HTML 開始，完整解釋：使用者點下畫面後，Browser 如何決定 target、建立 Event、dispatch Event，最後讓 JavaScript callback 開始執行。

這堂課先完全不談 Faro。因為 Faro 能接到 click 的前提，是 Browser 原本就已經有一套 DOM 與 Event 機制。

1. HTML 先只是一份文件描述

假設頁面原始 HTML 有一顆按鈕：

<main>
  <button id="daily-schedule-button">
    每日生產排程
  </button>
</main>

這段 HTML 首先只是文字。它描述有哪些 element、彼此怎麼巢狀、有哪些 attributes。

但 Browser 後面還需要做更多事，例如：

找到某個 element
讀取或修改它的 attribute
知道它的 parent / child
把使用者輸入對應到某個 element
在 element 上處理事件

因此 Browser 不能只保留原始文字；它需要一份在程式執行期間可以操作的文件模型。

2. Browser 解析 HTML，建立 DOM

HTML source
    │
    │ Browser parses
    ▼
DOM runtime model

DOM（Document Object Model）可以先理解成：

Browser 在記憶體中建立並維護的文件物件，以及這些物件之間的關係。

上面的 HTML 會形成類似下面的階層：

Document
└── html
    └── body
        └── main
            └── button
                id="daily-schedule-button"
這張圖的縮排只表示 parent / child hierarchy。它不是事件流程，也不是執行順序。

3. DOM element 為什麼需要是 object？

因為 Browser 不只要記住「這裡有一顆 button」，還要讓程式能對它做操作。

例如對這顆 button，程式可能需要知道：

它的 id 是什麼？
它的 parent 是誰？
它裡面的文字是什麼？
它有哪些 attributes？
它有沒有註冊 event listener？

所以 Browser 在 runtime 中用一個可操作的物件來代表這顆 element。對 HTML <button> 而言，常見的 DOM 介面名稱是 HTMLButtonElement。

HTML source
<button id="daily-schedule-button">...</button>
        │
        │ Browser parses / creates
        ▼
DOM runtime object
HTMLButtonElement

DOM object 是 Browser 建立與管理的；JavaScript 可以透過 Browser 提供的 DOM API 取得它的 reference。

4. JavaScript 如何取得某顆 DOM object？

HTML 可以替 element 設定一個作者自行命名的 id：

<button id="daily-schedule-button">...</button>

JavaScript 可以透過 DOM API 查詢：

const button = document.querySelector('#daily-schedule-button')

這裡有兩個角色：

名稱意思
document目前文件的 Document DOM object。
#daily-schedule-buttonCSS selector，表示找 id="daily-schedule-button" 的 element。

查詢成功後，button 變數裡不是 HTML 原始文字，而是那顆 DOM object 的 reference。

5. 使用者點下去時，先收到輸入的是 Browser

現在畫面已經 render 出來。使用者用滑鼠、觸控板或手指點下某個位置。

User input
    │ received by
    ▼
Browser

Browser 必須把這次輸入和目前畫面、layout、DOM 對應起來，判斷這次互動指向哪個 element。

假設判定結果是那顆 button：

Browser determines
        │
        ▼
button DOM object = event target

這個最初被 Browser 判定為事件對象的 DOM object，就是 target。

6. Browser 為這次互動建立 Event object

知道 target 後，Browser 會建立一個代表這次 runtime 事件的 Event object。

Click Event
├── type = "click"
└── target ─────► button DOM object

因此 callback 裡若收到一個 event：

event.type
// "click"

event.target
// reference to the button DOM object

這裡要分清楚兩種 object：

Object代表什麼
button DOM object頁面上的 button element 在 DOM runtime model 中的表示。
click Event object這一次 click 互動本身的 runtime 資料。

7. JavaScript 先登記 listener

JavaScript 不需要不停輪詢「現在有沒有 click」。它可以先告訴 Browser：未來發生符合條件的事件時，請呼叫哪個 function。

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

這行程式是在 document 上建立一筆 listener registration：

EventTarget = document
event type  = click
callback    = handleClick

此時未來那次 click 還沒有發生。只是先把 callback 登記給 Browser。

8. Browser dispatch Event

當 click 真正發生，target 已經確定，Event object 也已建立。接下來 Browser 會沿著 target 所在的 DOM hierarchy 處理這次 Event，這個過程叫做 event dispatch。

Document
└── html
    └── body
        └── main
            └── button ← target

同一次 dispatch 可以分成三個 phase：

Capture phase
Document → html → body → main → button

Target phase
button

Bubble phase
main → body → html → Document

一般 click 會 bubble。因此，如果 listener 註冊在 document 且沒有使用 capture，descendant button 的 click 可以在 Bubble phase 抵達 document。

target 在 dispatch 開始前就已經決定。Capture / Target / Bubble 描述的是同一個 Event 要怎麼沿 event path 被處理，不是用來尋找 target。

9. Browser 找到 listener，呼叫 callback

當 dispatch 到達符合的 listener registration，Browser 會呼叫先前登記的 callback，並把這次 Event object 當參數傳入。

Browser dispatch
      │ finds matching listener
      ▼
handleClick(event)
            ▲
            │ Browser passes Event object

此時 JavaScript engine 才開始執行 callback body：

function handleClick(event) {
  console.log(event.target)
}

11. 這和 Faro 的交界在哪裡？

到目前為止都還是 Browser 原生機制。

Faro click tracking 真正能介入的位置，是它自己先註冊一個 listener：

Browser Event
    │ dispatch
    ▼
document listener
    │ Browser calls
    ▼
ClickInstrumentation callback

Self-check

1. HTML source、DOM、JavaScript reference 三者的關係是什麼？

Browser 解析 HTML source，建立並管理 DOM runtime objects；JavaScript 透過 DOM API 取得這些 objects 的 reference。

2. event.target 指的是什麼？

Browser 對這次 Event 判定的最初 DOM target object。

3. callback 是誰呼叫的？

JavaScript 先登記 callback；事件發生後，由 Browser 的 event dispatch 機制在適當時機呼叫 callback，並傳入 Event object。

4. Capture phase 是拿來找 target 嗎？

不是。target 在 dispatch 開始前就已確定；Capture / Target / Bubble 是 Event 沿 event path 被處理的階段。

Recap

  • HTML 是文件描述；Browser 解析後建立 DOM runtime model。
  • DOM object 由 Browser 建立與管理；JavaScript 取得的是 reference。
  • 使用者輸入先進 Browser，由 Browser 決定這次 Event 的 target。
  • Browser 建立 Event object，其中 event.target reference 到 target DOM object。
  • JavaScript 用 addEventListener() 先登記 callback。
  • Browser dispatch Event；一般 click 可從 target 往 ancestors bubble。
  • dispatch 到符合的 listener 時，Browser 呼叫 callback(event)。
