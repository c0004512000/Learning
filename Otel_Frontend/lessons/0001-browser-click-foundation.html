瀏覽器如何知道你點了哪裡

Milestone 1 · 先建立 browser 原生事件邊界，再回到 Faro click tracking

你在領班助手按下「每日生產排程」時，Faro 要記錄這次互動。但在談 Faro 之前，先回答一個更底層的問題：

Faro 還沒介入以前，瀏覽器本身怎麼知道「你點了哪個頁面元素」，又怎麼讓 JavaScript 收到這件事？

這堂課只建立這條 browser 原生因果鏈。詳細 browser prerequisite 若卡住，就走 reference 支線；理解後再回來，不把所有 DOM 細節塞進主課。

1. HTML、DOM、畫面不是同一件事

假設 HTML 裡有：

<main>
  <button id="schedule">每日生產排程</button>
</main>

瀏覽器解析 HTML 後，會建立可由程式操作的 DOM 物件，例如代表按鈕的 HTMLButtonElement。你可以先把關係想成：

HTML source text
      ↓ 瀏覽器解析
DOM objects in browser memory
      ↓ 搭配 CSS 進行 layout / paint
你看到的畫面
東西這裡先怎麼理解
HTML瀏覽器收到的標記文字。
DOM瀏覽器根據文件建立、彼此有 tree 關係的可操作物件。
畫面瀏覽器依 DOM、CSS 等資訊實際呈現給人的結果。
如果「DOM object」仍然抽象： 先走 Reference｜DOM、document 與事件分派。那張卡會直接把 Document、button、listener list 與 event path 展開。

2. document 是目前網頁的 Document 物件

在頁面 JavaScript 裡：

document.querySelector('#schedule')

document 不是泛稱「文件」，也不是 documents 清單。它指向目前這張 HTML 文件對應的 Document 物件；JavaScript 可以從這個入口走進 DOM tree 找其他 DOM 物件。

document
└── html
    └── body
        └── main
            └── button#schedule

3. 你真的點下去：Event 是瀏覽器建立的

使用者點擊後，不是 JavaScript 先偵測到。瀏覽器／平台先接收到輸入，決定此次互動的 DOM target，然後建立對應的 browser Event object。

例如：

event.type   → "click"
event.target → 被點到的 DOM object
這個 Event object 不是 telemetry 紀錄。 它是瀏覽器處理這次互動時使用的事件資料。除非 Faro 或你的程式另外讀取、轉換、送出並讓 backend 儲存，否則不會自動變成日後可以查詢的 click history。

4. 瀏覽器接著「分派」event

在這裡，dispatch event 翻成「分派事件」比較精準。不是送到網路，而是瀏覽器依 DOM tree 建立事件路徑，把 event 分派到路徑上的 EventTarget。

Capture： document → html → body → main → button
Target：                                      button
Bubble：  button → main → body → html → document

路徑經過某個 EventTarget 時，瀏覽器會檢查那裡是否有符合此 event type 的 listener registration。

5. JavaScript 不是「抓 event」，而是先把 callback 登記出去

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

這段不是啟動一個 JavaScript 迴圈去不停找 click。它比較接近：

在 document 上登記：
- event type: click
- callback: handleClick
- options: ...

之後 click event 被瀏覽器分派、路徑走到符合的 listener registration 時，瀏覽器主動呼叫：

handleClick(event)
            ↑
        本次 Event object
        由瀏覽器傳進來
Callback 還不熟： 先走 Reference｜Callback 到底是什麼。重點是先分清楚 handleClick 與 handleClick()，以及「誰決定何時呼叫」。

6. 把一次 click 的因果鏈走完整

使用者 click
  → browser 接收輸入
  → browser 決定 DOM target
  → browser 建立 click Event
  → browser 分派 event
  → 找到相符 listener registration
  → browser 呼叫 callback(event)
  → JavaScript 在 callback 裡讀 event.target

Recap

  • HTML source、DOM objects、rendered 畫面是三個不同層次。
  • document 指目前 HTML 文件的 Document 物件。
  • click Event 是瀏覽器在使用者互動發生後建立的。
  • dispatch 在這裡理解為「分派」：沿 DOM event path 處理 event。
  • addEventListener() 先建立 listener registration，其中包含 callback。
  • JS 不主動抓 event；browser 分派事件時呼叫 callback，並把 Event object 傳進去。
  • Browser Event object 不等於 Faro telemetry。
