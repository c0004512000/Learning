一次 click 如何進入 JavaScript？

Milestone 1 · Browser native Event → JavaScript callback

這堂課的目標
學完後，你應該能從「使用者點下一個已經 render 出來的 element」開始，完整解釋 Browser 如何確定 target、建立 Event object、dispatch Event，最後呼叫 JavaScript callback。

這堂課假設你已經知道 Lesson 0 的前提：Browser 已經把 HTML 轉成 live DOM，JavaScript 可以透過 Browser 提供的 Web APIs 操作 DOM objects。這裡不再重教 source/runtime boundary，只回答一個問題：

使用者點下去之後，為什麼最後會執行 handleClick(event)？

如果「Browser / DOM / JavaScript / Web API」的關係還不穩，先回 Lesson 0。

1. JavaScript 先登記 listener

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

這裡還沒有 click 發生。JavaScript 只是先透過 Browser 的 Event API 建立一筆 listener registration：

EventTarget = document
event type  = "click"
callback    = handleClick
capture     = false（預設）

addEventListener() 在 Browser-side JavaScript 很常見；它的核心用途是：先告訴 Browser「未來這種 Event dispatch 到這裡時，要呼叫哪個 function」。

2. 使用者輸入發生時，Browser 先確定 target

假設目前 live DOM 是：

Document
└── body
    └── main
        └── button#buy

使用者在畫面上點了一個位置。Browser 會把輸入座標與目前 layout / rendered content 對照，判定這次 click 指向哪個 element。

User input
    │ Browser receives
    ▼
position / rendered layout
    │ hit testing
    ▼
button#buy = target
target 在 event dispatch 開始前就已經確定。
Capture phase 不是 Browser 從 document 一路往下「找 target」。

3. Browser 為這次互動建立 Event object

target 已知之後，Browser 建立代表「這一次 click」的 Event object：

Click Event object
├── type = "click"
├── target ─────────► button#buy
├── currentTarget
├── eventPhase
├── clientX / clientY
└── ...

這裡要特別分清楚 object direction：

Event object ── target reference ──► button DOM object

不是：
button DOM object
└── 暫時掛上一個 Event object

也就是說，click 發生時不需要把一組 event attributes 暫時塞進 button。Event 是獨立 object；它自己保存 target 等資料。

4. Event attributes 不是都在 dispatch 才決定

像 type、target、輸入座標等，會在 Event 建立／初始化時就有意義。Dispatch 的主要責任不是「找到 target」，而是處理：

這個已知 target 的 Event，要沿哪條 event path 處理？哪些已登記 listeners 應該在什麼順序被呼叫？

5. Browser 建立 event path

target 在 DOM hierarchy 裡有 ancestors：

Document
└── html
    └── body
        └── main
            └── button#buy  ← target

Browser 可以利用這條 hierarchy 建立本次 Event dispatch 的 path。這條 path 已知之後，才進入 Capture / Target / Bubble 的處理。

6. Dispatch 是「沿 path 執行 listener 規則」

Capture phase
Document → html → body → main → button

Target phase
button

Bubble phase
main → body → html → Document

這三個 phase 都屬於同一次 Event dispatch。

精準理解：
Dispatch 可以先想成 Browser 拿著這次 Event，沿既定 event path 檢查 listener registrations，依 event type、capture 設定與目前 phase 決定哪些 callback 要被呼叫，以及呼叫順序。

7. 為什麼不能「target 是 button，就只看 button 有沒有 listener」？

因為 listener 可以掛在 ancestors：

button.addEventListener('click', buttonHandler)
main.addEventListener('click', mainHandler)
document.addEventListener('click', documentHandler)

同一次 button click 可以沿 event path 讓多個不同 EventTargets 上的 listeners 被處理。因此：

知道 target
≠
已經知道只需要呼叫 target 自己的 listener

這也是 Faro ClickInstrumentation 可以只在 document 放一條 listener，卻收到 descendant clicks 的基礎。

8. event.target 與 event.currentTarget

整次 dispatch 中：

event.target
→ 最初被判定的 target，這裡一直是 button#buy

event.currentTarget
→ Browser 現在正在執行哪一個 EventTarget 上的 listener

例如 Event bubble 到 document listener 時：

event.target        → button#buy
event.currentTarget → document
event.eventPhase    → BUBBLING_PHASE

所以真正會隨 dispatch 改變的 runtime 狀態之一，是 currentTarget、eventPhase 這類「現在走到哪裡」的資訊；不是把 Event 搬到不同 DOM objects 上。

9. Dispatch 到 listener 時，Browser 才 call back JavaScript

當 Browser 走到符合條件的 listener registration：

Browser dispatch
      │ reaches matching listener
      ▼
callback = handleClick
      │ Browser calls
      ▼
handleClick(event)
            ▲
            │ same Event object is passed in

JavaScript 並不是不停 polling「現在有沒有 click」；它先登記 function，之後由 Browser call back。

10. Event object 的生命週期

Event object 是一個正常的 runtime object。概念上：

Browser creates Event
      ↓
dispatch
      ↓
listeners receive reference
      ↓
dispatch ends
      ↓
如果 JavaScript 沒有繼續保存 reference
      ↓
之後可以被 garbage collection

如果程式刻意保存：

let savedEvent

document.addEventListener('click', event => {
  savedEvent = event
})

那 JavaScript 還持有 Event reference，它就可能繼續存在。這不是 Browser 在 dispatch 後「把 Event 從 target 拔掉」；target 從來沒有被掛上 Event object。

11. 沒有 listener，也可能有 Event

Event system 不只是為了 JavaScript listener 而存在。Browser 還可能需要處理 element 的預設行為，例如 link navigation、checkbox toggle 等。

所以可以有：

Browser receives interaction
  ↓
creates / dispatches Event
  ↓
沒有 JavaScript listener 需要呼叫
  ↓
仍可能有 browser default behavior

因此「先有 Event，再依 dispatch 規則看有哪些 listeners」不是無效設計；Event 是 Browser 對一次互動的標準 runtime representation，而 listener invocation 只是 dispatch 的一部分。

12. 一次 click 的完整因果鏈

JavaScript beforehand:
document.addEventListener('click', handleClick)
        │ registers callback
        ▼
listener registration exists

Later...

User clicks
    │
    ▼
Browser receives input
    │ hit testing
    ▼
target = button
    │ creates
    ▼
Click Event object
    │ builds / uses event path
    ▼
Browser dispatches Event
    │
    ├── Capture
    ├── Target
    └── Bubble
          │ matching listener reached
          ▼
Browser calls handleClick(event)
          │
          ▼
JavaScript executes callback

到這裡都還是 Browser 原生 Event system。Faro click tracking 的入口只是其中一條 listener registration：

document.addEventListener('click', ClickInstrumentation callback)
        │
        │ later Browser dispatches descendant click
        ▼

        ▼

Self-check

1. Dispatch 是拿來找 event.target 嗎？

不是。target 在 dispatch 前已經確定；dispatch 依 event path、phase 與 listener registrations 決定哪些 callbacks 在什麼順序被呼叫。

2. Event object 會暫時掛在 target DOM object 上嗎？

不會。Event 是獨立 object；event.target 反過來 reference 到 target DOM object。

3. 已經知道 target 是 button，為什麼還需要 event path？

因為 listeners 可以註冊在 target 的 ancestors；同一次 Event 可能需要依 Capture / Target / Bubble 規則處理多個 EventTargets 上的 listeners。

4. event.target 與 event.currentTarget 最大差異是什麼？

target 指這次 Event 最初的 target；currentTarget 指目前 callback 所屬的 EventTarget，會隨 dispatch 位置改變。

Recap

  • JavaScript 先用 addEventListener() 建立 listener registration。
  • 使用者輸入發生時，Browser 先透過 hit testing 確定 target。
  • Browser 建立獨立 Event object；event.target reference 到 target DOM object。
  • Dispatch 不是找 target，而是沿 event path 依規則處理 listeners。
  • Capture / Target / Bubble 是同一次 dispatch 的不同階段。
  • event.target 基本維持最初 target；currentTarget / eventPhase 反映目前 dispatch 狀態。
  • 符合 listener registration 時，Browser 呼叫 callback 並傳入 Event object。
  • Event 沒有掛在 target 上；沒有 reference 後，Event object 之後可由 GC 回收。
