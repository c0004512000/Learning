一次 click 如何進入 JavaScript？

Milestone 1 · Browser native Event → JavaScript callback

這堂課的目標
學完後，你應該能從「使用者點下一個已經 render 出來的 element」開始，完整解釋 Browser 如何確定 target、建立 Event、分派 Event，最後呼叫 JavaScript callback。

這堂課沿用 Lesson 0 的前提：Browser 已經建立 live DOM，JavaScript 也可以透過 Browser 提供的 API 操作 DOM。

使用者點下去之後，為什麼最後會執行 handleClick(event)？

1. JavaScript 先登記 listener

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

這時候 click 還沒發生。這行只是在 Browser 那邊先登記：

掛在哪裡：document
等哪種事件：click
到時要呼叫誰：handleClick

這筆預先保存的設定，就是 listener registration。其中 handleClick 是 callback：先把 function 交出去，之後由 Browser 在正確時機呼叫。

2. 使用者真的點下去時，Browser 先確定 target

假設目前 DOM 是：

Document
└── body
    └── main
        └── button#buy

使用者點畫面上的某個位置後，Browser 會把輸入位置與目前 render 出來的畫面對照，判定這次 click 命中哪個 element。

User click
    │ Browser receives
    ▼
目前畫面位置
    │ Browser 判定命中的 element
    ▼
button#buy = target
target 在 Event dispatch 開始前就已經確定。
後面的 Capture / Target / Bubble 不是拿來搜尋 target。

3. Browser 建立代表這次 click 的 Event object

target 已知後，Browser 建立一個獨立 Event object，代表「這一次 click」：

Click Event object
├── type = "click"
└── target ─────────► button#buy

方向要分清楚：

Event object ── target reference ──► button DOM object

不是：
button DOM object
└── 暫時掛上一個 Event object

所以 Event 是獨立 object；event.target 只是指向這次 click 最初命中的 DOM object。

4. target 已知後，Browser 才建立這次 Event 要走的 path

target 的父層一路往上是：

Document
└── html
    └── body
        └── main
            └── button#buy  ← target

Browser 會利用這條父子關係建立本次 Event 的 event path：也就是這次分派過程會沿著哪些 DOM objects 處理 listeners。

5. Dispatch 的責任不是找 target，而是依 path 處理 listeners

event dispatch（事件分派）可以先理解成：

Browser 拿著這次 Event，沿既定 event path，依規則決定哪些已登記 listeners 要在什麼順序被呼叫。

同一次 dispatch 分成三段：

Capture phase
Document → html → body → main → button

Target phase
button

Bubble phase
main → body → html → Document

Capture / Target / Bubble 都是同一次 Event dispatch 的不同階段。

Capture 開始以前 target 已經知道；Bubble 也不會讓 target 自己的同一個 listener 再自動跑一次。Target phase 處理 target，Bubble 接著處理 target 的父層。

6. 為什麼知道 target 是 button，還不能只看 button listener？

因為 listener 可以掛在父層：

button.addEventListener('click', buttonHandler)
main.addEventListener('click', mainHandler)
document.addEventListener('click', documentHandler)

所以：

知道 target = button
        │
        └── 還要看 event path 上
            哪些 objects 有符合規則的 listeners

這也是 Faro ClickInstrumentation 可以只在 document 放一條 listener，卻收到 descendant button click 的基礎。

7. event.target 與 event.currentTarget

event.target 已經建立：它指向這次 click 最初命中的 button。

現在再加入另一個欄位：

event.currentTarget
→ Browser 現在正在執行哪一個 object 上的 listener

例如這次 click 已經 bubble 到 document listener：

event.target        → button#buy
event.currentTarget → document

此時若程式讀 event.eventPhase，它會得到「目前 dispatch 正在哪個 phase」的狀態；這個欄位要在已經理解 Capture / Target / Bubble 之後才有意義。

8. Dispatch 走到符合的 listener，Browser 才呼叫 callback

Browser dispatch
      │ 走到 document click listener
      ▼
callback = handleClick
      │ Browser calls
      ▼
handleClick(event)
            ▲
            │ Browser 傳入這次 Event object

JavaScript 不需要一直重複檢查「現在有沒有 click」。它先登記 callback，之後由 Browser 在 Event 分派到正確位置時呼叫。

9. 一次 click 的完整因果鏈

JavaScript beforehand:
document.addEventListener('click', handleClick)
        │ registers
        ▼
listener registration exists

Later...

User clicks
    │ Browser receives
    ▼
target = button
    │ Browser creates
    ▼
Click Event object
    │ Browser builds event path
    ▼
Event dispatch
    │
    ├── Capture
    ├── Target
    └── Bubble
          │ reaches matching listener
          ▼
Browser calls handleClick(event)
          │
          ▼
JavaScript executes callback

Recap

  • JavaScript 先用 addEventListener() 登記 listener 與 callback。
  • 使用者輸入發生後，Browser 先確定這次 Event 的 target。
  • Browser 建立獨立 Event object；event.target 指向最初 target DOM object。
  • Browser 依 DOM 父子關係建立本次 Event 的 event path。
  • Dispatch 不是搜尋 target，而是沿 path 依 Capture / Target / Bubble 規則處理 listeners。
  • event.target 保留最初 target；event.currentTarget 表示目前 callback 所屬的 object。
  • Dispatch 到符合的 listener 時，Browser 呼叫 callback 並傳入 Event object。
