Browser 到底在前端程式裡做什麼？

Prerequisite · Source code → Browser runtime → DOM / Web APIs

這堂課的目標
學完後，你應該能解釋：HTML／CSS／JavaScript 為什麼不是「打包在一起就彼此天然知道」；Browser 為什麼需要建立 DOM；JavaScript 為什麼能寫 document.querySelector()、fetch()；以及 source code 與目前 runtime state 為什麼是兩回事。

這不是一門完整前端基礎課。它只補 Faro 主線真正需要的 Browser runtime 先備知識：後面要理解 click instrumentation、Browser DevTools、Faro transport 與 CORS，都會依賴這個模型。

1. 先分清楚：你部署的是 source，使用者操作的是 runtime

假設前端部署後有：

dist/
├── index.html
├── app.js
└── style.css

它們可以一起被部署，但仍然是不同種類的輸入：

輸入主要描述
HTML文件結構與內容。
CSS呈現與樣式規則。
JavaScript程式邏輯與行為。

這三種分工不是因為「技術上只能這樣做」。Web Platform 選擇把 structure、presentation、behavior 分成不同 abstraction，讓 Browser 可以分別解析、套用、執行。

2. Browser 不是 HTTP Server，也不只是 JavaScript runtime

對前端應用來說，Browser 更接近一個 Web Application host environment：

Browser
├── HTML parser
├── DOM
├── CSS / layout / rendering
├── JavaScript engine
├── Event system
├── Networking
├── Storage
└── Security sandbox

HTTP Server 的責任可以很單純：把 HTML／JS／CSS 回給 Browser。檔案到達 Browser 之後，真正讓應用程式「活起來」的是 Browser。

3. Kubernetes 對照：source declaration ≠ runtime state

這個差異可以用 Kubernetes 對照：

Kubernetes
Deployment YAML
    │ apply / reconcile
    ▼
runtime objects / Pods / status

Browser
HTML source
    │ parse
    ▼
DOM runtime objects

Git 裡的 YAML 不等於現在 cluster 裡真的有哪些 Pod；同樣地，Server 回來的原始 HTML 也不等於 Browser 此刻正在維護的頁面狀態。

4. 為什麼需要 DOM？

原始 HTML 是文字描述：

<button id="buy">Buy</button>

Browser 需要一份可以在 runtime 中查詢、修改、建立 parent/child 關係、接收 Event 的結構。因此它解析 HTML，建立 DOM objects：

HTML source text
      │ Browser parses
      ▼
Document
└── html
    └── body
        └── HTMLButtonElement
            id = "buy"
            textContent = "Buy"

DOM 不是額外繞一層的資料庫；它就是 Browser 對「目前 document」建立與維護的 object model。

5. JavaScript language 本身不等於 Browser Web APIs

JavaScript 核心語言本身提供的是像：

Object
Array
Promise
function
if / for / class ...

而在 Browser 裡，host environment 另外提供：

document
window
fetch
localStorage
addEventListener
...

因此 document 並不是 ECMAScript 核心語言天生知道 DOM；是 Browser 把目前頁面的 Document object 暴露給 JavaScript 使用。

精準模型：
JavaScript engine 執行語言；Browser 作為 host environment 提供 DOM、networking、events 等外部能力。兩者合作，才形成 Browser 裡的 JavaScript 執行環境。

6. document.querySelector() 到底在問什麼？

const element = document.querySelector('#buy')

它不是回頭搜尋你的 HTML source file；它是在目前 Document 的 DOM tree 裡，找第一個符合 CSS selector #buy 的 Element。

JavaScript
    │ calls DOM API
    ▼
document.querySelector('#buy')
    │ Browser searches current DOM
    ▼
Element reference returned to JavaScript

#buy 只限制 id="buy"，不限制 tag type：

<button id="buy">...  → 可以找到
<div id="buy">...     → 可以找到
<p id="buy">...       → 可以找到

如果要限定 button，才寫 button#buy。

7. DOM 改了，原始 HTML source 不會跟著被改掉

假設 Server 原本回傳：

<button id="buy">Buy</button>

JavaScript 後來執行：

document.querySelector('#buy').remove()

結果是：

original HTML source
        │ parse
        ▼
initial DOM
        │ JavaScript mutates
        ▼
current DOM  ← button 已不存在

原始 response/source 不會因此被改寫。這也是 Browser DevTools 的 live DOM 與「最初下載到的 source」可能不同的原因。

8. 那 fetch() 為什麼也是 Browser 提供？

Network I/O 也不是 JavaScript 核心語言本身的能力，而是 host environment 提供的 runtime capability：

JavaScript
    │ calls
    ▼
fetch(...)
    │ Browser networking + security rules
    ▼
OS networking
    ▼
Network

同一個 JavaScript 語言跑在不同 host environment，能使用的能力可以不同。Browser 有自己的 sandbox 與 Web security model；Node.js 則是另一個 host environment。

這裡先停在 responsibility boundary。CORS 不在 Lesson 0 展開；它會在 Faro telemetry 真正透過 Browser 傳往 Alloy 的 Lesson 5 再正式處理。

9. 把整個模型收斂成一張圖

HTML / CSS / JavaScript source
            │ Browser loads
            ▼
┌─────────────────────────────────┐
│ Browser = Web App host          │
│                                 │
│ HTML ──parse──► DOM             │
│ CSS  ──style──► layout/render   │
│ JS Engine executes JavaScript   │
│          │                      │
│          ├─ DOM APIs ─► DOM     │
│          ├─ Event APIs          │
│          └─ fetch ────► Network │
└─────────────────────────────────┘

Self-check

1. 為什麼「HTML、CSS、JS 一起打包」不代表 JavaScript 天然持有每個 HTML element？

因為它們是不同輸入；Browser 解析 HTML 後才建立目前的 DOM runtime objects。JavaScript 要操作頁面時，是透過 Browser 提供的 DOM API 取得這些 objects 的 reference。

2. DOM 比較像原始 YAML，還是 Kubernetes runtime objects？

比較像 runtime objects。HTML source 比較接近 declaration；DOM 是 Browser 對目前 document 維護的 runtime model。

3. document、fetch 是 JavaScript 核心語言本身的一部分嗎？

不是。它們是 Browser host environment 提供給 JavaScript 使用的 Web APIs / host objects。

4. JavaScript 移除 DOM button，Server 原本回傳的 HTML 會跟著被刪掉嗎？

不會。被修改的是目前 Browser 維護的 live DOM runtime state。

Recap

  • HTML／CSS／JavaScript 是不同種類的 source；一起部署不代表 runtime 中彼此天然綁定。
  • Browser 是 Web Application host environment，不只是 JavaScript engine。
  • HTML source 經 Browser parse 後形成 DOM runtime objects。
  • JavaScript 透過 Browser 提供的 DOM APIs 取得並操作 DOM object references。
  • document.querySelector() 查的是目前 DOM，不是回頭搜尋原始 HTML source。
  • DOM mutation 不會改寫最初 HTML source。
  • fetch() 也是 host 提供的 runtime capability；Browser 會套用自己的 networking / security rules。
如果你還無法自己重建「source → Browser → runtime DOM → JavaScript reference」這條鏈，先停在這裡問我。Lesson 1 會直接把這個模型拿來解釋一次 click 如何進入 JavaScript callback。
