Browser 到底在前端程式裡做什麼？

Prerequisite · Source code → Browser runtime → DOM / Web APIs

這堂課的目標
學完後，你應該能解釋：前端檔案被下載到 Browser 後，Browser 做了什麼；DOM 為什麼存在；以及 JavaScript 為什麼能使用 document.querySelector() 與 fetch()。

先定義本課會一直用到的兩個詞：

  • source：你寫好並部署出去的 HTML、CSS、JavaScript 檔案。
  • runtime：這些程式真正跑起來之後，Browser 當下正在維護的狀態。
本課 Reference
之後只想快速回查 Browser、DOM、JavaScript 與 Web APIs 的責任邊界時，可直接使用： Browser runtime、JavaScript 與 Web APIs Reference →

1. 一起部署，不代表 JavaScript 天然持有 HTML element

假設前端部署後有：

dist/
├── index.html
├── app.js
└── style.css

它們可以一起部署，但分工不同：

檔案主要負責
HTML描述頁面有哪些內容與結構。
CSS描述這些內容要怎麼呈現。
JavaScript描述程式要執行的邏輯與行為。

這是 Web 的設計分工，不是「技術上只能用三種語言」。一起部署只代表它們一起被交給 Browser，不代表 app.js 裡會自動出現每個 HTML element 的變數。

2. Browser 是讓 Web 應用真正跑起來的環境

HTTP Server 可以把 HTML、CSS、JavaScript 回傳給 Browser；但收到檔案之後，還需要有人負責：

解析 HTML
建立並維護 DOM
套用 CSS 並計算畫面
執行 JavaScript
接收滑鼠／鍵盤輸入
處理網路 request
套用 Browser 安全限制

這些工作由 Browser 承接。因此 Browser 不只是「顯示網頁」，也不只是「執行 JavaScript」；它是 Web 應用真正運作的執行環境。

3. Kubernetes 對照：source 不等於 runtime state

Kubernetes
Deployment YAML
    │ apply / reconcile
    ▼
目前 cluster runtime objects

Browser
HTML source
    │ Browser parses
    ▼
目前 DOM runtime objects

Git 裡的 YAML 不等於 cluster 現在實際有哪些 Pod。同樣地，Server 回傳的原始 HTML，也不等於 Browser 此刻正在維護的頁面狀態。

4. DOM 是 Browser 對目前頁面建立的可操作模型

原始 HTML 只是文字：

<button id="buy">Buy</button>

Browser 解析後，會建立目前文件的 DOM 結構：

Document
└── html
    └── body
        └── button
            id = "buy"
            textContent = "Buy"

這份 DOM 讓 Browser 與 JavaScript 可以處理「目前真的存在什麼 element、彼此是什麼父子關係、現在的 attribute 是什麼」。

所以 DOM 不是多繞一層的資料庫；它就是 Browser 對目前頁面結構建立並持續維護的 runtime model。

5. JavaScript 能力和 Browser 額外提供的能力要分開

JavaScript 語言本身能表達像：

變數
if / for
function
Object / Array

JavaScript 跑在 Browser 裡時，Browser 另外提供：

document
fetch
localStorage
addEventListener
...

Browser 裡有一個負責執行 JavaScript 的元件，通常稱為 JavaScript engine。但 document、DOM、networking、Event system 等能力，是 Browser 這個執行環境另外提供的。

因此 document 不是 JavaScript 天生就知道 DOM；是 Browser 把目前文件對應的 Document object 提供給 JavaScript 使用。

6. document.querySelector() 查的是目前 DOM

const element = document.querySelector('#buy')

這行不是回頭搜尋原始 HTML 檔案。它是在 Browser 目前維護的 DOM tree 裡，找第一個符合 #buy 的 element。

JavaScript
    │ 呼叫 DOM API
    ▼
document.querySelector('#buy')
    │ Browser 查目前 DOM
    ▼
回傳 element reference

#buy 表示找 id="buy"，不限制它一定是 button：

<button id="buy">...  → 可以找到
<div id="buy">...     → 可以找到
<p id="buy">...       → 可以找到

如果要限定是 button，才寫 button#buy。

7. 改 DOM，不等於改掉原始 HTML

假設 Server 原本回傳：

<button id="buy">Buy</button>

後來 JavaScript 執行：

document.querySelector('#buy').remove()

結果是：

original HTML source
        │ Browser parses
        ▼
initial DOM
        │ JavaScript modifies
        ▼
current DOM  ← button 已不存在

被改的是目前 Browser 維護的 DOM；Server 原本回傳的 HTML 不會因此被回寫。

8. fetch() 也是 Browser 提供的外部能力

JavaScript 要對外送 HTTP request 時，在 Browser 裡會使用 Browser 提供的 networking API：

JavaScript
    │ calls fetch(...)
    ▼
Browser networking
    │ 使用 OS 網路能力
    ▼
Network

Browser 也會在這一層套用安全限制。可以先把它理解成：網頁裡的 JavaScript 不是想連哪裡、讀什麼都完全沒有邊界。

跨來源 request 的具體規則會在後面的 Faro telemetry 傳送課程再學；Lesson 0 先只建立「request 仍由 Browser 執行環境承接」這個責任邊界。

9. 把整個模型收斂成一張圖

HTML / CSS / JavaScript source
            │ Browser loads
            ▼
Browser
├── HTML ──parse──► DOM
├── CSS ─────────► layout / render
├── JavaScript engine ──► 執行 JS
├── Event system
└── Networking

JavaScript
├── DOM API ─────► 讀／改目前 DOM
├── Event API ───► 登記事件處理
└── fetch() ─────► 請 Browser 發 request

Recap

  • source 是部署出去的檔案；runtime 是 Browser 真正跑起來後的當下狀態。
  • HTML／CSS／JavaScript 可以一起部署，但各自扮演不同角色，不會因此自動互相持有。
  • Browser 負責解析、畫面計算、執行 JavaScript、處理 Event、networking 與安全限制。
  • DOM 是 Browser 對目前文件建立並維護的 runtime model。
  • JavaScript 透過 Browser 提供的 DOM APIs 取得並操作目前 DOM。
  • document.querySelector() 查目前 DOM，不是回頭搜尋原始 HTML source。
  • 修改 DOM 不會回寫 Server 原本回傳的 HTML。
  • fetch() 在 Browser 裡也是由 Browser 提供並執行 networking 能力。
