1. listener 在哪裡，和 click 從哪裡開始，是兩件事

ClickInstrumentation 註冊的是：

document.addEventListener('click', this.handleClick)

當 descendant click bubble 到 document，Browser 呼叫 handleClick(event)。這時：

event.currentTarget → document
                      目前正在執行 listener 的 object

event.target        → 使用者最初點到的 element
                      例如 span / button / a

所以 currentTarget 回答「listener 現在在哪裡執行」；target 回答「這次 click 最初命中哪個 element」。

2. 為什麼 extraction 要從 event.target 開始？

因為 currentTarget 在這條 listener 裡幾乎永遠只會告訴你：

currentTarget = document

但 ClickInstrumentation 真正想知道的是：

這次 click 是從 DOM tree 的哪個位置進來？它自己或它的 ancestors 上，有沒有我要追蹤的 attribute？

因此搜尋起點必須是 event.target。

讀 event.target 不代表 listener 掛在 target 上。
listener 仍在 document。target 只是 Browser Event 保留的原始命中 element reference。

3. closest() 解決 ancestor 上才有 attribute 的情況

<p-button data-link-name="MCCS">
  <button>
    <span>MCCS</span>
  </button>
</p-button>

如果使用者點到內層 span：

event.target = span

document
  └── ...
      └── p-button[data-link-name="MCCS"]
          └── button
              └── span  ← target

ClickInstrumentation 從 span 往 ancestor 找：

span                              ✗
  ↑
button                            ✗
  ↑
p-button[data-link-name="MCCS"]   ✓

這就是 closest('[data-link-name]') 的用途。它不是找 listener，而是找「離 target 最近、具有指定 attribute 的 ancestor / self」。

4. data-* 是誰建立的？

角色責任
Browser / HTML原生支援 data-* custom data attributes。
Foreman developer在 template / component markup 上實際加上 data-link-name 與它的值。
Faro click package不建立這些 DOM attributes；只依 trackAttributes 去讀。
 
Developer marks DOM
      ↓
data-link-name exists
      ↓
ClickInstrumentation reads it
      ↓
Faro payload

5. Foreman Assistant 現在實際追蹤哪些 attributes？

目前已驗證的初始化設定只有：

trackAttributes: [
  'data-link-name'
]

所以現在的 Foreman click tracking 並沒有設定 data-page、data-action、data-panel-topic。

目前已驗證有 data-link-name 的地方包含：

  • 主畫面的 subsystem 入口：[attr.data-link-name]="item.subsystem"。
  • Toolbar 的五個 static link：User Guide、Reference Document、AI、Foreman Manual、Contact Administrator。

DOM 裡即使還有其他 data-*，例如 data-red-light-count，只要沒有列進 trackAttributes，就不會進 click payload。

6. 現在 payload 會送什麼？

例如 ancestor 上有：

data-link-name="MCCS"

ClickInstrumentation 會形成：

{
  link_name: "MCCS"
}

轉換規則：

data-link-name
  ↓ remove "data-"
  ↓ replace "-" with "_"
link_name

現行 click payload 只包含命中的 configured trackAttributes。它不會自動塞入所有 DOM 資訊。

7. User / device 是另外的 metadata 路徑

Click payload
└── link_name       ← data-link-name

User state
└── id / username   ← getUser() / Faro user state

Device metadata
└── device.type     ← device detector

因此不要把 user、device 誤認為 ClickInstrumentation 從 DOM 抽出的額外 click attributes。

8. 什麼情況不會送 click telemetry？

第一種：target 與 ancestors 都找不到 data-link-name。

closest('[data-link-name]') → not found
payload = {}
→ stop
→ 不呼叫 pushEvent()

第二種：同一個 EventTarget 在約 300 ms 內重複 click，後續事件會被 throttle。

9. 目前 Foreman 的完整 click 資料流

User click
    │ Browser determines target
    ▼
Browser Event
    │
    │ target = original clicked element
    │ currentTarget = document
    ▼
document listener
    │ Browser calls
    ▼
ClickInstrumentation.handleClick(event)
    │
    ├── start from event.target
    │
    ├── find configured attribute
    │      └── data-link-name only
    │
    ├── closest('[data-link-name]')
    │
    ├── not found → empty payload → stop
    │
    ├── found → { link_name: value }
    │
    ├── same target within 300 ms → stop
    │
    ▼
api.pushEvent('click', payload)
    │
    ▼
Faro click telemetry

Recap

  • currentTarget 是目前 listener 所在 object；這裡是 document。
  • target 是原始 click element，所以是 closest() 搜尋的起點。
  • listener location 與 click origin 是兩個不同概念。
  • data-link-name 由 Foreman developer 放在 DOM 上，Faro package 只讀取。
  • Foreman 現在 trackAttributes 只有 data-link-name。
  • data-link-name="MCCS" 會形成 { link_name: "MCCS" }。
  • 找不到 attribute 就不送；同 target 約 300 ms 內重複 click 也會被擋。
