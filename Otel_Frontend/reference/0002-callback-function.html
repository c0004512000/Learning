Callback 到底是什麼？

Reference · 分清楚「函式本身」、「現在呼叫」與「之後由誰呼叫」

先抓住一句話：
callback（回呼函式）不是特殊語法，也不是特殊 function 類型。它描述的是一個角色：你把函式本身交給另一方，之後由另一方在自己的流程中決定何時呼叫它。

1. 函式本身 vs 現在呼叫函式

function handleClick(event) {
  console.log(event.target)
}

handleClick      // 函式本身
handleClick()    // 現在立刻呼叫函式
寫法意思現在執行了嗎？
handleClick取得函式本身，可以存起來或傳給別人。還沒有。
handleClick()現在呼叫這個函式。有。

2. 放進 DOM event：先把函式登記出去

document.addEventListener('click', handleClick)

這裡傳的是 handleClick，不是 handleClick()。意思是把函式本身提供給 browser-managed event listener 機制，先存進 listener registration。

listener registration
- event type = "click"
- callback   = handleClick
- capture    = false（預設）
這時還沒有未來那顆 click Event object。
現在只是把規則登記好：未來符合條件的 Event 被 dispatch 到這裡時，要呼叫哪個 callback。

3. 誰真的呼叫 callback？

對 browser DOM event 這個案例，控制流是：

JavaScript 先呼叫瀏覽器提供的 API

JavaScript
   │
   └──► document.addEventListener('click', handleClick)
                                      │
                                      └── 登記 handleClick

之後真的發生 click

Browser 建立＋dispatch Event
   │
   └──► 找到相符 listener registration
              │
              └──► handleClick(event)
                        ↑
                  Browser 呼叫 callback

所以在這個情境中，最精確的說法不是「JavaScript 抓到 Event」，而是：

JavaScript 先登記 callback；Browser 在 Event dispatch 過程中找到 registration，呼叫 callback，並把本次 Event object 傳進參數。

4. 為什麼叫 call back？

back 可以從控制權方向理解：

先：你的程式呼叫 API，把函式交出去

你的程式 ─────► 外部 API / framework / browser mechanism

後：對方在自己的流程裡再呼叫你提供的函式

你的 callback ◄───── 對方呼叫回來

callback 不等於「把資料傳回來」，也不代表一定是非同步；重點是函式由誰決定何時呼叫。

5. 一次 click 的 callback 因果鏈

  1. JavaScript 定義 handleClick 函式。
  2. JavaScript 呼叫 document.addEventListener(...)。
  3. handleClick 函式本身被登記進 listener registration。
  4. 之後使用者真的 click。
  5. 瀏覽器決定 target 並建立 click Event object。
  6. 瀏覽器 dispatch 這顆 Event。
  7. dispatch 走到相符 listener registration。
  8. 瀏覽器呼叫 handleClick(event)。
  9. JavaScript engine 執行你寫在 callback 裡的程式。

6. Event、listener、callback 不要混在一起

名詞在 click 情境中是什麼
使用者輸入滑鼠／觸控產生的實體互動。
Event object瀏覽器為這次互動建立的 runtime 事件資料。
Listener registration事先登記的 event type + callback + options。
Callback之後會由瀏覽器呼叫的函式，例如 handleClick。
Callback argument event瀏覽器真正呼叫 callback 時，傳進來的本次 Event object reference。

7. Callback 不等於 async

Callback 描述的是控制權與呼叫責任，不是同步／非同步分類。

同步 callback

function double(x) {
  return x * 2
}

[1, 2, 3].map(double)

double 被交給 map，再由 map 在自己的迭代流程裡呼叫，所以它也是 callback。

Event callback

document.addEventListener('click', handleClick)

handleClick 的呼叫時機由未來的 browser Event dispatch 決定。

8. 用 Python 對照

def handle(value):
    print(value)

def run(callback):
    result = 123
    callback(result)

run(handle)
你先呼叫 run(handle)
          │
          └── 把 handle 函式交給 run

run() 內部之後呼叫 callback(result)
                       │
                       └── 實際就是 handle(result)

和 DOM event 的共同核心都是：「先交出函式本身，之後由接收方呼叫」。差別只是接收方與觸發條件不同。

Recap

  • Callback 是一種角色，不是特殊 function 類型。
  • handleClick 是函式本身；handleClick() 是現在呼叫。
  • Callback 的核心是：函式先交給另一方，再由另一方在自己的流程裡呼叫。
  • DOM event 中，addEventListener() 先建立 listener registration。
  • 未來 Event 發生後，是瀏覽器 dispatch Event 並呼叫 callback。
  • callback 裡的 event 是瀏覽器呼叫時傳進來的本次 Event object reference。
  • Callback 不等於 async。
