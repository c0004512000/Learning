Callback 到底是什麼？

先搞懂「把函式交出去」與「誰在什麼時候把你叫回來」

先抓住一句話： callback（回呼函式）不是特殊語法，也不是特殊種類的 function。它只是某個函式在一段互動裡扮演的角色：你把函式本身交給另一方，之後由對方決定何時呼叫它。

1. 函式本身 vs 現在呼叫函式

function handleClick(event) {
  console.log(event.target)
}

handleClick      // 函式本身
handleClick()    // 現在立刻呼叫函式
寫法意思執行了嗎？
handleClick取得函式本身，可以存起來或傳給別人。還沒有。
handleClick()現在就呼叫函式。有。

2. Callback 的核心：把函式交出去

document.addEventListener('click', handleClick)

這裡傳的是 handleClick，不是 handleClick()。意思是：

document，這個函式先交給你。之後符合條件的 click event 被分派到這裡時，請你再呼叫它。
一秒判斷法： 如果一個函式被當成值傳給另一個 API / 函式，而且接收方會在自己的流程裡呼叫它，那個被交出去的函式就在扮演 callback。

3. 為什麼叫 call back？

back 是相對於最開始的控制方向。

第一步：你的程式先呼叫瀏覽器 API

你的程式
   │
   └──► document.addEventListener('click', handleClick)
                                  │
                                  └── 把 handleClick 交出去

之後：瀏覽器在適當時機呼叫回你的函式

瀏覽器
   │
   └──► handleClick(event)
            ↑
          call back

因此 callback 不是「把資料傳回來」的意思，也不代表一定非同步。名稱描述的是：控制權先交出去，接收方之後再呼叫你提供的函式。

4. 放回 click event 情境

  1. JavaScript 建立 handleClick 函式。
  2. JavaScript 呼叫 document.addEventListener(...)。
  3. 把 handleClick 函式本身交給瀏覽器。
  4. 瀏覽器把 callback 與 event type 等設定保存在 listener registration。
  5. 之後使用者真的點擊。
  6. 瀏覽器建立並分派 click event。
  7. 事件路徑經過相符 listener 時，瀏覽器執行 handleClick(event)。
  8. JavaScript engine 開始跑你寫在 callback 裡的邏輯。
所以 JS 不是「抓到 event」。 JavaScript 先把 callback 登記給瀏覽器；瀏覽器分派事件時找到這個 callback，呼叫它，再把本次 Event object 當參數傳進去。

5. Trigger、Event、listener、callback 不要混在一起

名詞在 click 情境中是什麼
使用者動作真的按下滑鼠／觸控頁面。
Event瀏覽器為這次發生的事情建立的事件物件。
Listener registration登記在 EventTarget 上的「event type + callback + options」設定。
Callback真正會被瀏覽器呼叫的函式，例如 handleClick。

6. Callback 不等於 async

Callback 描述的是「誰負責呼叫這個函式」，不是同步或非同步。

同步 callback

function double(x) {
  return x * 2
}

[1, 2, 3].map(double)

double 被交給 map，再由 map 呼叫，所以它也是 callback。

事件 callback

document.addEventListener('click', handleClick)

handleClick 的呼叫時機由未來的事件分派決定。

7. 用 Python 對照

def handle(value):
    print(value)

def run(callback):
    result = 123
    callback(result)

run(handle)
你先呼叫 run(handle)
          │
          └── 把 handle 函式交給 run

run() 內部之後呼叫 callback(result)
                       │
                       └── 實際就是 handle(result)

自我檢查

Q1. 哪個最接近 callback 的核心？
Q2. 為什麼傳 handleClick，不是 handleClick()？

Recap

  • Callback 是一種角色，不是特殊 function 類型。
  • handleClick 是函式本身；handleClick() 是現在呼叫它。
  • Callback 的核心是：函式先被交給另一方，再由另一方決定何時呼叫。
  • back 指控制權先交出去，之後接收方再 call back 進你的程式。
  • 在 DOM event 中，瀏覽器分派事件並呼叫 listener registration 裡保存的 callback。
  • Callback 不等於 async。
