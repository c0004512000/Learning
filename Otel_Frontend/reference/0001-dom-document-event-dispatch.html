DOM、document 與事件分派

Reference · 專門拆清楚 DOM object、selector、target、listener、Capture、Target、Bubble 與 propagation

先抓住兩條主線：
① DOM object 是瀏覽器建立／管理，JavaScript 取得 reference。
② click Event 也是瀏覽器建立；JavaScript 先登記 callback，之後由瀏覽器在 dispatch 過程中呼叫。

1. HTML、DOM、JavaScript 不是同一層

HTML source text
      │
      │ Browser parse
      ▼
DOM objects in browser memory
      │
      │ Browser exposes DOM APIs
      ▼
JavaScript 可以取得 object reference 並操作
HTML element / markup
文件中的標記，例如 <button ...>。
DOM object
瀏覽器解析文件後，在記憶體中建立並管理的程式物件。
HTMLButtonElement
對應 HTML button element 的 DOM 介面／物件型別名稱。
JavaScript reference
JavaScript 指向那顆 browser-managed DOM object 的 reference。
不要說「DOM 變成 JavaScript object」。
DOM object 原本就是瀏覽器建立的 runtime object。JavaScript 只是透過 DOM API 取得它的 reference。也不需要額外發明「HTML object」這個概念。

2. 同一個固定範例：每日生產排程按鈕

<main>
  <button id="daily-schedule-button">
    每日生產排程
  </button>
</main>

daily-schedule-button 只是範例作者取的 id。它不是 browser API，也不是 Faro 名詞。

#daily-schedule-button
↑
# 是 selector 語法：找 id="daily-schedule-button" 的 element
const button = document.querySelector('#daily-schedule-button')

這行會讓 JavaScript 拿到那顆 button DOM object 的 reference。

3. document 與 DOM tree

下面是階層，不是流程。縮排每深一層就表示 child：

Document
└── html
    └── body
        └── main
            └── button
                id="daily-schedule-button"

document 是頁面 JavaScript 取得目前 HTML 文件所對應 Document DOM object 的入口。

document.querySelector(...)
         │
         └── 從目前 Document 的 DOM tree 找符合 selector 的 element

4. DOM tree 跟 Event path 有什麼關係？

DOM tree 先描述誰包含誰。當 button 成為本次 click 的 target 時，瀏覽器可以利用這個 hierarchy 建立 Event dispatch 要走的路徑。

DOM hierarchy：
Document
└── html
    └── body
        └── main
            └── button  ← target

Event dispatch 會沿這條 ancestor chain 處理 listeners。
不要把 DOM tree 的縮排與 event flow 箭頭混在一起。
DOM tree 表達 parent / child；Capture / Bubble 才是在描述同一個 Event dispatch 的處理方向。

5. Click 發生後，是誰決定 target？

滑鼠／觸控輸入
      ↓
瀏覽器收到輸入
      ↓
瀏覽器根據位置與畫面結構判定對應 element
      ↓
決定這次 Event 的 target
      ↓
建立 click Event object

如果這次點到 button：

event.target → 那顆 button DOM object
target 不是 creator。
Event 是瀏覽器建立；event.target 只是記錄這次 Event 最初指向哪個 DOM object。

6. EventTarget、listener registration、callback

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

Document、很多 Element 等物件具備 EventTarget 能力，可以事先登記 listeners。

addEventListener() 在這裡先建立／保存的概念是：

listener registration
- type: "click"
- callback: handleClick
- capture: false（預設）

這時候還沒有未來那顆 click Event object。

7. Dispatch 到底是什麼？

瀏覽器已經知道 target 後，還要回答：

Event path 上哪些已登記的 listeners 要被呼叫？按照什麼順序？

這個處理過程就是 event dispatch（事件分派）。

8. Phase 是「同一次 dispatch 現在走到哪一段」

phase 不是另一個 Event，也不是重新觸發 click。

Capture phase：外 → 內
Document → html → body → main → button

Target phase：
button

Bubble phase：內 → 外，但從 target 的 parent 開始
main → body → html → Document
Capture 開始以前 target 就已經確定。
Capture 不是瀏覽器一路往內「找 target」；它是在既有 event path 上處理 capture listeners。
Bubble 不會讓 target 自己再跑一次。
button 在 Target phase 已經處理過；Bubble 接著處理的是 button 的 ancestors。

9. capture: true / false 是 listener 的設定

// ancestor 想在 target 前收到
document.addEventListener('click', handleClick, { capture: true })

// 預設 non-capture
document.addEventListener('click', handleClick)

更精確地說：

capture: true
這個 listener 在 ancestor 的 Capture phase 時機處理。
capture: false
預設。若 listener 在 ancestor，通常在 Bubble phase 收到 descendant event；若 listener 本身就在 target，仍是在 Target phase 處理。

所以不要把「capture: false 是預設」簡寫成「Bubble 是預設」。registration option 與 runtime phase 不是同一件事。

10. event.eventPhase 是 runtime 狀態

event.eventPhase 只是讓程式在 callback 執行當下知道：「這一次 dispatch 現在在哪個 phase？」

值意義
1CAPTURING_PHASE
2AT_TARGET
3BUBBLING_PHASE

因此：

capture: true / false
→ listener registration 的預先設定

event.eventPhase
→ 本次 Event dispatch 當下的 runtime 狀態

11. event.target 與 event.currentTarget

這兩個很容易混：

event.target
→ 這次 Event 最初指向的 DOM object

event.currentTarget
→ callback 現在是在哪一個 EventTarget 的 listener 上被執行

例如 document listener 收到 button click：

event.target        → button
event.currentTarget → document

這也是 event delegation 能運作的重要基礎：ancestor listener 可以收到 descendant click，然後看 event.target 判斷最初來源。

12. Event delegation

假設 list 裡有很多 buttons：

list
├── button A
├── button B
├── button C
└── button D

不一定要每顆都各掛一個 listener：

list.addEventListener('click', event => {
  console.log(event.target)
})

因為 descendant click 可以 bubble 到 list。這種讓 ancestor 統一接 descendants events，再透過 target 判斷來源的做法叫 event delegation（事件委派）。

13. stopPropagation() 真正做什麼？

它不是防止 handler 重複、不是停止 JavaScript、也不是網路控制。它只是在這一次 Event dispatch 中告訴瀏覽器：

不要再把這個 Event 繼續傳到 event path 後面的 DOM objects。
card
└── deleteButton  ← target
deleteButton.addEventListener('click', event => {
  event.stopPropagation()
  deleteItem()
})

如果產品需求是「Delete 只刪除，不要讓外層 card 的 click handler 也收到這次 click」，這才是合理用途。

14. event.bubbles 跟 stopPropagation() 不一樣

event.bubbles
這種 Event 是否具備 target 後往 ancestors bubbling 的能力；是 Event 本身的性質。
stopPropagation()
對目前這一次 dispatch 中途喊停，不會把 event.bubbles 從 true 改成 false。

15. 一次 click 的完整控制流

HTML source
  ↓ Browser parse
DOM tree 已存在

JavaScript 先：
document.addEventListener('click', handleClick)
  ↓
保存 listener registration

之後使用者 click：
Browser 收到 input
  ↓
Browser 決定 target
  ↓
Browser 建立 click Event
  ↓
Browser dispatch Event
  ↓
Capture → Target → Bubble
  ↓
走到相符 listener registration
  ↓
Browser 呼叫 handleClick(event)
  ↓
JavaScript engine 執行 callback

Recap

  • DOM object 是瀏覽器建立／管理；JavaScript 取得 reference。
  • HTMLButtonElement 是 DOM 介面／物件型別名稱，不是另一種「HTML object」。
  • daily-schedule-button 只是範例 id；#daily-schedule-button 是 selector。
  • DOM tree 表達 parent / child；Capture / Bubble 表達 Event dispatch 方向。
  • Event 與 target 都由瀏覽器 runtime 決定／建立；target 不是 creator。
  • listener registration 在 Event 發生以前就先存在。
  • Capture / Target / Bubble 是同一次 dispatch 的不同 phase。
  • capture option 是 registration setting；event.eventPhase 是 runtime state。
  • event.target 是最初來源；event.currentTarget 是目前 callback 所屬 EventTarget。
  • Bubble 不會讓 target 的同一個 listener 自動再跑一次。
  • event.bubbles 與 stopPropagation() 是不同責任。
