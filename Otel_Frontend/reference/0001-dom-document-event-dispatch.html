DOM、document 與事件分派

先把「HTML、瀏覽器、JavaScript、Event」的責任邊界拆清楚，再談 Faro。

這張 Reference 要修正四個容易混掉的點： DOM 為什麼又會被 JavaScript 操作、#daily-schedule 到底是什麼、capture / bubbling 是什麼，以及 event.target 為什麼叫 target。

1. DOM 是瀏覽器在管，為什麼又說它是 JavaScript 物件？

先不要把「瀏覽器物件」和「JavaScript 可以操作的物件」當成互斥的兩件事。

① HTML原始文字，例如 <button>每日生產排程</button>
↓ 瀏覽器解析
② DOM瀏覽器在記憶體中建立並維護的文件物件樹。
↓ 瀏覽器提供 DOM API 給 JavaScript
③ JavaScript取得 DOM 物件的 reference，然後讀取或修改它。

所以「代表按鈕的 DOM JavaScript 物件」這句話很容易誤導。更精確的說法應該是：

DOM 物件是瀏覽器建立、瀏覽器持有的物件；JavaScript 可以透過瀏覽器提供的 DOM API 取得並操作它。

例如 HTML 裡真的只有這段文字：

<button id="daily-schedule">每日生產排程</button>

瀏覽器解析後，會建立代表這顆按鈕的 DOM object。對 JavaScript 而言，它的型別通常會看到成 HTMLButtonElement：

const button = document.querySelector('#daily-schedule')
console.log(button.constructor.name)
// HTMLButtonElement

這不是 JavaScript 自己創造了一顆按鈕，而是 JavaScript 拿到了「瀏覽器已經建立的那顆 DOM 物件」的 reference。

HTML element
原始文件中的標記，例如 <button ...>。
DOM object
瀏覽器解析後在記憶體裡建立的物件。
HTMLButtonElement
這種按鈕 DOM object 對外提供的介面／型別名稱。
「HTML object」
不是這裡應該使用的標準概念名稱，所以不要用它來理解 DOM。

2. #daily-schedule 到底是什麼？

daily-schedule 只是我在範例中替這顆按鈕取的 id。它沒有任何瀏覽器特殊意義，你可以叫它 abc、submit 或其他合法名稱。

<button id="daily-schedule">每日生產排程</button>

而前面的 # 是 selector 語法：#xxx 表示「找 id 等於 xxx 的 element」。

document.querySelector('#daily-schedule')
                       └───────┬───────┘
                               │
                     找 id="daily-schedule"

所以你有時候看到：

button#daily-schedule

這只是簡寫「一個 button，它的 id 是 daily-schedule」。它不是 HTML 原始語法。

3. DOM 的階層要看成一棵 tree，不是平行的卡片

下面才是這個範例真正的父子關係：

Document
└── html
    └── body
        └── main
            └── button id="daily-schedule"

document 是 JavaScript 裡取得最上面那個 Document 物件的入口：

document
  ↓
Document object
  ↓ 可以從這裡查 DOM tree
querySelector(...)

因此：

const button = document.querySelector('#daily-schedule')

意思不是「搜尋 HTML 字串」，而是：「從目前這份 Document 的 DOM tree 裡，找到 id 是 daily-schedule 的 DOM object」。

4. 使用者 click 後，到底是誰建立 Event？

不是按鈕自己建立 Event，也不是 JavaScript 先建立 Event。簡化後的責任鏈是：

手指 / 滑鼠輸入
      ↓
瀏覽器收到輸入
      ↓
瀏覽器判斷這個座標落在哪個 DOM element
      ↓
得到：這次 click 的目標是 button
      ↓
瀏覽器建立 click Event object
      ↓
瀏覽器把 event 朝這個 target 分派

「判斷座標落在哪個 element」可以先理解成 hit testing。現在不用記演算法，只要知道：target 是瀏覽器根據這次輸入判定出來的，不是 target 自己創造 event。

5. 為什麼叫 event.target？target 不是很像「事件要對它做什麼」嗎？

這裡的 target 比較接近「這次 event 是朝哪一個 DOM node 分派的目標」，不是「event 要攻擊／修改誰」。

你點下按鈕
    ↓
瀏覽器判定：這次 click 是發生在這顆 button
    ↓
這顆 button 成為 event 的 target
event.target 回答的是： 「這次事件最初是以哪一個 DOM object 作為目標？」

如果叫 event.triggerer，反而容易讓人以為「這個 DOM element 主動產生了 event」。但 browser click 的來源其實是使用者／輸入裝置，Event object 則是瀏覽器建立的。因此 target 更符合這個模型。

6. listener 先登記，瀏覽器之後才呼叫 callback

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

這段的意思只是先告訴瀏覽器：

請在 document 上記住：
- 我關心 click
- 到適合的階段時，請呼叫 handleClick
- 呼叫時把本次 Event object 傳進去

所以 event 參數不是函式自己生出來的：

瀏覽器：handleClick(eventObject)
                         ↓
function handleClick(event) {
                     ↑
              這個參數收到它
}

7. 先理解 bubbling，再看 capture

假設你真的點的是最裡面的 button：

document
└── html
    └── body
        └── main
            └── button  ← 你點這裡

瀏覽器處理 DOM event 時，不只會看 button 本身。事件路徑還會經過它的祖先節點。

Bubble（冒泡） event 到達 button 之後，再從最內層往外層走：button → main → body → html → document。這就是為什麼 listener 掛在 document，仍然可以收到後代 button 的 click。

你可以把它想成：button 那裡發生的 click，一層一層「往父節點冒上去」。

Capture（捕獲） 在 event 真正抵達 button 以前，瀏覽器還有一段由外往內的路徑：document → html → body → main → button。

因此完整的簡化流程才是：

Capture： document → html → body → main → button
Target：                                      button
Bubble：  button → main → body → html → document

8. 那 capture: true 是幹嘛的？

addEventListener() 可以指定「這個 listener 想在哪個階段被呼叫」。

document.addEventListener('click', handleClick, { capture: true })

capture: true 的意思是：

當 event 正在由外往內走 Capture 階段時，就執行這個 listener。

如果沒有指定，通常等同 capture: false，listener 會在一般的 target / bubbling 流程中被處理。大多數日常 click listener 不需要特別開 capture: true。

// Capture 階段執行
document.addEventListener('click', handleClick, { capture: true })

// 一般情況：不使用 capture
document.addEventListener('click', handleClick)

9. event.target 和 event.currentTarget 為什麼會不同？

現在 bubbling 已經有定義，這個差異就比較自然：

你點 button
    ↓
event.target = button

Event 冒泡到 document
    ↓
document 上的 listener 正在執行
    ↓
event.currentTarget = document
event.target
這次 event 最初指向的 DOM object；在範例中是被點到的 button。
event.currentTarget
現在正在執行的 listener 是掛在哪一個 EventTarget 上。

Recap

  • DOM 是瀏覽器建立並管理的物件樹；JavaScript 只是透過 DOM API 取得並操作這些物件。
  • HTMLButtonElement 是按鈕 DOM object 的介面／型別名稱，不代表 JavaScript 自己建立它。
  • #daily-schedule 是 selector，表示找 id="daily-schedule" 的 element。
  • button 不會自己創造 click Event；瀏覽器收到輸入、判定 target，再建立 Event object。
  • event.target 是這次事件最初指向的 DOM object。
  • bubbling 是由 target 往祖先節點走；capture 是在抵達 target 前由外往內走。
  • capture: true 只是要求 listener 在 capture 階段執行，不是 click tracking 必須設定的東西。
  • Browser Event object 與 Faro telemetry 是兩個不同層次。
