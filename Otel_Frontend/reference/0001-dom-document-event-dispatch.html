DOM、document 與事件分派

從一次 click 開始，拆清楚 target、listener、Capture、Target、Bubble，以及 Event 何時會停止往外傳。

這張 Reference 的目標：你應該能自己重建一次 click 的完整處理順序，並分清楚「Event 往 ancestor 傳」和「同一個 handler 重複執行」是兩件完全不同的事。

1. HTML、DOM、JavaScript 的責任邊界

① HTML原始標記文字，例如 <button>每日生產排程</button>。
↓ browser parses（瀏覽器解析）
② DOM瀏覽器在記憶體中建立並維護的文件物件樹。
↓ browser exposes DOM APIs（瀏覽器提供操作介面）
③ JavaScript透過 DOM API 取得 DOM object 的 reference，然後讀取或操作它。
精確模型：DOM object 是瀏覽器建立與管理的物件；JavaScript 可以透過瀏覽器提供的 DOM API 取得 reference 並操作它。

例如：

<button id="daily-schedule">每日生產排程</button>

const button = document.querySelector('#daily-schedule')
console.log(button.constructor.name)
// HTMLButtonElement
HTML element
原始文件中的標記，例如 <button ...>。
DOM object
瀏覽器解析文件後在記憶體中建立的物件。
HTMLButtonElement
按鈕 DOM object 對程式暴露的介面／型別名稱。

2. #daily-schedule 是 selector

daily-schedule 是 HTML 作者替 element 指定的 id；前面的 # 是 selector 語法，表示「找 id 等於這個值的 element」。

<button id="daily-schedule">每日生產排程</button>

const button = document.querySelector('#daily-schedule')
                                      ↑
                         找 id="daily-schedule"

3. document 與 DOM tree

Document
└── html
    └── body
        └── main
            └── button id="daily-schedule"

document 是頁面 JavaScript 取得目前 HTML document 所對應 Document object 的入口。因此 document.querySelector(...) 是從目前 Document 的 DOM tree 中找符合 selector 的 DOM object。

4. Click 發生後，是誰建立 Event？

button 不是 Event 的製造者。簡化後的因果鏈是：

手指 / 滑鼠輸入
      ↓ browser receives input（瀏覽器收到輸入）
瀏覽器取得輸入位置
      ↓ hit testing（判斷位置落在哪個畫面元素）
瀏覽器判定該位置對應 button
      ↓ sets target（指定本次事件目標）
button 成為這次 click 的 target
      ↓ creates（建立）
瀏覽器建立 click Event object
event.target 是「這次 Event 最初指向哪個 DOM object」，不是「哪個 DOM object 創造了 Event」。

5. 為什麼知道 target 後還需要 dispatch？

知道 target = button 只回答「這次 click 指向誰」。瀏覽器接著還要決定：

這次 Event 應該讓 event path 上哪些已登記的 listener 執行，而且按照什麼順序執行？

這個處理過程叫做 event dispatch（事件分派）。

6. Listener 是 Event 發生以前先登記

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

document、button、main 這類可以登記 event listener 的物件，都具有 EventTarget 的能力。這裡先理解成：

可以讓程式登記 listener，並在 Event dispatch 經過它時讓瀏覽器呼叫相符 callback 的物件。

addEventListener() 只是在 document 上先保存：

- type: "click"
- callback: handleClick
- capture: false（預設）

它不會預先建立未來的 click Event。

7. Phase：同一次 dispatch 現在走到哪一段

phase（階段）不是另一個 Event，也不是重新觸發 click。它只是描述：

同一個 Event 正在被 dispatch 時，現在走到整條處理流程的哪一段？

假設 target 已經確定是 button：

document
└── html
    └── body
        └── main
            └── button  ← event.target 已確定
Capture phase（捕獲階段）｜外 → 內document → html → body → main → button
target/path 已經知道了。瀏覽器朝 target 處理路徑；ancestor 上符合 event type 且 capture: true 的 listener 會在這一趟被呼叫。
Target phase（目標階段）Event 抵達 button。button 自己符合條件的 listeners 在 target 上被處理。
Bubble phase（冒泡階段）｜target 的 parent → 更外層 ancestormain → body → html → document
如果 Event 允許 bubbling，瀏覽器接著處理 target 的 ancestors 上符合條件的 non-capture listeners。
Bubble 不會把 target 再處理一次。button 已經在 Target phase 被處理；Bubble 接下來處理的是 button 的 ancestors，例如 main、body、document。

8. capture: true / false 選的是 listener 的時機

// ancestor 想在 target 前收到
 document.addEventListener('click', handleClick, { capture: true })

// capture: false（預設）
 document.addEventListener('click', handleClick)

精確地說，是 capture: false 為預設，不是「Bubble 是預設」。如果 listener 所在的物件本身就是 event.target，它是在 Target phase 執行，不會因為 capture: false 就多跑一次 Bubble。

9. Bubble 不等於 handler 重複執行

假設：

card
└── deleteButton
card.addEventListener('click', openDetail)
deleteButton.addEventListener('click', deleteItem)

如果直接點 card：

event.target = card

Target: card
        → openDetail() 執行一次

Bubble: card 的 parent → 更外層 ancestors
        → 不會回頭再執行 card 的 openDetail()

如果點 deleteButton：

event.target = deleteButton

Target: deleteButton
        → deleteItem()

Bubble: card
        → openDetail()
這裡不是 deleteItem() 被重複執行。是同一個 click Event 先讓 target 上的 listener 執行，再讓 ancestor 上另一個 listener 有機會執行。

10. 什麼時候選 Capture？什麼時候選預設的 non-capture？

想在 descendant handler 前先觀察
選 capture: true。例如 document-level telemetry 希望盡量早看到 click。
一般 target 自己處理 click
通常使用預設 capture: false；listener 在 target 上只執行一次。
Ancestor 統一處理 descendants
Capture 與 Bubble 都能做到；差別主要是 ancestor 想在 target 前收到，還是 target 後收到。
Event delegation
常見做法是 ancestor 使用預設 non-capture listener，等 descendant click bubble 上來，再用 event.target 判斷來源。

11. Event delegation 為什麼有用？

假設一個清單有很多 button：

list
├── button A
├── button B
├── button C
└── button D

不一定要每顆都各寫一個 listener：

list.addEventListener('click', event => {
  console.log(event.target)
})

因為 click 會 bubble，A/B/C/D 的 click 都可以抵達 list。這種讓 ancestor 統一接 descendants event 的方式叫 event delegation（事件委派）。

12. stopPropagation()：什麼時候真的要截斷 Event？

stopPropagation() 的意思不是程式 crash、server 掛掉或網路中斷。它只是在這一次 dispatch 中告訴瀏覽器：

這個 Event 從現在開始，不要再繼續傳到 event path 上後面的 DOM objects。

例如 card 點擊會打開詳細頁，但 card 裡有一顆刪除按鈕：

card                         ← click → openDetail()
└── deleteButton             ← click → deleteItem()

如果產品需求是「點 Delete 只刪除，不要同時讓 card 的 click handler 也處理」，可以：

deleteButton.addEventListener('click', event => {
  event.stopPropagation()
  deleteItem()
})
Target: deleteButton
        → stopPropagation()
        → deleteItem()

Bubble 往 card 的路徑被截斷
        X
card    → openDetail() 不會因這次 click 被呼叫
stopPropagation() 不是 click 的常態「防重複」工具。正常 bubbling 不會讓 target 的同一個 listener 自己重跑。只有你真的不希望更外層 ancestors 收到這次 Event 時，才有理由截斷 propagation。

有時也可以不截斷 Event，而讓 ancestor 自己判斷是否處理：

card.addEventListener('click', event => {
  if (event.target.closest('.delete-button')) {
    return
  }

  openDetail()
})

這樣 click 還能繼續往更外層傳，例如 document-level telemetry 仍然有機會收到。

13. event.bubbles 和 stopPropagation() 不是同一個開關

event.bubbles 是 Event object 的 read-only boolean 性質：

event.bubbles  // true 或 false
bubbles === true
這個 Event 的規則允許 target 之後繼續進入 ancestor bubbling flow。
stopPropagation()
對這一次正在進行的 dispatch 設下停止傳遞的命令；它不會把 bubbles 改成 false。
button.addEventListener('click', event => {
  console.log(event.bubbles) // true

  event.stopPropagation()

  console.log(event.bubbles) // 仍然是 true
})

所以心智模型是：

bubbles = true
= 這個 Event 本來具備往 ancestors bubble 的能力

stopPropagation()
= 但這一次 dispatch 走到這裡就停止繼續傳

對 browser 產生的 click Event，你讀取它的 bubbles；程式不會靠 stopPropagation() 去修改這個 boolean。建立 synthetic Event 時，可以在建立時指定是否 bubbles，例如：

new Event('demo', { bubbles: false })

14. 為什麼 document.addEventListener('click', ...) 能收到 button click？

在 document 這個 DOM EventTarget 上登記一個 click listener。未來如果某次 click 的 event path 在 bubbling 階段經過 document，請瀏覽器呼叫 handleClick(event)。

如果這次 Event 在抵達 document 前被 stopPropagation() 截斷，document 的 Bubble listener 就收不到；若 document 使用 Capture listener，而且停止發生在更內層，document Capture listener 已經更早執行過。

15. event.target 和 event.currentTarget

你點 button
    ↓
event.target = button

同一個 Event bubble 到 document
    ↓
document 上的 listener 正在執行
    ↓
event.currentTarget = document
event.target
這次 Event 最初指向的 DOM object。
event.currentTarget
目前正在執行的 listener 所屬 EventTarget。

16. 最後才看 event.eventPhase

現在 phase 已經有具體意義了，event.eventPhase 只是 browser API 把「目前走到哪一段」暴露成程式可以讀的值：

NONE (0)
Event 現在沒有處於 dispatch 中。
CAPTURING_PHASE (1)
目前正在 target 之前的 Capture 階段。
AT_TARGET (2)
目前正在 event.target 本身。
BUBBLING_PHASE (3)
目前正在 target 之後的 ancestor Bubble 階段。
不用背 1 / 2 / 3。先理解 Capture / Target / Bubble；數字只是 API encoding。

17. Trace 現在只需要知道這個邊界

目前正在建立的是 browser Event mental model。Tracing 的 Span、parent/child、active context、context propagation 會在後面的 Faro / OTel 主線正式學，不需要在這裡先展開。

現在只保留一個必要 bridge：

Capture 與 Bubble 會改變 telemetry listener「什麼時候看到這次 click」。如果之後要追「click 引發了哪些 downstream work」，較早或較晚觀察可能影響 instrumentation 設計；但那是 tracing 章節要解的問題，不是理解 DOM Event 的必要前提。

Recap

  • DOM object 由 browser 建立與管理；JavaScript 透過 DOM API 取得 reference。
  • browser 收到 click input、判定 target、建立 Event，再開始 dispatch。
  • Capture / Target / Bubble 是同一次 dispatch 的不同階段。
  • Target listener 在 Target phase 被處理；Bubble 不會讓同一個 target listener 再執行一次。
  • Bubble 是 target 處理後，讓 target 的 ancestors 有機會收到同一個 Event。
  • Capture 與 Bubble 都能讓 ancestor 統一看到 descendant click，差別主要在 listener 的執行時機。
  • event delegation 常利用 bubbling 讓 ancestor 統一處理 descendants。
  • stopPropagation() 是截斷這一次 Event 的後續傳遞，不是防止 target handler 自己重複執行。
  • event.bubbles 是 read-only Event 性質；stopPropagation() 不會把它改成 false。
  • event.target 是最初 target；event.currentTarget 是目前 listener 所在的 EventTarget。
  • event.eventPhase 只是把目前 Capture / Target / Bubble 狀態暴露成 API 值。
  • Tracing 細節目前延後；這裡只需要知道 Capture / Bubble 會改變 telemetry 觀察 click 的時機。
