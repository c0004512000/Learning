DOM、document 與事件分派

把抽象名詞還原成瀏覽器記憶體裡的物件與實際呼叫流程

先抓住一句話： JavaScript 並不是不停搜尋「有沒有 click」。瀏覽器負責接收輸入、決定事件目標、建立 event、分派（dispatch）event；JavaScript 只是先把 callback 登記好，等瀏覽器在分派過程中呼叫它。

1. DOM 具體來說是什麼？

假設頁面 HTML 是：

<html>
  <body>
    <main>
      <button id="schedule">每日生產排程</button>
    </main>
  </body>
</html>

HTML 是文字。瀏覽器解析後，會在記憶體中建立一組彼此有父子關係的 DOM 物件：

Document 物件代表目前整份網頁文件
HTMLHtmlElement 物件對應 <html>
HTMLBodyElement 物件對應 <body>
HTMLElement 物件對應 <main>
HTMLButtonElement 物件對應 <button id="schedule">
所以 DOM 不是畫面，也不是 HTML 字串。 它是瀏覽器建立的可操作物件，以及這些物件之間的 tree 關係。

2. document 是什麼？

每一份 HTML document 都由一個 Document 物件表示。頁面 JavaScript 中的全域變數 document，就是取得「目前這一頁的 Document 物件」的入口。

document
└── html
    └── body
        └── main
            └── button#schedule
console.log(document)
console.log(document.body)
const button = document.querySelector('#schedule')

document.querySelector(...) 不是去搜尋 HTML 原始字串，而是在目前 DOM tree 中找對應的 DOM 物件。

3. addEventListener() 記住的是什麼？

function handleClick(event) {
  console.log(event.target)
}

document.addEventListener('click', handleClick)

這一步不是開始 polling。它比較接近把以下設定登記到 document 這個 EventTarget：

listener registration
- type: "click"
- callback: handleClick
- capture: false

真正長期被保存的是這個 listener registration。使用者之後每一次 click 所產生的 Event object，並不會自動成為永久歷史紀錄。

4. 點擊如何一路變成 JavaScript 執行？

  1. 使用者輸入發生。 滑鼠、觸控或其他 pointing device 產生平台輸入。
  2. 瀏覽器收到輸入。 不是 JavaScript 主動去抓。
  3. 瀏覽器決定目標。 例如 DOM 中的 button#schedule。
  4. 瀏覽器建立 Event object。 其中包含 type、target 等資料。
  5. 瀏覽器分派（dispatch）event。 它依 DOM tree 建立事件路徑，檢查路徑上的 EventTarget。
  6. 遇到相符 listener 時，瀏覽器呼叫 callback。 本次 Event object 被當作參數傳入。

5. 所以 JS 到底怎麼「拿到」event？

function handleClick(event) {
  // event 不是這個函式自己建立的
  // 是瀏覽器呼叫 handleClick 時傳進來的
  console.log(event.type)
  console.log(event.target)
}

document.addEventListener('click', handleClick)
你的 JS：先登記 handleClick
      ↓
使用者：點 button
      ↓
瀏覽器：建立 click Event
      ↓
瀏覽器：分派 event
      ↓
瀏覽器：在路徑上找到相符 listener
      ↓
瀏覽器：handleClick(event)
      ↓
你的 JS：開始執行 handleClick 裡的程式
精準說法： 不要說「JS 抓到 event」。應該說「JavaScript 先註冊 callback；瀏覽器分派事件時主動呼叫 callback，並把 Event object 傳進去」。

6. 為什麼 listener 掛在 document 也能知道 button 被點？

document
└── html
    └── body
        └── main
            └── button   ← event.target

簡化後，一次 click 會沿事件路徑經歷：

Capture： document → html → body → main → button
Target：                                      button
Bubble：  button → main → body → html → document
欄位意思
event.target最初真正被點到的 DOM 物件。
event.currentTarget目前正在執行哪一個 EventTarget 上的 listener。
event.type事件類型，例如 click。
event.eventPhase目前位於 capture、target 或 bubble 哪個階段。

7. 「dispatch」在這裡怎麼翻？

這個情境下建議翻成分派事件。它不是把資料送上網路，而是瀏覽器依事件路徑，把這個 event 交給應該經過的 EventTarget，並呼叫符合條件的 listener callback。

8. Event 有沒有被「記錄」？

東西會自動成為永久紀錄嗎？
listener registration它是設定，會持續存在到被移除或相關物件生命週期結束。
本次 browser Event object不會自動成為你的 telemetry history。
Faro / analytics telemetry只有監控程式另外讀取、轉換、送出，backend 再儲存後，才成為可查詢紀錄。
 
瀏覽器原生世界
使用者 click
  → Browser Event
  → DOM event dispatch
  → listener callback(event)

                ↓ Faro 從這裡接手

監控資料世界
callback 讀取 event.target / 其他資訊
  → 建立 Faro telemetry
  → transport
  → Alloy / Collector / backend
  → 儲存與查詢

Recap

  • DOM 是瀏覽器建立的文件物件樹。
  • document 是目前 HTML 文件的 Document 物件。
  • addEventListener() 登記的是 event type、callback 與 options。
  • JavaScript 不需要 polling；瀏覽器分派 event 時會主動呼叫 callback。
  • callback 的 event 參數，是瀏覽器呼叫函式時傳入的本次 Event object。
  • browser event 不等於永久 telemetry；Faro 需要另外讀取、轉換、送出與儲存。
