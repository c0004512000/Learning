範圍
不需要精通 DevTools。你需要能判斷：現在要查的是頁面結構、程式當下的值、callback 執行，還是 HTTP request；選對地方後，能讀出與 Faro 有關的證據。

1. 同一個頁面，四種觀察角度

Panel 是 DevTools 中的一個工作區；每個工作區有自己的主要資料與工具。它們不是四份互相獨立的應用程式，而是從不同角度觀察同一個 Browser runtime。

2. 先認識外框，不依賴固定座標

在 Chrome 按 F12 或 Ctrl + Shift + I 開啟 DevTools。主要工作區名稱通常在 tab strip；窄視窗可能把部分名稱收進 »。DevTools 可停靠右側、底部或獨立視窗，因此不要記「永遠在右上角」，要認名稱與區域用途。

Drawer 是主要工作區下方可展開的輔助區域；按 Esc 可切換顯示。Console 可以在 Drawer 出現，所以你可能同時看到 Elements 的 DOM 樹與底下的 Console；這仍是同一個頁面的觀察工具。

Panel 與 tab 層級不同：Network 是工作區；Headers、Payload、Response 是「選定某筆 request 後」的細節 tabs。還沒選 request 時找不到 Payload，不代表 Faro 沒有 payload。

3. Elements：目前頁面的結構

DOM 樹是 Browser 當下管理的頁面結構，外觀像 HTML，但不等於 repository 原始 template。展開父節點可以看到 children；attributes 則跟在 element tag 上。右側或下方常有 Styles／Computed，用來看 CSS；Faro click Lab 不需要先深入 CSS。

  1. 用 Element Picker（Ctrl + Shift + C）在頁面點選想觀察的 UI。
  2. 在 DOM 樹確認選中的 tag；可能是 inner span，不是外層 button。
  3. 沿 parent 展開／查看，找到持有 data-link-name 的 ancestor。

Breadcrumb 是選定 element 的 ancestor 路徑提示，幫你從 inner node 回到外層；它不是 network request 流程。

Faro 問題：「這顆 UI 現在有可擷取的值嗎？」→ Elements。查到值後，仍要去 Sources 證明 extraction 執行、去 Network 比對 payload。

4. Console：查值與查看訊息

Console 有兩種主要內容：程式／Browser 輸出的訊息，以及你輸入 expression 後得到的結果。它不是自動記錄所有函式執行的完整流水帳。

在 Elements 選好 node 後，DevTools 的 $0 代表最近選定的 DOM node。這是 DevTools helper，不是 Foreman 自己定義的變數。可以查：

$0.tagName
$0.closest('[data-link-name]')?.getAttribute('data-link-name')
getEventListeners(document).click

getEventListeners 也是 DevTools helper，不是網站 JavaScript everywhere 都能使用的 API。它列出 registration；結果若是 Zone.js wrapper，不能直接說 Faro callback 執行過。

安全習慣
Console 可執行會改變頁面狀態的 JavaScript。此 Lab 先用唯讀查詢；不要貼不理解的指令，也不要讀出 localStorage、cookie 或 authentication material。分享 error 時同樣檢查 URL 與內容是否帶敏感值。

Faro 問題：「目前查到的 attribute 是什麼？是否有 CORS error？」→ Console。但沒有 error 可能只是沒有訊息或尚未記錄，不代表資料流成功。

5. Sources：程式檔與執行現場

Sources 常分成三區：檔案 navigator（選載入的 script）、code editor（看程式碼）、debugger sidebar（breakpoint 與停點資訊）。部署可能顯示 bundle，例如 main.js；source map 若可用，才可能映射回原始檔名。沒有原始檔名不等於函式沒有執行。

Breakpoint 是要求 debugger 在指定條件暫停 JavaScript 的工具。Event Listener Breakpoint 對 click 暫停時，先看：

  • Paused reason：為什麼停下來。
  • 目前 source line：下一步執行位置與所在 script。
  • Call Stack：當下仍在執行中的函式呼叫鏈，不是所有歷史呼叫。
  • Scope：選定 frame 當下可見的 local／其他變數；可能包含個資，不能整區直接分享。

Resume 繼續執行；Step into 嘗試進入下一個函式呼叫；Step over 跑過目前步驟而不逐步進入子呼叫。它們不是用來讓 request 重送的按鈕。

Faro 問題：「click 真的進入 ClickInstrumentation.handleClick 嗎？」→ Sources。看到 Zone.js 時繼續找 wrapped callback；只有找到可辨識的 runtime frame，才作 execution claim。Debugging 完要 Resume 並移除 breakpoint，避免下一次操作一直暫停。

6. Network：HTTP 往返紀錄

一列通常是一筆 request，不是一個 click。一次 click 可帶來 application request、resource telemetry、tracing telemetry 與 click telemetry；preflight 也是另一列。先看 Method + Type + Status，再選細節 tab。

  1. 操作前先開 Network，確認 recording 啟用；它不會自動補回所有開啟前的 request。
  2. 需要跨 navigation 保留紀錄時啟用 Preserve log；Clear 用來避免把上次操作混入。
  3. Filter 輸入 alloy 是縮小顯示範圍，不會停止其他 request。看不到時先確認 filter 是否過窄。
  4. 選一列後：Headers 看 General／request headers／response headers；Payload 看送出的 body；Response 看收到的 body；Timing 看耗時分段。

Initiator 提供建立 request 的呼叫線索；Waterfall 提供各 request 的時間排列與耗時。它們可以協助定位順序與延遲，不能取代 click payload 的內容 correlation。

跨 origin POST 需要 preflight 時：Browser 先用 OPTIONS 問 permission，允許後才繼續真正 request。preflight 可能被快取，所以每次 click 不一定都出現新的 OPTIONS；沒有 OPTIONS 不可直接判成 CORS 失敗。

OPTIONS → Headers：Browser 要求什麼，receiver 允許什麼？
POST → General：URL / Method / Status
     → Payload：click + 相同 link_name
     → Response：receiver 回什麼

202 Accepted ≠ Collector / storage 全部成功

Faro 問題：「哪一筆 POST 含剛才的 click？」→ Network Payload。問題：「callback 有沒有執行？」仍回 Sources，而不是拿一列 Network 當完整 execution proof。

Self-check：先選工作區

要證明 click 當下真的進入 Faro handleClick，先去哪個工作區？

Recap

  • Elements：目前頁面結構；找 target 與 tracked ancestor。
  • Console：查 runtime 值、registration 與錯誤；不是完整 execution 記錄。
  • Sources：載入的程式與暫停現場；證明 Faro callback execution。
  • Network：request 與 response；用 payload 做 correlation，用 status 設 proof limit。

遇到不理解的畫面，告訴 agent「我要證明什麼」與你看到的區域，不必先精通所有工具。
