W3C traceparent 快速查表

給 Lesson 7、Lesson 8 與 troubleshooting 重複查閱的 propagation reference

一句話版本
traceparent 不是把 span 本身送給 backend；它只是把「這個 request 屬於哪條 trace、呼叫端目前是哪個 operation」序列化進 HTTP header，讓接收端有機會建立正確的 parent/child relationship。

1. 格式

traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
             │  │                                │                │
             │  │                                │                └─ trace-flags
             │  │                                └─ parent-id
             │  └─ trace-id
             └─ version
Fieldversion 00 長度真正代表什麼
version2 hex charsheader format version；目前常見是 00。
trace-id32 hex chars整條 distributed trace 的 ID。
parent-id16 hex chars呼叫端目前 operation/request 的 ID；常見 tracing system 中就是 caller span ID。
trace-flags2 hex charstracing flags；最低 bit 可表示 sampled hint。

Normative source: W3C Trace Context §3.2。

2. 最容易看錯的地方：parent-id 不是 backend 的 span ID

判讀規則
同一條 trace 的核心是 traceId 相同；parent/child 關係則靠「child span 記住 caller span ID」建立。backend 不應把 caller 的 parent-id 直接拿來當自己的 span ID。

3. Propagation 與 telemetry export 是兩件事

Business HTTP path
Browser ── traceparent ──> Backend

Telemetry path A
Browser span ── Faro/OTLP export ──> Collector / Tempo

Telemetry path B
Backend span ── OTLP export ──────> Collector / Tempo

traceparent 只負責把 context 帶過 process boundary；它不是 span payload，也不代表 span 已經成功寫入 Tempo。

4. 沒有 header 時會怎樣？

HTTP request 本身仍然可能完全成功；只是 tracing system 沒有 incoming parent context 時，通常會為這個 request 建立新的 trace context。

有 propagation：
Browser trace T ──> Backend trace T

沒有 propagation：
Browser trace T     Backend trace U
                    ↑ request 功能仍可能成功

所以「API 200 OK」與「前後端 trace 有串起來」是兩個不同 claim。

backendUrls 不是 Alloy receiver URL。它描述的是哪些 backend API URL 可以參與 trace-context propagation。

Internal evidence: faro-click-tracking contract。Faro v2.9.0 implementation basis: external source pointers。

6. Cross-origin 時再多一個 Browser boundary

如果 Browser 與 backend 不同 origin，request 想帶 traceparent 時要同時滿足 CORS policy。backend 沒允許該 header 時，Browser 可能在 preflight 階段就不讓真正的 business request 送出。

7. Debug 時要分三個 claim

Claim最低需要的 evidence
Frontend 有把 context 傳出去Browser business request headers 裡看到具體 traceparent。
Backend 有加入同一條 tracebackend server span 的 trace ID / parent relationship 能對上 incoming context。
Tempo 顯示完整前後端 treefrontend 與 backend span telemetry 都成功 export，並在 trace backend 以同 trace ID 可見。
Evidence boundary
目前 Jeter evidence 已證明相關 configuration 存在，但尚未保存一筆 concrete Browser header + backend parent + Tempo trace 的完整 runtime chain。因此不要把「設定看起來正確」寫成「runtime 已成功 join」。
