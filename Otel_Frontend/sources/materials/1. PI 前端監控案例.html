解決方案

建立一個追蹤 click 的 package

核心功能

將「點擊監聽」、「裝置資訊擷取」與「使用者身分」封裝成一個共用的 package.

底層使用 Faro Web SDK 的 initializeFaro(), 對外開放 initFaro(), 提供宿主專案不需要修改既有的 onClick 程式碼。

裝置辨別方式

  • 採用 maxTouchPoints 搭配 pointerType , maxTouchPoints 是靜態數值, maxTouchPoints=0 → 無觸控功能, maxTouchPoints>0 → 有觸控功能
  • 需求中有提到, 平板接上滑鼠, 希望被認定為筆電, 若只採用 maxTouchPoints 無法得到預期的結果, 因此在 click event 發生的同時, 會記錄當下使用的點擊裝置, 就是 pointerType (mouse/pen/touch), 當 maxTouchPoints > 0 → 判斷為平板, 加上 pointerType=mouse, 判斷為 desktop.
    • 若改成只採用 pointerType, 當 user 使用鍵盤觸發, ex. Tab 切換到元素後按 Enter or 空白鍵, pointerType="" , 是空字串, 因此需要 maxTouchPoint 做為備援
    • 目前套件在偵測裝置的功能上, 將 maxTouchPoint+pointerType 綁定在一起, 因此若未來其他宿主專案想要開啟偵測裝置的功能, 但並沒有平板接上滑鼠, 希望被認定為筆電的特殊需求, 會因為 pointerType 而影響到最終的裝置判斷結果
    • 預期下一版本: 將是否開啟 pointerType 獨立成一個功能, host 可以自由選擇是否要啟動 pointerType
  • 將裝置辨識的結果儲存到自定義的device_type 變數, 該變數代表裝置類型, 並帶入 Faro metas 內, 並且每個 signal (log/trace/exception/event/measurement), 都會取得當下最新的裝置類型

身分辨別方式

  • foreman-assistant 已經可以在連結被點擊的當下, 記錄使用者的工號, 為了讓 faro 可以將使用者身分傳送到 alloy, 提供 host 可以自定義 callback function 去抓取 data.
  • 使用者不需要知道如何呼叫 faro.api , 將 faro.api 的邏輯都包裝在 package
  • host 需要自行撰寫 callback function 取得 user info, 並且回傳符合 FaroUserInfo interface 的 type.
    可以參考 foreman-assistant 的實際程式碼 foreman-assistant getUser callback function
  • getUser: (): FaroUserInfo | null => {
    const employee = JSON.parse(
      localStorage.getItem(EMPLOYEE_STORAGE_KEY) ?? 'null'
    ) as Employee | null;
    if (!employee) {
      return null;
    }
    return {
      id: employee.empID,
      username: employee.ename,
    };
  },

  • 將 user info 存進 metas, 併入之後所有的 signal (ex. log/trace/exception/event/measurement) 都會帶著該 user info.
    可以在 payload 的 meta.user 查看 user 的 id & username, 要呈現哪些 user info 可以由宿主專案自行定義, 但必須要有 id
    詳細可參考 user info parameters
  • export interface FaroUserInfo {
  id: string; // id 必填
  username?: string;
  email?: string;
  attributes?: Record<string, string>; // 可自定義任何想針對 user 記錄的數據
}

連結辨別方式

  • foreman-assistant 已經具備紀錄點擊的連結名稱, , 但會因為語系的不同, 會將同一個連結當作不同的連結紀錄, 因此套件更改成由 host 自行定義 attribute name (ex. data-link-name), 套件只會抓取 host 定義好的 attribute name.
  • faro-click-tracking 會將自定義的 attribute name 的 data-* 前綴刪除並且將 "-" 改成 "_" ex. data-link-name → link_name 參考修改 payload key

繁體中文 vs. English

  • 在繁體中文和 English, 同一個連結, 在繁體中文是 "每日生產排程", English 是 "Auto-Scheduling", 以資料面來說, 這兩者是不同的資料, 但實際上其實是相同的連結, 因此為了解決此問題, 會去抓取 host 自定義的 attribute name, 由 host 自行帶入 value, 解決不同語系的問題。

導入方式

安裝依賴

npm install @sre2/faro-click-tracking

在前端主程式呼叫一次 initFaro(), 帶入必要的 config

  • 這是實際運行在 foreman-assistant 的程式碼, 可以參照 foreman-assistant production
import { initFaro, type FaroUserInfo } from '@sre2/faro-click-tracking';

initFaro({
  environment: 'tw-prod', // 指定部署環境
  app: {
    name: 'foreman-assistant', // 必填, 需要知道數據從哪一個服務傳送
    version: environment.appVersion, // 可選, 自行決定, 可以根據 release 版本
  },
  getUser: (): FaroUserInfo | null => { // 選填, 需要紀錄使用者數據就需要自行寫 callback function
    const employee = JSON.parse(
      localStorage.getItem(EMPLOYEE_STORAGE_KEY) ?? 'null'
    ) as Employee | null;
    if (!employee) {
      return null;
    }
    return {
      id: employee.empID,
      username: employee.ename,
    };
  },
  trackAttributes: ['data-link-name'], // 選填, 自定義點擊事件追蹤的 attribute, 是一個陣列, 可以支援多個 attribute
  enableDeviceTypeDetection: true // 選填, 是否開啟裝置辨識
});

attributes 說明

 environment (必填)

  • 目前支援 tw-prod, tw-stage, tw-test, tw-uat, tw-exp, th-test, 可以查看對應的 domain enviroment & domain mapping
  • 存放在 meta

 app

  • name (必填): 需要紀錄是哪一個服務的數據, 所以要設定 service name
  • version (選填): 可以自由定義, 也可以不要填
  • 存放在 meta

 getUser (選填)

  • User info 提供兩種方式, 推薦使用 callback function 的方式抓取 user info
  • 另一種方式為手動埋點, 可以參考 手動埋點紀錄 User info
  • 存放在 meta 

 trackAttributes (選填)

  • 是一個陣列, 可以存放多個 attributes
  • 除了在 initFaro 設定, 還需要到 html 想追蹤的元素添加對應的 attributes
  • 範例可以參照 如何設定 trackAttributes
  • 存放在 Event, 透過 pushEvent, 所以會在 otel.receiver.faro 添加 event_data_ prefix.  請看官方來源

enableDeviceTypeDetection (選填)

  • 是否要追蹤操作系統的裝置, 目前辨識的方法是使用 maxTouchPoints + pointerType, 會將平板+滑鼠辨識成「desktop」
  • 這是未來需要做的更彈性的功能, 要將是否動態辨識裝置功能設定為 Optional, 也就是是否要使用 pointerType 辨識裝置, 原因如下:
    • pointerType: 屬於動態數值, 在使用者操作的當下才會辨識 (pen/mouse/touch)
    • maxTouchPoints : 靜態數值, 會在使用者進入系統的當下就辨識完成
  • 存放在 meta
