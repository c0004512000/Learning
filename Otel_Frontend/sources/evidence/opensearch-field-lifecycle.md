## Verified findings

### Upstream and package layers

- Faro translator `pkg/translator/faro/logs_to_faro.go` converts Faro log/event payload data into OTel log attributes and applies the `event_data_` naming convention. The translator is the source of that prefix; it is not generated by the Foreman templates.
- Package `ClickInstrumentation` first transforms `data-link-name` to payload key `link_name` (and `data-panel-topic` to `panel_topic`) before calling `pushEvent()`. Thus the package normalization and translator prefix are two separate layers.

### Collector transform and export

- Stage runtime ConfigMap’s `transform/opensearch_body` and production’s `transform/parse-body-to-attributes` execute `merge_maps(attributes, ParseKeyValue(body), "upsert")` for string bodies before their OpenSearch exporters. This is where key/value body content becomes searchable log attributes in the Garmin pipeline.
- Stage exporter configuration uses dataset `foreman-assistant`, namespace `tw-stage`, mapping `ss4o`; production uses the same dataset/mapping but namespace `tw-prod` while targeting the stage OpenSearch endpoint. Filter processors restrict the Foreman pipeline by service name before export.

### Actual indices and mappings

- Stage OpenSearch cluster `TW-PIDE-OpenSearch-STAGE` currently contains:
  - `ss4o_logs-foreman-assistant-tw-stage` (green/open)
  - `ss4o_logs-foreman-assistant-tw-prod` (green/open)
- Production OpenSearch cluster `TW-PIDE-OpenSearch-PROD` is green (15 nodes) but the bounded `_cat/indices/ss4o_logs-foreman-assistant*` query returned `[]`; no matching Foreman index was found there at verification time.
- Stage mapping exposes `attributes.event_data_link_name` and an `attributes.event_data` `flat_object`, in addition to fields such as `attributes.kind`, `attributes.event_name`, `attributes.device_type`, `attributes.user_id`, `attributes.session_id`, `traceID`/`spanID` and top-level `traceId`/`spanId`.
- Production’s corresponding index on the stage cluster exposes `attributes.event_data_link_name` and the same principal event/device/user/trace field family; mapping shape is not identical to stage’s `flat_object` entry, so lessons must not claim mappings are byte-for-byte identical.
- Read-only field queries observed click documents with `event_name=click` and `attributes.event_data_link_name` (examples such as `DailySchedule`/`HourlyProductionUnits`; no user values copied). This confirms field presence, not a guarantee of delivery for every click.

## Environment routing truth

```
Faro click payload
  → Alloy Faro receiver
  → OTLP log
  → Collector body parser / filter
  → attributes.event_data_*
  → OpenSearch exporter
  → ss4o_logs-foreman-assistant-{tw-stage|tw-prod}
```

For the current production Collector, the final index is physically on the **stage** OpenSearch cluster because its exporter endpoint is stage. The `tw-prod` namespace in the index name is a logical routing label, not proof of a production-cluster index.
