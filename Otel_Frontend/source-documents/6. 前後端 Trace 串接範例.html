Faro receiver 設定

  • 需要設定 cors policy, origins & headers 都需要設定
  • 可以參考 tw-stage alloy helm chart value

Alloy Server (Current Version)

  • 可以看到不論是 receiver, processor, exporter, 都是呼叫 otelcol, 因此 otel collecotor 是支援該接收 faro 的, 只是當前 tw-prod, tw-stage 的版本不支援, 各環境版本請參考 升級 Otel Stack
configMap:
	otelcol.receiver.faro "frontend" {
      endpoint = "0.0.0.0:12347"
      
      cors {
          allowed_origins = ["*"]
          allowed_headers = ["traceparent"]
      }
      
      max_request_body_size = "10MiB"
    
      output {
        logs = [otelcol.processor.batch.default.input]          
        traces = [otelcol.processor.batch.default.input]
      }
    }

    otelcol.processor.batch "default" {
      output {
        logs = [otelcol.exporter.otlp.collector.input]
        traces = [otelcol.exporter.otlp.collector.input]
      }
    }
    
    otelcol.exporter.otlp "collector" { # 將前端可觀測性數據 export 到現有的 open-telemetry collector
      client {
        endpoint = "opentelemetry-collector.open-telemetry.svc.cluster.local:4317"
        tls {
          insecure = true
        }
      }
    }

OTel Collector(升級到 v0.133.0+ 後, 可以參考該 config)

config:
  receivers:
    faro: # 接收前端可觀測性數據
      endpoint: 0.0.0.0:12347
      cors:
        allowed_origins:
          - "*"
        allowed_headers:
          - "*"
    otlp: # 接收後端可觀測性數據
      protocols:
        grpc:
          endpoint: 0.0.0.0:4317
        http:
          endpoint: 0.0.0.0:4318


Frontend 設定

  1. 可以到 Jeter-Faro-Trace-Demo-Frontend 測試前後端 Trace 串接
  2. Trace-前端程式碼範例
initFaro({
  // 環境名稱於執行期由 window.__APP_CONFIG__ 決定（見 authState.ts），
  // 套件依此解析對應的 Alloy Faro receiver 端點。
  environment: FARO_ENVIRONMENT,
  app: {
    name: 'jeter-faro-trace-demo-frontend',
    version: '1.0.0',
  },
  // 對後端網域的 fetch/XHR 請求注入 W3C traceparent header
  backendUrls: [new RegExp(BACKEND_URL)],
  // 全域點擊監聽只追蹤標記了 data-link-name 的元素，轉換為 event_data_link_name
  trackAttributes: ['data-link-name'],
  // 開啟裝置類型偵測，裝置類型改以 Faro meta 隨每一種 signal 送出
  enableDeviceTypeDetection: true,
  // 讀取目前登入使用者身分，套件會於 click/visibilitychange/storage 事件時自動比對並同步
  getUser: () => {
    const id = getCurrentUserId()
    return id ? { id } : null
  },
})
initFaro({
  ...,
  backendUrls: [ // 前端只需要設定要串接的後端 URL 即可將 traceparent header 傳遞給後端
    'https://api.example.com',        // 字串：完整比對此網域
    /^https:\/\/.*\.example\.com$/,   // 正規表示式：比對所有 example.com 子網域
  ],
});

Backend 設定

  • backend 也需要允許 traceparent header
  • Trace-後端程式碼範例
// ---------- CORS：允許前端來源與 trace header ----------
builder.Services.AddCors(options =>
{
    options.AddPolicy(CorsPolicy, policy =>
        policy.WithOrigins(corsOrigins)
              .AllowAnyMethod()
              .AllowAnyHeader());
});
