# Session 02 — Why Containerization? | Verified source basis

Date: 2026-11-22 (Asia/Taipei)

## Scope
Docker Fundamentals Session 02: 以部署痛點 → 相依衝突／環境漂移／Artifact 追溯 → CI 建構一次並交付 Image → Tag/Digest 與環境邊界作為教學順序。這是根據 Mission 和 First-principles 課程需求整理的教學證據，不表示 Garmin 的 Production Workflow 已實測或審計。

## Verified Docker official sources

1. [What is a container?](https://docs.docker.com/learn/content/what-is-a-container/) (verified/published 2026-10-21)
   - Developer、CI、Production 的 Runtime 與套件版本差異會帶來失敗風險。
   - Container 封裝程式、必要 user-space 執行內容，使用隔離的執行環境。
   - 使用同一 Image 有助固定封裝內容，並不等於所有外部環境完全相同。

2. [Share your image on Docker Hub](https://docs.docker.com/learn/content/share-your-image-on-docker-hub/) (verified/published 2026-10-21)
   - Registry 用來保存並按名稱分發 Image，可由其他執行環境 Pull。
   - Image Tags 可能被重新指派（mutable）；Tag 不必然固定內容。
   - 可透過內容 Digest 識別 Image。Harbor 為 Private Registry 的例子，但本課程未驗證特定內部名稱、Project Key 或 URL。

3. [docker image pull](https://docs.docker.com/reference/cli/docker/image/pull/)
   - Docker 支援依 Tag 或 Digest 取得 Image；Digest 能固定內容版本。
   - 教學中的 sha256:… 為格式示例，非真實公司 Image ID。

4. [Building best practices](https://docs.docker.com/build/building/best-practices/)
   - Image Tags 可變；官方建議可用 Digest Pin 以確定特定 Image 版本。
   - Image 建構與相依管理需設計，不保證相同 Dockerfile 每次都建出 bit-for-bit 相同產物。
   - Image 供應鏈、安全性與持續更新需另外治理。

5. [Docker Engine security](https://docs.docker.com/engine/security/)
   - Docker Daemon 與 Container 隔離有安全邊界與攻擊面；不能把 Container 當成 VM 等級的完整隔離。
   
6. [Docker Engine](https://docs.docker.com/engine/)
   - 官方 Docker Engine 主索引；Docker 的 Engine / Storage / Networking / Security 文件入口。

## Explanation boundaries and teaching decisions

- 「相同 Source Code ≠ 相同執行環境」，但不同套件版本也不必然發生錯誤；須確認相容性。
- Python venv 主要隔離 Python 套件環境；多個 Python Runtime 本就可共存；Container 不是唯一解決方案。
- OCI Image 封裝 User-space 檔案與啟動設定，不包含所有 External Dependencies、Kernel、環境變數／Secrets／DB 狀態。
- 原則是 CI Build、驗證 Artifact、Registry 保存，Deployment 使用相同 Image 內容；「兩邊都同一 Git SHA」或「兩邊都同一 Tag」不足以證明內容相同。
- Digest 對特定內容提供不可變的識別；多平台 Image Index 的相同 Digest 可包含不同平台對應 manifest，第二堂只點到。
- 將 Source Code → Image Artifact 的分發提升到觀念層級，避免第二堂塞入 docker build/push 命令清單。
- 同 Image 並不保證 Runtime 行為、DB Migration 與 Rollback 成功。
- VM 的 Kernel 隔離、Namespace / cgroups 底層實作留 Session 03。
- 所有例子（orders-api、Python／library 版本、Git SHA abc123、registry.example.com）均為示意，不能宣稱是 Garmin 實際工作負載。
