Mission：從程式執行的基本事實出發，逐步理解 Container 的必要性與底層機制，進而讀懂 Dockerfile、觀察實際 Container 的網路／儲存，最後串接 Kubernetes／CKA。

為什麼這樣安排？

概念依賴順序是：Program / Process → Container / Docker（What）→ 為什麼需要（Why）→ Linux 隔離（How）→ Image 與 Build → Container Lifecycle → Network → Runtime / Kubernetes。VM 是在學會 Linux Process 與 Container 的基本模型後才引入的比較工具，不是第一堂的先備知識。

一堂課的目的是讓大家建立可推論的模型，而不是填滿技術名詞。每堂約 30 分鐘，包含情境、圖解、驗證實驗、理解練習與回饋。
