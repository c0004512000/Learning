SESSION 01 / WHAT · 30 MINUTES

Container 是什麼？
Docker 又在做什麼？

先從你每天都在執行的程式開始。當你知道一個程式如何變成正在運作的 Process，就能理解 Container 並不是「迷你 VM」；接著才有辦法正確區分 Dockerfile、Image 與 Container。

對象：具備基本開發經驗的工程師。不預設你懂 Linux Namespace、cgroups、Hypervisor 或 Docker 指令。

這堂結束後，你應該能夠
  1. 用一般應用程式說明「程式檔案」與「正在執行的 Process」的差別。
  2. 描述 Container 的基本樣貌：程式在一個受隔離的執行環境中運作。
  3. 清楚區分 Docker、Dockerfile、Docker Image 與 Docker Container。
  4. 預測從同一個 Image 啟動兩個 Container，會產生什麼執行關係。

成功標準不是背定義，而是看到陌生的 Docker 指令時，知道它在建立檔案模板、建立實例，還是操作正在執行的程序。

01 / 00–07′ · FROM CODE TO PROCESS先別急著談 Docker：一個程式是怎麼跑起來的？

假設你寫了一支 Python 程式，內容只有一行：

# app.py
print("Hello, World!")

這時 app.py 只是儲存在磁碟上的檔案，尚未有任何程式正在執行。直到你在 Terminal 輸入：

python app.py

作業系統才會啟動 Python 直譯器，讓它載入並執行 app.py。被啟動、正在執行的程式實例，就叫做 Process（行程）。程式檔案和 Process 不是同一個東西：一份程式檔案可以被執行很多次，產生不同的 Process。

而且執行並不只有「程式碼」：Python 直譯器是 Runtime，匯入的第三方套件屬於 Dependencies；Process 還需要讀取檔案、使用記憶體、存取網路等功能，這些資源由作業系統管理。

現場思考（先猜再展開）

如果硬碟有三份 app.py，但沒有任何人執行它，現在有三個 Python Process 嗎？

查看解析

沒有。檔案數量不等於 Process 數量；Process 必須在程式被啟動後才存在。

02 / 07–14′ · EXECUTION ENVIRONMENTContainer：讓程式在有邊界的環境裡執行

我們剛剛看到：一般的 Python 程式被啟動後，會成為 Process，並使用作業系統提供的功能。

現在換個方式：如果希望這個 Process 看到的是一套特定的檔案、程式庫與網路環境，而不是直接依賴 Host 上所有共用的內容呢？

Container 就提供這種執行方式。你可以先把它理解成：一組受管理的 Process，運作在具有隔離邊界的執行環境裡。其中的程式依然是一般 Process，沒有被變成一種新的「Container 程式語言」。

所以，Container 不是一台縮小版的完整電腦，也不是另一套獨立 Kernel。但它也不只是「一個檔案系統」：裡面可以有多個 Process，還涉及檔案、網路、程序視圖和資源管理。

你可能會追問：「Linux 究竟怎麼讓這些 Process 看到不同的環境？」很好，這正是第三堂的主題：到時會從 Linux Kernel 延伸到 Namespaces、cgroups 與 Root Filesystem。第一堂只需要把 Container 的位置放對。

用自己的話回答

Container 裡執行的 Python，跟直接在 Linux Host 上執行的 Python，哪個才是真正的 Process？

查看解析

兩者都是真正的 Process。差別在於 Container 中的 Process 受到特定執行環境與隔離機制管理。

03 / 14–22′ · PACKAGE / BUILD / RUNDocker 是什麼？它跟 Container 有什麼差別？

Container 是一種執行環境的概念與技術，不是 Docker 獨有的發明。Docker 則提供一套實用工具，協助你定義應用程式的執行內容、將內容建成 Image，並由 Image 建立與管理 Container。

先認識四個在文件與工作流程裡最常出現的詞：

名詞它是什麼最簡單的判斷方式
Dockerfile一份用來建構 Image 的指示文件。描述「要準備什麼」。
Image唯讀的建構產物，包含檔案與啟動設定，用來建立 Container。描述「準備好的模板」。
Container從 Image 建立的執行實例；可以啟動、停止、刪除。描述「建立出的實例」。
Docker Engine處理 Image、Container、Network、Volume 等資源管理的系統。描述「誰負責管理」。

下面不是要求你現在學會寫 Dockerfile，而是先看懂整個流程的意思：

FROM python:3.12-slim
WORKDIR /app
COPY app.py .
CMD ["python", "app.py"]

這份文件描述如何準備 Python 環境、放入程式檔案，以及執行實例啟動時預設要跑的命令。FROM、COPY 與 CMD 的精確行為，第四、五堂會完整解釋。

特別注意：Image 不是正在執行的程式。Image 可以存在卻沒有 Container；Container 也可以處於 Stopped 狀態、沒有正在執行的主要 Process。這就是為什麼「Image 是模板、Container 是實例」比「Image 等於壓縮檔、Container 等於 VM」更準確。

Docker CLI（你輸入的 docker ... 指令）只是操作介面之一。背後還有接收 API 請求的 Docker Daemon（dockerd），完整的 Engine 與 Runtime 架構會在第八堂介紹。

預測結果

如果團隊只有一份 nginx:alpine Image，可不可以啟動兩個各自運作的 Nginx Container？

查看解析

可以。同一份 Image 可以建立多個 Container；它們有不同的執行實例、名稱與生命週期。

04 / 22–27′ · OBSERVE, NOT MEMORIZE用最少指令驗證：Image 不是 Container

以下 Demo 在有 Docker Engine 的測試環境執行。目標只是觀察「一份 Image → 兩個實例」，不是要求學員背 CLI。請勿在正式環境直接操作。

步驟 1：啟動第一個 Container。

docker run -d --name l01-web-a -p 127.0.0.1:8080:80 nginx:alpine

這裡先知道 nginx:alpine 是 Image 名稱，l01-web-a 是 Container 名稱；-d 讓服務留在背景執行，127.0.0.1:8080:80 是把 Host 本機 Port 8080 對應至 Container Port 80。完整的 Port Mapping 機制會留到 Networking 堂。

步驟 2：用相同 Image 啟動第二個 Container。

docker run -d --name l01-web-b -p 127.0.0.1:8081:80 nginx:alpine

因為 Host 的 8080 已被第一個 Container 使用，第二個選 8081。這裡並沒有重新定義另一份 Image。

步驟 3：觀察實例與程序。

docker ps
docker top l01-web-a
docker top l01-web-b

預期 docker ps 顯示兩個不同名稱、不同 Container ID 的執行實例；兩次 docker top 分別呈現各自 Container 內的程序資訊。你也可以在執行 Docker 的那台機器上開啟 http://127.0.0.1:8080 與 http://127.0.0.1:8081，觀察兩個服務。

步驟 4：清理資源。

docker rm -f l01-web-a l01-web-b

驗證前提：Docker Daemon 可連線、環境可取得 nginx:alpine、Host 的 8080/8081 未被占用。這裡提供可執行的實驗與預期觀察，不是已在公司 Runner 或 Kubernetes Node 上實測的結果。

講師可以追問的兩個問題

（1）刪除 A，B 應不應該停止？（2）刪除兩個 Container 後，原本的 Image 還在不在？

先讓大家預測，再執行驗證。這會為後續的 Container Lifecycle 與 Image Storage 課程建立問題意識。

60 秒口述挑戰：假設一位同事問你「我們既然有 Dockerfile，是不是就等於有一個正在跑的 Container？」試著用 Dockerfile → Image → Container → Process 的順序解釋。若還卡住，回到 Figure 04；也可以將你卡住的那個概念帶回 ChatGPT 討論。

本堂核心模型

  1. 程式檔案不等於 Process；程式被啟動才有執行實例。
  2. Process由作業系統管理，使用 Runtime、Library 等執行條件。
  3. Container是受隔離、受管理的執行環境，裡面跑的仍是真正的 Process。
  4. Dockerfile描述如何建構 Image。
  5. Image是唯讀模板；Container是根據 Image 建立的實例。
  6. Docker提供建構、交付、執行與管理 Container 的工具。
