Docker Fundamentals · 第一堂

從一支 Python API 認識 Container 和 Docker

一份程式可以執行幾次？

磁碟上的 app.py 存著程式內容，這就是 Program。在終端機輸入 python app.py，作業系統啟動 Python 直譯器來執行它，這次執行就有了一個 Process（行程）。在兩個終端機各執行一次，你會得到兩個行程，各有自己的識別編號（PID）與記憶體空間。

如果只把 app.py 複製三份，會有幾個新行程？

零個。複製增加了檔案數量，執行程式才會產生行程。

把 FastAPI 搬到 Linux Server，需要一起準備什麼？

你在自己的電腦上啟動 FastAPI 成功。接著把程式放到一台既有或新建的 Linux 虛擬機器（VM）。在這台機器上，誰來執行 Python 語法？程式執行到 from fastapi import FastAPI 時去哪裡找套件？服務又從哪裡取得資料庫位址？

工程師可以用部署腳本或組態管理工具準備這些條件。現在把規模放大到十個服務：庫存 API 要新版 Python，報表服務還得使用舊版套件。你會把它們放在哪裡？

共用一台 VM

只需維護一套作業系統。可以用 venv 分開 Python 套件，但仍要管理各服務使用的直譯器、系統函式庫與設定；升級共用元件時，也要確認哪些服務會受影響。

每個服務各一台 VM

可以各自安裝、升級與重開機。代價是可能多出十套要配置、更新與修補的 Guest OS，也就是安裝在各台 VM 裡的作業系統。

若服務需要的是彼此獨立的執行環境，每組行程都需要一整套 Guest OS 嗎？

共用一個 Linux 核心，讓行程各自看見不同的環境

我們希望更新庫存服務的套件時，報表服務仍能使用它原本的版本。這種把服務相互影響的範圍分開的能力，就是隔離（Isolation）。Linux 的核心（Kernel）管理行程、檔案與網路。它能限制一組行程看到哪些檔案、使用哪些網路介面，以及能用多少資源。

在這樣的邊界內執行一個或一組行程，就形成了 Linux Container。看圖時先找 Python 行程，再沿箭頭找管理它的核心。

隔離環境準備好了，Python 從哪裡來？

回到同一台 Server。即使十個服務已經各有隔離環境，Python、FastAPI、設定和啟動命令仍需要有人準備。你可以用 Shell 腳本或 LXC 範本自動化。若想把準備好的檔案和啟動設定保存起來，讓下一個實例直接重用，就需要一致的建構與管理方式。

Docker 提供這套工具。Dockerfile 描述建構步驟，Image 保存建構好的檔案及預設設定，Docker Engine 依 Image 建立、啟動及管理 Container。Linux 的行程隔離能力也能由其他容器工具使用。

建構一次，啟動兩個 API

在有 Docker 的主機建立一個空目錄，在裡面放入下列兩個檔案。這支 API 只有一個路由，讓我們可以直接觀察兩個實例的回應。

app.py

from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def hello():
    return {"message": "hello"}

Dockerfile

FROM python:3.12-slim
WORKDIR /app
RUN pip install --no-cache-dir fastapi uvicorn
COPY app.py .
CMD ["python", "-m", "uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]

第一行提供 Python，接著安裝 API 與伺服器套件，再把程式放進 Image。最後一行保存啟動命令。到這個目錄執行：

docker build -t lesson-api:1 .
docker run -d --name lesson-api-a -p 127.0.0.1:8080:8000 lesson-api:1
docker run -d --name lesson-api-b -p 127.0.0.1:8081:8000 lesson-api:1
docker ps --filter ancestor=lesson-api:1

找出兩列的 IMAGE 與 CONTAINER ID：前者相同，後者不同。主機的 8080 連到 A，8081 連到 B。用瀏覽器分別開啟 http://127.0.0.1:8080 與 http://127.0.0.1:8081，兩個實例都應回傳 hello。

停止 A，B 的網址還能用嗎？

執行 docker stop lesson-api-a，再重新整理兩頁。8081 仍由 B 回應。A 處於停止狀態，兩個 Container 的生命週期各自獨立。完成後以 docker rm -f lesson-api-a lesson-api-b 清理兩個實例。

一份 Image，多個執行實例

一份 Python Program 可以啟動多個 Process。同樣地，一份 Image 可以建立多個 Container，每個 Container 都能啟動自己的行程。這個類比說明的是「一份內容，多次執行」：Image 還包含執行環境與預設設定，而每個 Container 有自己的可寫入層，停止後仍保有實例身分。

同一份測過的 Image 也可以交付給 Development、Stage 和 Production，省去在每個環境重裝 Python 與套件的工作。這就是 Build Once, Deploy Many。各環境提供的變數、資料庫和主機 Kernel 仍可能不同。
