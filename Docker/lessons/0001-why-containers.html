01 / 為什麼需要容器化？（0–7 分鐘）

一個服務不只依賴原始碼。它還仰賴特定版本的 Runtime、Library、系統工具與設定。沒有一致的封裝方式，就會變成「同一份程式碼 + 不同 Server 狀態 = 不同結果」。

現場提問 · 1 分鐘

假設 CI 產出同一份 Image，推送到 Registry 後分別部署 Test 和 Prod。這是否代表兩個環境一定表現相同？

展開講者解析

不一定。Image 主要標準化程式和大量 User Space 依賴，但 Kernel/CPU 架構、DB、Secrets、設定、外部網路等仍是其他輸入。這正是「改善可重現性」與「保證完全相同」的差別。

VM 能做的事

隔離應用程式及整個 Guest OS，可以安裝相依環境，也能用 VM Template 建立標準化交付。

Container 不同的取捨

將程式與 User Space 依賴包成 Image，執行時共享 Kernel，通常有更低的每個工作負載額外 OS 開銷。

02 / VM 和 Container 到底在隔離什麼？（7–15 分鐘）

先認識三個詞：Application 是程式；Kernel 是 OS 管理 Process、Memory、Network 與 I/O 的核心；Hypervisor 提供 VM 所需的虛擬硬體環境。

①
VM 不是「較重的 Container」

Hypervisor 提供一套虛擬 CPU、Memory、裝置等介面；Guest OS 認為自己在一台機器上運行，因此會啟動自己的 Kernel、管理自己的 Process 和檔案系統。VM 隔離的邊界包含 OS 核心。

②
Container 不是「沒有 OS」

它仍需要 Kernel 的檔案、網路、Process 等服務，只是沒有為每個 Container 再啟動一套 Kernel。Image 提供大量 User Space 檔案，隔離則由既有 Linux Kernel 執行。

看圖判斷 · 1 分鐘

兩個 VM 可以分別使用不同的 Guest Kernel。那麼在同一 Linux Host 上的兩個普通 Linux Containers，可以分別換成兩種不同的 Linux Kernel 嗎？

展開講者解析

不能。它們共享同一個正在執行的 Host Linux Kernel。Image 裡就算有另一版 Kernel 檔案，也不會改變正在服務 System Call 的 Kernel。

03 / VM 開機與 Container 啟動，差在哪裡？（15–21 分鐘）

VM 並不是只要「新增一個 Process」就能開始執行應用程式。它必須先有一個可以讓 Guest Kernel 運作的虛擬機器環境。Linux Container 則利用已經啟動的 Kernel，建立隔離環境後直接執行 Process。

這也解釋了為什麼 VM 經常用來提供較強的 OS 隔離，而 Container 更適合需要頻繁建立與替換執行實例的交付方式。不過並沒有任何一種架構能單憑「VM」或「Container」名稱保證效能與安全。

04 / 用一次 read() 看懂 Kernel 邊界（21–26 分鐘）

當程式要讀取已開啟的檔案，可以呼叫 read(fd)。這裡 fd 是 File Descriptor（代表已開啟檔案的識別值）。這是 System Call：程式請 Kernel 幫忙讀資料。

05 / 現場驗證與課後檢查（26–30 分鐘）

在一台已安裝 Docker Engine 的 Linux Host 上，用一個 nginx Container 觀察「Container 內的 Process，也能在 Linux Host 上看到」。

docker run -d --name demo nginx:alpine
docker top demo

# Linux Host：取得該 Container 主 Process 的 Host PID
PID=$(docker inspect -f '{{.State.Pid}}' demo)
ps -p "$PID" -o pid,ppid,comm,args

docker rm -f demo
現場觀察 · 2 分鐘

預期會觀察到什麼？Host 看得到該 Container 的主 Process。這說明容器並不是另一台有獨立 Kernel 的小型電腦，但還不能單獨證明 Namespace / cgroups 的所有隔離細節。

若使用 Docker Desktop，所謂 Linux Host 可能是其內部 Linux VM／WSL 2 環境；請避免把它和外層 Windows／macOS Host 混淆。實際輸出依環境而定。

兩個普通 Linux Containers 在同一 Host 上執行，會有幾個供它們使用的 Host Kernel？

用 40 秒回顧完整因果

部署：Image 讓程式與大量依賴一起交付。架構：VM 各有 Guest Kernel，Linux Container 共用 Host Kernel。啟動：VM 要啟動 Guest OS，Container 則在現有 Kernel 上建立隔離 Process。讀檔：System Call 直接由對應 Kernel 處理，不會每次穿過 dockerd。
