VM / Container：一頁理解 Kernel 邊界

如果只記得一句話：VM 虛擬化硬體並啟動 Guest Kernel；Linux Container 隔離 Process 並共用 Host Kernel。

兩種執行路徑（箭頭表示呼叫或委派）

VM

App
system call ↓
Guest Kernel
裝置 I/O ↓
Virtual Device / Hypervisor
↓
Hardware

Container

App + User Space
system call ↓
Shared Linux Kernel
↓
Hardware

三個不要混淆的名詞

名詞是什麼不是什麼
Kernel管理 Process、Memory、I/O 的核心不是 /usr 或 /bin 的檔案集合
Image / RootFS程式與 User Space 檔案的封裝不是另一個運行中的 Kernel
Container受隔離規則管理的 Process 執行環境不是每個實例都有一套 Guest OS

常見例外

Windows／macOS 的 Docker Desktop 執行 Linux Containers 時通常仰賴 Linux VM／WSL 2；Linux Container 仍共享該 Linux 環境的 Kernel。VM 也未必是完整桌面 OS，重點是有獨立 Guest Kernel，而不是 GUI 或安裝容量。

與下一堂的關聯

Namespaces 負責隔離 Process 可見的系統資源視角；cgroups 管理資源使用；RootFS 提供檔案內容。下一堂再拆解它們如何組合。
