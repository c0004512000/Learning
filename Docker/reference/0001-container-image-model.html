REFERENCE 01 / CONTAINER · IMAGE · DOCKER

Container、Image、Docker
一頁建立正確關係

遇到任何 Docker 指令時，先判斷它在描述程式檔案、建構模板、建立實例，還是操作正在執行的 Process。

你應該能區分的名詞

Program / Source Code
儲存在檔案系統上的程式內容，存在不代表正在執行。
Process
程式被啟動後的執行實例，由作業系統管理。
Runtime / Libraries
程式執行時需要的執行工具、函式庫等依賴。
Container
受隔離、受管理的執行環境，裡面可以有一個或多個 Process。
Dockerfile
定義 Image 如何建構的指示文件。
Image
用來建立 Container 的唯讀模板；不等於執行中的程式。
Docker
協助建構、分發、執行與管理 Container 的平台及工具。
Docker Engine
Docker 的核心管理系統，包括 Docker Daemon、API 等組件；第八堂會拆解 Runtime 架構。

三個最常見的混淆

Image = Container？

不對。Image 是建立實例的模板；Container 是基於 Image 建立的實例。

Container = 一台獨立的 Linux VM？

不對。典型 Linux Container 的 Process 使用所在 Linux 環境的 Host Kernel；不會為每個 Container 啟動獨立 Guest Kernel。

Container = 只有一個 Process？

不完全正確。Container 常以一個主要 Process 管理生命週期，但實際上可以有多個 Process。

最小觀察實驗

docker run -d --name l01-web-a -p 127.0.0.1:8080:80 nginx:alpine
docker run -d --name l01-web-b -p 127.0.0.1:8081:80 nginx:alpine
docker ps
docker top l01-web-a
docker top l01-web-b
docker rm -f l01-web-a l01-web-b

實驗前需確認 Docker 可用、可取得 Image、Port 8080/8081 未占用。以上是教學範例與預期驗證方向，不是公司環境的實測紀錄。
